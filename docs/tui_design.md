# Mica TUI 交互与视觉设计

## 1. 文档定位

本文是 Mica Textual TUI 的产品设计事实源，记录已经由用户确认的界面结构、视觉规则和
交互行为。后续第六阶段计划负责把这些规则拆成可执行任务，不在阶段计划中复制本文正文。

本文当前只定稿：

- 启动界面与头部信息。
- 用户消息与输入框。
- 唯一工作状态条。
- 模型思考内容与正式回复。
- 对话区的流式输出和滚动行为。

工具调用卡片、权限窗口、`ask` 交互、会话界面、配置界面、模型选择、斜杠命令和快捷键
总表仍待逐项讨论。未定稿内容不得由实现任务自行补全。

## 2. 总体风格

Mica 使用克制、清晰、偏工程工具的深色终端界面：

- 终端原始深色背景是主要画布，不使用大面积高饱和背景。
- 主色为浅蓝到深蓝，不使用紫色作为品牌主色。
- 绿色表示成功，红色表示失败、取消或中断，灰色表示次要说明。
- 用户消息、思考内容、模型回复和工具记录必须在视觉上容易区分。
- 颜色不能是状态的唯一表达；状态同时使用稳定文字说明。
- 不使用聊天气泡、头像、阴影或过度装饰。

## 3. 启动界面

### 3.1 Logo

新工作区启动 Mica 时，在对话记录区顶部展示折叠几何感的 `M` 形 Logo。Logo 使用适合终端
的 Unicode 或块字符绘制，通过 Textual/Rich 的文本样式实现浅蓝到深蓝的层次，不在终端中
直接显示 PNG。

Logo 必须提供响应式降级：

- 终端空间充足时显示完整 Logo。
- 终端较窄时显示紧凑 Logo。
- 空间不足或终端能力有限时显示纯文本 `Mica`。
- 真彩色不可用时降级到 256 色或基础蓝色；禁用颜色时仍能正确阅读。

### 3.2 启动信息区

Logo 下方使用清晰分区或边界展示当前会话启动时实际加载的资源，例如：

- 内置系统提示词。
- global `AGENTS.md`。
- workspace `AGENTS.md`。
- 当前可用的内置工具。
- 已加载的 Skill 和扩展；当前没有时明确显示 `none`，不得虚构能力。

启动信息位于可滚动的对话记录区顶部，会随着后续对话自然滚出视野，不固定占用屏幕。界面
只能读取会话启动时已经建立的上下文快照，不得为了渲染界面重新组装系统提示词或重新读取
`AGENTS.md`。

## 4. 运行中布局

运行中的界面分为三个稳定区域：

```text
┌─ 可滚动的对话记录区 ────────────────────────────────┐
│  用户消息、思考内容、模型回复和工具记录               │
└──────────────────────────────────────────────────────┘

  Mica · ready / working... / done / cancel / interrupt
┌─ 固定输入框 ──────────────────────────────────────────┐
│ 输入内容                                              │
└──────────────────────────────────────────────────────┘
```

- 对话记录区可以滚动。
- 工作状态条固定在输入框正上方。
- 输入框固定在界面底部。
- 整个界面只能存在一条工作状态条。
- 工作状态条绝不插入用户消息、模型回复或历史记录之间。

## 5. 用户消息

### 5.1 消息卡片

用户消息使用左对齐的低对比度卡片：

- 不显示 `You` 或其他角色标题。
- 使用与终端背景轻微区分的深灰色背景。
- 左侧使用一条短蓝线作为身份标记。
- 正文使用清晰的浅色文字。
- 不使用完整边框、圆角气泡、头像或阴影。
- 用户原始文本按纯文本显示，不主动解释为 Markdown。

### 5.2 输入框

输入框初始高度为一行，并按显示需要自动增长：

- 普通长文本只做显示层软换行，不在消息中插入换行符。
- `Shift+Enter` 插入真实换行。
- `Enter` 发送消息。
- 输入框最高增长到八行。
- 超过八行后保持固定高度并在内部滚动。
- 有未显示内容时，通过 `↑ N more` 或 `↓ N more` 提示上下方剩余内容。

### 5.3 长粘贴

终端支持 bracketed paste 时，长粘贴作为不可拆分的粘贴片段保存，并在输入框中显示紧凑
摘要：

```text
[paste #1 +66 lines]
```

- 不展开预览粘贴内容。
- 不允许逐字编辑粘贴片段。
- 光标移动时整体跨过该片段。
- Backspace 或 Delete 接触该片段时，删除整个粘贴片段。
- 短粘贴继续作为普通文本处理。
- 发送时向模型和会话层还原完整原文，不能把摘要文字当成真实消息内容。
- 发送后的用户消息卡片继续显示紧凑摘要。

当前会话格式没有保存这类界面展示元数据。恢复会话时如何重建同一粘贴摘要，留给 TUI 完成
后的会话格式优化任务处理；不得通过污染模型上下文来伪造恢复效果。

图片输入暂不进入当前 TUI 构建范围，待基础 TUI 完成后再统一设计多模态消息、Provider 和
会话格式。

## 6. 唯一工作状态条

### 6.1 位置与生命周期

`Mica · working...` 是整轮运行的唯一全局状态，始终位于输入框正上方。它不属于任何一条
消息，不进入对话记录，也不会随滚动离开视野。

初次等待输入时显示：

```text
Mica · ready
```

用户输入文字但尚未发送时保持 `ready`。只有用户按下 `Enter`，新的 Run 真正开始时才切换
为 `working`。

### 6.2 动画

不使用色块或进度条。动画由两部分组成：

- `Mica · working...` 整体在浅蓝、标准蓝和深蓝之间变化。
- 末尾点号按 `.`、`..`、`...` 循环出现。

颜色反映距离上一次可观察进展的时间，不假装诊断网络状态：

| 距离上次进展 | 颜色表现 | 含义 |
|---|---|---|
| 0～3 秒 | 浅蓝到标准蓝 | 正常工作或持续收到反馈 |
| 3～10 秒 | 标准蓝逐渐变为中蓝 | 暂时没有新内容 |
| 10 秒以上 | 缓慢变为深蓝 | 较长时间没有新进展 |

收到新的思考内容、正式文本或工具状态后，颜色重新回到较亮的蓝色并重新计时。模型开始输出
正式回答后，状态仍然是 `Mica · working...`，动画继续运行，直到整个模型与工具循环结束。

### 6.3 阶段说明

状态条右侧可以使用灰色文字显示真实可知的阶段和耗时：

```text
Mica · working...                       (thinking 2.1s)
Mica · working..                      (responding 4.7s)
Mica · working.                         (waiting 8.6s)
```

只有收到 Provider 独立思考信号时才使用 `thinking`。不能解析普通回答来伪造思考状态。工具
阶段的具体文案随工具卡片设计一起确定。

### 6.4 完成、取消与中断

只有整个 Run 完整成功后才切换为：

```text
Mica · done                     (thought 2.8s · total 11.3s)
```

没有独立思考内容时使用 `waited`，不虚构 `thought`。`done` 停止动画，并保留到用户下一次
真正发送消息；它不复制到历史对话中。

尚未出现任何模型、思考、工具或交互进展时取消，显示红色：

```text
Mica · cancel
```

已经出现任意进展后中断，显示红色：

```text
Mica · interrupt
```

两种状态都立即停止动画。界面可以保留已经显示的部分内容用于诊断，但不把不完整轮次写入
正式会话历史。

## 7. 模型思考内容

思考内容只有在 Provider 返回独立思考信息时才能展示。TUI 不从普通回复、标签文本或模型
措辞中猜测思考内容。

思考内容采用灰色文字、左侧细灰线和比正式回复更深一级的缩进，不使用背景卡片。提供三种
显示模式：

1. `full`：完整展示实际收到的思考内容。
2. `collapsed`：默认只显示前几十个字符或最多两行，使用 `Ctrl+O` 在折叠和完整之间切换。
3. `hidden`：不显示思考正文，但状态条仍可显示真实的 `thinking` 阶段。

## 8. 思考强度

思考强度和思考内容的显示模式是两个独立设置。思考强度的候选档位为：

```text
关闭
Minimal
Low
Medium
High
XHigh
Max
```

Mica 不主动探测或判断某个模型支持哪些档位。后续模型配置采用“Provider 选择协议适配器，
模型声明能力”的结构：Provider 的 `api` 选择已实现的协议适配器，例如
`openai-responses` 或 `openai-completions`；模型的 `reasoning` 明确是否支持思考；可选的
`thinkingLevelMap` 把上述统一档位映射到供应商实际接收的值。

`reasoning` 缺失或为 `false` 时，界面只允许关闭思考，也不发送思考强度参数。
`reasoning: true` 且 `thinkingLevelMap` 缺失或为空时，使用该 `api` 适配器经过测试的默认档位
与映射；非空时只展示配置明确列出的档位。模型配置不填写原始响应 JSON 路径，各协议适配器
负责把自己的请求字段和流式响应统一成 Mica 的思考事件。没有独立思考事件时，TUI 不展示或
猜测思考正文，但唯一 `working` 状态条仍正常工作。

思考强度的 Provider 传递、思考内容的识别和事件契约，在全部 TUI 样式定稿后单独讨论并先于
TUI 实现完成；本文当前只固定产品表现。

## 9. 模型正式回复

模型正式回复直接显示在终端背景上：

- 不使用背景卡片、角色标题、头像或聊天气泡。
- 正文使用清晰的终端浅色。
- Markdown 标题、列表标记和链接使用克制的蓝色。
- 行内代码使用轻微灰色背景。
- 代码块使用比终端稍亮的深灰区域，显示语言名称并进行基础语法着色。
- 思考内容结束后，正式回复沿同一阅读主轴自然开始。

流式输出时，在正文末尾显示小型蓝色光标。短小增量可以合并后快速刷新，避免 Markdown
逐字符重绘产生明显闪烁；完成后移除流式光标，并对完整 Markdown 做一次最终渲染。整个过程
中唯一工作状态条持续动画，只有 Run 完整结束后才显示 `done`。

## 10. 滚动与恢复

- 用户位于对话底部时，流式输出自动跟随最新内容。
- 用户主动向上滚动后，不再强制拉回底部。
- 有新内容时显示 `↓ new output`，返回底部后恢复自动跟随。
- 恢复历史会话时只渲染已持久化的正式消息和完整工具历史。
- 不重放 `working` 动画，不伪造旧耗时，也不伪造没有保存的旧思考内容。

## 11. 工具调用卡片

工具调用按真实执行位置嵌入可滚动的对话记录区。一次调用只创建一张卡片；状态变化时更新
原卡片，不为开始、执行和完成分别创建重复记录。卡片使用明显但偏深的背景色：正在执行为
蓝色，成功为绿色，执行失败或执行中被中断为红色。已经成功完成的工具不会因为后续 Run
被中断而改成红色。

工具卡片随对话滚动，不替代输入框上方唯一的 `Mica · working...` 状态条。卡片中的长内容
默认折叠；聚焦卡片后，`Ctrl+O` 作为统一的详情开关，与思考内容使用同一套“展开或折叠
当前焦点”语义。

当前 Engine 对模型一次返回的多个工具调用按原顺序逐个执行。TUI 的 MVP 也按这一真实顺序
渲染，不把 `read` 或其他工具表现成已经并行运行。并行调度需要独立的安全契约和后端任务，
不随 TUI 渲染顺手引入。

### 11.1 `write`

`write` 使用无外框的文件内容预览卡片，只展示工具名、目标路径和写入内容，不使用参数表、
`path`/`content` 标签、独立状态栏、耗时或文件大小总结。

```text
write  docs/tui_design.md

# Mica TUI 交互与视觉设计

## 1. 文档定位

本文是 Mica Textual TUI 的产品设计事实源……

... (5 more lines, 15 total, ctrl+o to expand)
```

- 工具名使用明亮、略微加粗的浅色；路径使用浅青蓝色和下划线。
- 显示工具实际接收的工作区相对路径，不由 TUI 拼接用户绝对路径。
- 写入内容按原始纯文本显示，保留空格、缩进、换行和 Markdown 标记，不进行 Markdown
  渲染或额外语法着色。
- 长行只做显示层软换行，不改变真实行数。
- 默认显示前十个逻辑行；内容不超过十行时完整显示且不出现折叠提示。
- 展开后显示完整内容和 `... (15 total, ctrl+o to collapse)`；再次操作恢复前十行。
- 执行期间卡片为深蓝色；成功后同一卡片原地变为深绿色，内容和展开状态保持不变。
- 失败或执行中断后原地变为深红色，在内容末尾增加一行固定安全原因；不显示 traceback、
  底层异常、凭据或用户绝对路径。
- 创建新文件和完整覆盖旧文件使用相同视觉结构，不额外显示 `created`、`overwritten`、
  字节数或耗时。

### 11.2 `edit`

`edit` 使用与 `write` 相同的无外框状态卡片，但正文只展示修改位置的逐行差异，不显示
`old_text`、`new_text`、参数表或完成摘要。

```text
edit  docs/tui_design.md

  18  ## 2. 总体风格
  19
- 20  Mica 使用简洁的终端界面。
+ 20  Mica 使用克制、清晰、偏工程工具的深色终端界面。
  21
  22  - 主色为浅蓝到深蓝。
     ...
```

- 标题继续显示工具实际接收的工作区相对路径；工具名和路径样式与 `write` 一致。
- 未修改的上下文行使用灰白色；删除行使用浅红色 `-`；新增行使用黄绿色 `+`。空白新增
  或删除行仍保留标记和行号。
- 替换固定先显示删除的旧行，再显示增加的新行。仅删除时不添加虚假的空新增行。
- 多行替换计算最小逐行差异，不把实际未变化的整块内容全部标记为删除和新增；当前不增加
  逐字符高亮。
- 默认展示修改位置之前和之后最多三行上下文，其余文件内容用 `...` 省略。
- 差异不超过二十行时完整展示所有变化；超过二十行时保留前十行和后十行变化，并使用
  `Ctrl+O` 展开或折叠完整差异。
- 工具调用提出后，蓝色卡片显示准备执行的差异；成功后原地变为绿色；失败或执行中断后
  原地变为红色并保留尝试的差异。
- 找到唯一匹配时显示真实行号和上下文。找不到或存在多个匹配时，不伪造文件位置，只显示
  无行号的旧内容和新内容，并附加固定安全原因及“文件保持不变”。
- 已完成的绿色卡片不会因为后续 Run 被中断而改成红色。

### 11.3 `read`

`read` 使用单行、无外框的紧凑状态卡片，只展示工具名和实际读取的工作区相对路径，不展示
文件正文、行号、文件大小、读取行数、耗时或结果摘要。

```text
read  docs/tui_design.md
```

- 工具名与路径样式和 `write` 一致，路径使用浅青蓝色和下划线。
- 执行期间卡片为深蓝色，读取成功后同一行原地变为深绿色。
- 读取失败或中断后原地变为深红色；必要时在同一行末尾追加简短安全原因，不展开为多行
  错误面板。
- 多个 `read` 调用分别保留一行，并按 Engine 的实际执行顺序出现。

### 11.4 `bash`

`bash` 卡片分为命令区和动态输出区。开头展示 Agent 实际提交的完整命令；TUI 可以折叠
显示，但不得截断或改写真正交给 Bash 的命令。

```text
bash

$ uv run pytest \
    tests/test_engine.py \
    tests/test_tool_executor.py \
... (4 more display lines, ctrl+o to expand)
```

- 命令保留原始引号、转义符、换行和连接符，不转换成 PowerShell 或重新排版。
- 命令区默认最多占三行显示高度；长单行发生软换行时也按屏幕显示行计算。
- `Ctrl+O` 只展开或折叠完整命令的显示，执行始终使用完整原始命令。
- 已识别的凭据在显示层替换为 `[REDACTED]`，但折叠不能改变命令执行语义。
- 需要权限确认时，先显示准备执行的命令，再打开独立权限窗口。

用户允许后，在命令下方动态追加合并后的 stdout/stderr。输出视口默认显示最新八行；超过
八行时自动跟随最新内容，但不删除此前已接收且仍在工具输出上限内的内容。用户聚焦卡片并
向上滚动后暂停自动跟随，新内容通过 `↓ N new lines` 提示；返回底部后恢复跟随。

```text
bash

$ uv run pytest -q

... (42 earlier lines, ctrl+o to expand)
tests/test_cli.py ............................
tests/test_engine.py .........................
tests/test_file_tools.py .....................
tests/test_jsonl_store.py ....................
tests/test_session_service.py ................
tests/test_tool_executor.py ..................
tests/test_workspace.py ......................
850 passed, 1 skipped
```

- 执行期间卡片为深蓝色；退出码为 `0` 后原地变为深绿色。
- 成功但没有输出时显示 `(no output)`。
- 非零退出、启动失败、超时、输出超限或执行中断时原地变为深红色，保留已经显示的安全
  输出，并在末尾显示 `exit N` 或固定失败原因。
- 完成后默认保留最后八行；更早内容用 `... (N earlier lines, ctrl+o to expand)` 折叠。
- 动态输出仍受现有总字节上限、凭据清洗、取消和进程树回收边界约束。

### 11.5 `ask`

`ask` 是专用交互工具，不使用普通用户消息卡片。等待回答时采用带浅青色上下分隔线的深色
选择面板：可选标题位于低调的灰色标签中，问题使用明亮文字，当前选项使用 `›` 和浅青色，
说明文字使用缩进灰色，推荐项必须由 Agent 明确提供。

```text
────────────────────────────────────────────────────────

 后续任务

你希望我接下来进行哪种工具测试？

› 1. 读取文件（推荐）
     使用读取工具查看刚才修改后的文档内容。

  2. 执行命令
     使用终端命令检查工作区文件及其基本信息。

  3. 再次编辑
     继续修改文档中的指定内容。

  4. 网络搜索
     使用联网搜索工具查询指定主题。

  5. Type something.

────────────────────────────────────────────────────────
Enter 选择 · ↑/↓ 移动 · n 添加备注 · Esc 取消
```

- `↑`/`↓` 移动，数字键直接定位，`Enter` 确认，`n` 为当前选择添加备注。
- 选择 `Type something.` 后在面板内打开文本输入；回答只进入 `ask` 工具结果，不形成普通
  USER 消息或新的 Run。
- `Esc` 取消当前 `ask` 并中断本轮 Run；`Ctrl+O` 沿用统一详情开关，不引入第二套折叠键。
- 回答完成后，面板折叠为绿色只读记录，例如
  `ask  问题` 与下一行 `→ 已选答案`；添加的备注显示在答案下方。
- 完成后的记录可以通过 `Ctrl+O` 重新查看原选项，但不能重复提交。
- 取消或交互失败时折叠为红色记录；回答不会被渲染成用户消息卡片。

为了表达该界面，`ask` 公共参数需要在 TUI 前从单一 `question` 扩展为可选标题、问题、
二至四个结构化选项、选项说明、最多一个推荐项和是否允许自定义回答。没有结构化选项时，
仍可降级为单个自由文本问题，不伪造选择项。

## 12. TUI 实现前补充任务

`ls` 不再作为 Mica 内置工具。TUI 开始实现前必须安排独立补充任务，从工具注册、Provider
工具清单、权限映射、自动化测试和用户文档中移除 `ls`，并把内置工具数量由六个更新为
五个：`read`、`write`、`edit`、`bash`、`ask`。

目录查看改由 `bash` 完成。当前所有 `bash` 调用仍遵守既定命令权限确认，不因为承担目录
查看而自动升级成免确认的安全命令。是否在未来增加安全只读命令分类，需要另行设计和验收。

除 `ls` 清理外，TUI 实现前还必须完成以下后端闭环：

1. 思考强度与思考内容：由 Provider 的 `api` 选择协议适配器，由模型的 `reasoning` 和可选
   `thinkingLevelMap` 声明能力与档位映射；各适配器统一产生独立思考事件，不从普通回复中
   猜测思考内容。
2. 工具呈现事件：为前端提供经过清洗的工具参数、差异/结果摘要和状态快照；TUI 不读取
   ToolExecutor 私有状态，也不为历史卡片重新执行工具。
3. Bash 动态输出：增加有序的安全输出增量事件，同时保持输出上限、取消、超时和进程树
   回收；当前只在结束后返回完整 ToolResult 的行为不足以支持动态卡片。
4. 结构化 `ask`：扩展选项、说明、推荐、自定义回答与备注契约，并保持迟到响应失效和等待
   清理边界。
5. 历史工具卡片：把当前会话写入格式升级为 v3，在主 JSONL 的成功轮次中保存独立、严格、
   经过清洗的工具展示快照，使恢复会话不依赖当前工作区文件重新推断旧的 `edit` 差异或
   Bash 过程；继续严格读取 v1/v2，不创建第二套 sidecar 文件。

v3 展示快照与送给模型的正式消息分字段保存，只包含重建最终工具卡片所需的安全信息。它不
保存 `working` 动画、实时耗时、未完成轮次、未经清洗的参数、凭据或无界原始输出。v1/v2
会话没有展示快照时使用兼容的简化历史样式，不重新执行工具，也不重新读取工作区文件。
