# Mica 终端交互与视觉设计

## 1. 文档定位

本文是 Mica 终端交互前端的产品设计事实源，记录已经由用户确认的界面结构、视觉规则和
交互行为。后续第六阶段计划负责把这些规则拆成可执行任务，不在阶段计划中复制本文正文。

本文已经定稿：

- 启动界面与头部信息。
- 用户消息与输入框。
- 唯一工作状态条。
- 模型思考内容与正式回复。
- 主缓冲区上的流式输出、差分重绘和终端原生 scrollback。
- 内置 `write`、`edit`、`read`、`bash` 工具卡片与 `ask` 选择面板。

权限确认面板的底部布局、编号选择和一次允许/拒绝范围已确认（见 11.7）。
启动首屏、底部输入区和环境事实布局已经通过视觉参考确认（见 3.3、4.1 和 5.2）。默认前端
迁移为主缓冲区上的轻量保留式文档：终端拥有背景、scrollback 与鼠标滚动，Mica 负责差分
渲染语义组件和底部交互区。当前不显示独立快捷键栏；斜杠命令和完整快捷键帮助仍待后续阶段
实现，未定稿内容不得由实现任务自行补全。

## 2. 总体风格

Mica 使用克制、清晰、偏工程工具的深色终端界面：

- 终端自己的背景是主要画布；Mica 不填充全屏背景、不进入 alternate screen。用户消息、
  代码块和工具卡片可以使用局部背景，其中工具状态允许使用大面积低饱和色块。
- 主色为浅蓝到深蓝，不使用紫色作为品牌主色。
- 绿色表示成功，红色表示失败、取消或中断，灰色表示次要说明。
- 用户消息、思考内容、模型回复和工具记录必须在视觉上容易区分。
- 颜色不能是状态的唯一表达；工具状态可以使用稳定符号和安全原因，不强制增加
  `running/completed` 等冗余文字。
- 不使用聊天气泡、头像、阴影或过度装饰。

## 3. 启动界面

### 3.1 Logo

新工作区启动 Mica 时，在对话记录区顶部展示折叠几何感的 `M` 形 Logo。Logo 使用适合终端
的 Unicode 或块字符绘制，通过 ANSI/Rich 文本样式实现浅蓝到深蓝的层次，不在终端中
直接显示 PNG。

Logo 必须提供响应式降级：

- 终端空间充足时显示完整 Logo，不在图形右侧重复显示小写 `mica` 字标。
- 终端较窄时显示紧凑 Logo，同样不显示伴随字标。
- 空间不足或终端能力有限时显示纯文本 `Mica`。
- 真彩色不可用时降级到 256 色或基础蓝色；禁用颜色时仍能正确阅读。

### 3.2 启动信息区

Logo 下方使用清晰分区或边界展示当前会话启动时实际加载的资源，例如：

- 内置系统提示词。
- global `AGENTS.md`。
- workspace `AGENTS.md`。
- 当前可用的内置工具。
- 已加载的 Skill 和扩展；当前没有时明确显示 `none`，不得虚构能力。

启动信息作为语义文档的首批内容输出到终端主缓冲区，会随着后续对话自然进入 scrollback，
不固定占用屏幕。界面
只能读取会话启动时已经建立的上下文快照，不得为了渲染界面重新组装系统提示词或重新读取
`AGENTS.md`。

Context 中已成功加载的 global/workspace `AGENTS.md` 必须显示装配层提供的安全相对路径，例如
`~/.mica/AGENTS.md` 与 `./AGENTS.md`；没有加载时显示 `none`。不得用 `yes` 代替路径，也不得
显示用户 HOME 的绝对路径。前端仍不得为此重新读取文件或访问 ContextBuilder 私有状态。

内容在边界内缩进并自然换行：Context 显示内置系统提示词及实际加载的 global/workspace
`AGENTS.md` 的安全相对路径或 `none`；Skills、Extensions 显示真实名称或 `none`；Tools 显示
真实数量和当前五个工具。
窄终端可以减少装饰线长度、改为紧凑标签或纵向换行，但不得丢失分区含义或伪造资源。

## 4. 运行中布局

运行中的界面由主缓冲区语义文档和当前底部交互区组成：

```text
  用户消息、思考内容、模型回复和工具记录

  Mica · working... / done(8s) / stop / error
┌─ 当前输入框 ──────────────────────────────────────────┐
│ 输入内容                                              │
└──────────────────────────────────────────────────────┘
  ~\workspace path (branch)                     current-model
  sessions: current title or session id
```

- 终端主缓冲区保存对话历史，鼠标滚轮、右侧滚动条和终端自身的 scrollback 快捷键由终端拥有。
- 工作状态、输入框和事实信息是当前文档末尾的可重绘区域，不要求固定在物理屏幕底部。
- 新输出必须插入底部交互区上方；刷新模型或工具内容时不能把输出写到输入框下方。
- Run 期间输入框保持可见但禁用；环境事实继续显示。
- 整个界面只能存在一条工作状态条。
- 工作状态条绝不插入用户消息、模型回复或历史记录之间。

Ask 或权限等待属于阻塞式交互。此时上方文档和待处理工具记录保持可见，交互组件替代整个
工作状态、输入框和事实区域并成为唯一输入模式；普通 composer 不露出，也不接收输入。交互
完成且 Run 继续时恢复 working、禁用 composer、事实区及未提交草稿。

### 4.1 底部事实信息

输入框下方使用低干扰布局展示当前已有的真实事实：

- 第一行左侧显示当前工作区及当前 Git 分支；用户 HOME 内路径折叠为 `~\...`，不显示 `W:`。
- 第一行右侧显示当前实际模型标识，不显示 `M:`。
- 第二行左侧以 `sessions:` 开头；优先显示非空会话标题，没有标题时显示 Session ID。
- 当前不显示权限模式、耗时和工具数；权限模式的后续位置等待单独确认。

模型切换、会话重命名或会话切换成功后立即刷新对应字段；Git 分支在输入区恢复时通过受控的
公开工作区事实刷新，不使用 Timer 轮询。当前没有稳定来源的 Context token、费用、缓存命中率
和扩展计数不显示。信息区不得读取 Provider、Store 或 Executor 私有状态。窄终端按优先级省略，
但保留 Workspace、Model 和 `sessions:` 的可发现性；省略不得修改底层状态。

当前不显示独立快捷键提示栏。快捷键总表及其视觉位置在真实绑定完成后再讨论；未实现或尚未
验收的按键不得提前出现在首屏中。

## 5. 用户消息

### 5.1 消息卡片

用户消息使用左对齐的低对比度卡片：

- 不显示 `You` 或其他角色标题。
- 使用与终端背景轻微区分的深灰色背景。
- 左侧使用一条短蓝线作为身份标记。
- 正文使用清晰的浅色文字。
- 不使用完整边框、圆角气泡、头像或阴影。
- 用户原始文本按纯文本显示，不主动解释为 Markdown。

### 5.2 输入框

输入框初始高度为一行，并按显示需要自动增长：

- 输入区使用一个稳定的完整边框包裹提示符、编辑区域和可选快捷键提示，不能只画上边线或在
  聚焦时出现断裂的第二套原生边框。
- 左侧显示克制的 `›` 输入提示符；空输入时显示 `Type your request or command...`。宽终端
  可在同一边框右侧显示 `Enter to send · Shift+Enter for new line`，空间不足时优先隐藏右侧
  提示而不是压缩正文。
- 聚焦、失焦、空白和多行状态只能改变语义色，不能改变边框几何、左右内边距或使某条边消失。
- 普通长文本只做显示层软换行，不在消息中插入换行符。
- `Shift+Enter` 插入真实换行。
- `Enter` 发送消息。
- 普通文本中，`←`/`→` 按字符移动，`↑`/`↓` 在多行之间移动，`Home`/`End` 到达对应行边界；
  光标所在位置必须与实际插入、Backspace 和 Delete 的位置一致。失焦恢复后这些行为不变。
- 输入框最高增长到八行。
- 超过八行后保持固定高度并在内部滚动。
- 有未显示内容时，通过 `↑ N more` 或 `↓ N more` 提示上下方剩余内容。
- Run 活动时保留同一输入框与草稿，但设为禁用；普通文字和 Enter 不进入新的提交，Esc、
  Ctrl+C 与 Ctrl+O 仍由全局输入控制器处理。Run 结束后恢复可编辑状态与原光标位置。
- 渲染器更新上方模型或工具内容时，必须把输入框和事实区作为一个整体临时擦除并在文档末尾
  重绘，不能让并发输出出现在输入框下方。

### 5.3 长粘贴

终端支持 bracketed paste 时，长粘贴作为不可拆分的粘贴片段保存，并在输入框中显示紧凑
摘要：

```text
[paste #1 +66 lines]
```

- 不展开预览粘贴内容。
- 不允许逐字编辑粘贴片段。
- 光标移动时整体跨过该片段。
- Backspace 或 Delete 接触该片段时，删除整个粘贴片段。
- 短粘贴继续作为普通文本处理。
- 发送时向模型和会话层还原完整原文，不能把摘要文字当成真实消息内容。
- 发送后的用户消息卡片继续显示紧凑摘要。

当前会话格式没有保存这类界面展示元数据。恢复会话时如何重建同一粘贴摘要，留给 TUI 完成
后的会话格式优化任务处理；不得通过污染模型上下文来伪造恢复效果。

图片输入暂不进入当前 TUI 构建范围，待基础 TUI 完成后再统一设计多模态消息、Provider 和
会话格式。

## 6. 唯一工作状态条

### 6.1 位置与生命周期

工作状态是整轮运行的唯一全局状态，位于输入框正上方。它不属于任何一条消息，不进入会话
历史；终端上翻时可随文档末尾离开视野，不尝试覆盖终端原生 scrollback。

初次等待输入和普通空闲时不常驻显示 `ready`。只有用户按下 `Enter` 且新的 Run 真正开始时
才显示 `Mica · working...`。

### 6.2 动画

不使用色块或进度条。保留原动态效果：

- 末尾点号按 `.`、`..`、`...` 循环出现。
- 文字使用既有克制蓝色；动画只表达仍在运行，不按沉默时长改变颜色或推断阶段。

从用户提交到整个模型与工具循环终止，模型思考、正式回答和工具执行阶段都保持
`Mica · working...`。Ask 或 Permission 成为活动输入模式时隐藏工作状态；交互完成且 Run
继续时恢复动画。

### 6.3 阶段说明

状态条不显示 `thinking/responding/waiting` 阶段，也不显示进行中耗时。具体进展由思考、回复、
工具卡片和交互组件自身表达，状态条只回答“本轮是否仍在运行”。

### 6.4 完成、取消与中断

只有整个 Run 完整成功后才短暂显示实际总耗时：

```text
Mica · done(8s)
Mica · done(1m 24s)
```

`done` 停止动画，约两秒后自动消失，不复制到历史对话中。小于一分钟显示整秒；一分钟以上
显示分钟和秒，必要时显示小时和分钟，不显示毫秒或思考分项耗时。

用户主动中断显示红色：

```text
Mica · stop
```

`stop` 立即停止动画，并保留到下一次 Run 开始。Provider、Engine 或其他运行链异常显示持久
`Mica · error`，同时使用独立的固定安全诊断；它同样到下一次 Run 开始才被 working 替换。
界面保留已经显示的部分内容用于诊断。业务层必须把原始用户指令、
已经完成的模型步骤和工具结果、以及确实收到的部分模型输出保存为明确的中断检查点；它不是
完整成功轮次，不能伪造模型总结、工具成功或未执行结果。后续请求、重启恢复或模型切换时，
模型应能看到这份结构完整且经过清洗的进度，并知道上一轮未完成。

### 6.5 全局中断与退出

- `Esc` 在模型输出、工具执行、Ask 等待和权限等待期间都请求取消当前真实 Run；它不关闭
  Mica，不把取消伪造成权限拒绝或空回答。空闲时按 `Esc` 不产生动作。
- `Ctrl+C` 第一次不退出：活动 Run 中先请求取消，空闲时进入约两秒的退出待确认状态；只有
  在该时间内第二次可观察按键才退出程序。同一输入批次内由按键、原生信号或重复分发产生的
  近同步重复不得绕过这一状态机；超时后的下一次按键重新作为第一次处理。新输入层应保留
  终端提供的按键身份；平台仍不提供 key-up 或重复计数时，延迟自动重复风险必须如实展示并
  由真实终端复验。
- 取消必须继续通过现有 CancellationToken、Engine、Broker、Provider 和 Bash 清理链路，
  保留已显示的安全内容，不写入伪造的成功轮次，不遗留 pending 交互或子进程；真实中断进度
  只通过专用检查点原子保存。

## 7. 模型思考内容

思考内容只有在 Provider 返回独立思考信息时才能展示。TUI 不从普通回复、标签文本或模型
措辞中猜测思考内容。

思考内容采用灰色文字、左侧细灰线和比正式回复更深一级的缩进，不使用背景卡片。提供三种
显示模式：

1. `full`：完整展示实际收到的思考内容。
2. `collapsed`：只显示前几十个字符或最多两行。
3. `hidden`：不显示思考正文。

显示模式完全由用户设置决定，不响应 `Ctrl+O`，也不依赖历史组件焦点；设置入口和持久化仍
属于 Phase 7。

## 8. 思考强度

思考强度和思考内容的显示模式是两个独立设置。思考强度的候选档位为：

```text
关闭
Minimal
Low
Medium
High
XHigh
Max
```

Mica 不主动探测或判断某个模型支持哪些档位。后续模型配置采用“Provider 选择协议适配器，
模型声明能力”的结构：Provider 的 `api` 选择已实现的协议适配器，例如
`openai-responses` 或 `openai-completions`；模型的 `reasoning` 明确是否支持思考；可选的
`thinkingLevelMap` 把上述统一档位映射到供应商实际接收的值。

`reasoning` 缺失或为 `false` 时，界面只允许关闭思考，也不发送思考强度参数。
`reasoning: true` 且 `thinkingLevelMap` 缺失或为空时，使用该 `api` 适配器经过测试的默认档位
与映射；非空时只展示配置明确列出的档位。模型配置不填写原始响应 JSON 路径，各协议适配器
负责把自己的请求字段和流式响应统一成 Mica 的思考事件。没有独立思考事件时，TUI 不展示或
猜测思考正文，但唯一 `working` 状态条仍正常工作。

思考强度的 Provider 传递、思考内容识别和独立事件契约已经建立；TUI 只消费这些公共事件。
模型能力配置、档位选择和界面偏好仍属于 Phase 7，不在 Phase 6 自行补全。

## 9. 模型正式回复

模型正式回复直接显示在终端背景上：

- 不使用背景卡片、角色标题、头像或聊天气泡。
- 正文使用清晰的终端浅色。
- Markdown 标题、列表标记和链接使用克制的蓝色。
- 行内代码使用轻微灰色背景。
- 代码块使用比终端稍亮的深灰区域，显示语言名称并进行基础语法着色。
- 思考内容结束后，正式回复沿同一阅读主轴自然开始。

P6-11A 已经验证主缓冲区运行闭环，但其验收截图仍把用户消息、模型思考、工具记录和正式回复
压在相邻行中，并把 Markdown 源标记直接暴露给用户。P6-11B 必须在不引入聊天气泡或全屏背景的
前提下，用稳定的身份标记、次要文字、段落留白和局部语义背景建立清晰层级；正式回复完成后必须
呈现标题、列表、行内代码和代码块，而不是继续显示 `**`、反引号等原始标记。

流式输出时，在正文末尾显示小型蓝色光标。短小增量可以合并后快速刷新，避免 Markdown
逐字符重绘产生明显闪烁；完成后移除流式光标，并对完整 Markdown 做一次最终渲染。整个过程
中唯一工作状态条持续动画，只有 Run 完整结束后才显示 `done`。

一次 Run 可以包含多次模型请求。每次模型请求产生独立的思考/正式回复片段：同一步骤内的
连续 Delta 更新同一组件；首个 `ToolPrepared` 结束当前模型步骤，工具卡片按 Engine 事件
顺序出现在该片段之后；工具结果触发的下一次模型文字必须创建在上一批工具卡片之后。不得按
整个 `run_id` 把多次模型文字合并到首个回复组件，也不得把文字和工具分别堆成两组。

## 10. 滚动与恢复

- 终端主缓冲区拥有 scrollback、鼠标滚轮、右侧滚动条和终端自身的 scrollback 快捷键；Mica 不维护 transcript
  `scroll_y`、自动跟随、锚点或 `↓ new output`。
- 主屏渲染器保留当前会话的语义文档。普通流式内容和状态动画只差分重绘变化尾部；全局工具
  展开、终端宽度变化或较早组件高度变化可以触发受控全量重绘。
- 重绘不能丢失事件顺序、当前输入草稿或终端 scrollback。终端失焦不改变当前 `IDLE/RUNNING/
  ASK/PERMISSION` 输入模式，恢复后的第一发按键直接按该模式处理。
- 前端不捕获鼠标滚轮，也不建立 Bash 卡片内部滚动区。用户浏览旧输出完全使用终端能力。
- 恢复历史会话时渲染已持久化的成功轮次；中断检查点使用明确的未完成状态恢复其安全消息和
  已发生的工具进度，不重放未完成操作。
- 不重放 `working` 动画，不伪造旧耗时，也不伪造没有保存的旧思考内容。

或已被后端截断的内容不得由前端补造。

当前 Engine 对模型一次返回的多个工具调用按原顺序逐个执行。终端前端也按这一真实顺序
渲染，不把 `read` 或其他工具表现成已经并行运行。并行调度需要独立的安全契约和后端任务，
不随 TUI 渲染顺手引入。

工具调用前的模型文字、该批工具卡片和工具完成后的下一次模型文字必须沿同一语义文档按事件
顺序交错出现。测试和视觉验收都以渲染文档中的真实顺序为准，不能只确认各种组件最终存在。

### 11.1 `write`

`write` 使用无外框的文件内容预览卡片，只展示工具名、目标路径和写入内容，不使用参数表、
`path`/`content` 标签、独立状态栏、耗时或文件大小总结。

```text
write  docs/tui_design.md

# Mica TUI 交互与视觉设计

## 1. 文档定位

本文是 Mica 终端交互前端的产品设计事实源……

... (5 more lines, 15 total, ctrl+o to expand)
```

- 工具名使用明亮、略微加粗的浅色；路径使用浅青蓝色和下划线。
- 显示工具实际接收的工作区相对路径，不由 TUI 拼接用户绝对路径。
- 写入内容按原始纯文本显示，保留空格、缩进、换行和 Markdown 标记，不进行 Markdown
  渲染或额外语法着色。
- 长行只做显示层软换行，不改变真实行数。
- 默认显示前十个逻辑行；内容不超过十行时完整显示且不出现折叠提示。
- 全局工具展开后显示完整安全内容和 `... (15 total, ctrl+o to collapse)`；再次操作使全部
  工具恢复各自的默认折叠预算。
- 执行期间卡片为深蓝色；成功后同一卡片原地变为深绿色，内容和展开状态保持不变。
- 失败或执行中断后原地变为深红色，在内容末尾增加一行固定安全原因；不显示 traceback、
  底层异常、凭据或用户绝对路径。
- 创建新文件和完整覆盖旧文件使用相同视觉结构，不额外显示 `created`、`overwritten`、
  字节数或耗时。

### 11.2 `edit`

`edit` 使用与 `write` 相同的无外框状态卡片，但正文只展示修改位置的逐行差异，不显示
`old_text`、`new_text`、参数表或完成摘要。

```text
edit  docs/tui_design.md

  18  ## 2. 总体风格
  19
- 20  Mica 使用简洁的终端界面。
+ 20  Mica 使用克制、清晰、偏工程工具的深色终端界面。
  21
  22  - 主色为浅蓝到深蓝。
     ...
```

- 标题继续显示工具实际接收的工作区相对路径；工具名和路径样式与 `write` 一致。
- 未修改的上下文行使用灰白色；删除行使用浅红色 `-`；新增行使用黄绿色 `+`。空白新增
  或删除行仍保留标记和行号。
- 替换固定先显示删除的旧行，再显示增加的新行。仅删除时不添加虚假的空新增行。
- 多行替换计算最小逐行差异，不把实际未变化的整块内容全部标记为删除和新增；当前不增加
  逐字符高亮。
- 默认展示修改位置之前和之后最多三行上下文，其余文件内容用 `...` 省略。
- 差异不超过二十行时完整展示所有变化；超过二十行时保留前十行和后十行变化，全局
  `Ctrl+O` 展开或折叠全部工具记录中的完整差异。
- 工具调用提出后，蓝色卡片显示准备执行的差异；成功后原地变为绿色；失败或执行中断后
  原地变为红色并保留尝试的差异。
- 找到唯一匹配时显示真实行号和上下文。找不到或存在多个匹配时，不伪造文件位置，只显示
  无行号的旧内容和新内容，并附加固定安全原因及“文件保持不变”。
- 已完成的绿色卡片不会因为后续 Run 被中断而改成红色。

### 11.3 `read`

`read` 使用单行、无外框的紧凑状态卡片，只展示工具名和实际读取的工作区相对路径，不展示
文件正文、行号、文件大小、读取行数、耗时或结果摘要。

```text
read  docs/tui_design.md
```

- 工具名与路径样式和 `write` 一致，路径使用浅青蓝色和下划线。
- 执行期间卡片为深蓝色，读取成功后同一行原地变为深绿色。
- 读取失败或中断后原地变为深红色；必要时在同一行末尾追加简短安全原因，不展开为多行
  错误面板。
- 多个 `read` 调用分别保留一行，并按 Engine 的实际执行顺序出现。

### 11.4 `bash`

`bash` 卡片分为命令区和动态输出区。开头展示 Agent 实际提交的完整命令；TUI 可以折叠
显示，但不得截断或改写真正交给 Bash 的命令。

```text
bash

$ uv run pytest \
    tests/test_engine.py \
    tests/test_tool_executor.py \
... (4 more display lines, ctrl+o to expand)
```

- 命令保留原始引号、转义符、换行和连接符，不转换成 PowerShell 或重新排版。
- 命令区默认最多占三行显示高度；长单行发生软换行时也按屏幕显示行计算。
- 全局 `Ctrl+O` 展开或折叠所有终态工具中的完整命令；执行始终使用完整原始命令。
- 已识别的凭据在显示层替换为 `[REDACTED]`，但折叠不能改变命令执行语义。
- 需要权限确认时，先显示准备执行的命令，再打开独立权限窗口。

用户允许后，在命令下方动态更新合并后的 stdout/stderr。活动工具无论全局展开状态如何，
始终只显示最新八条逻辑行及准确的 earlier-lines 提示；完整安全缓冲继续保留在既有工具输出
上限内，但卡片不建立内部视口、不接收滚动键，也不显示未读行提示。

```text
bash

$ uv run pytest -q

... (42 earlier lines, ctrl+o to expand)
tests/test_cli.py ............................
tests/test_engine.py .........................
tests/test_file_tools.py .....................
tests/test_jsonl_store.py ....................
tests/test_session_service.py ................
tests/test_tool_executor.py ..................
tests/test_workspace.py ......................
850 passed, 1 skipped
```

- 执行期间卡片为深蓝色；退出码为 `0` 后原地变为深绿色。
- 成功但没有输出时显示 `(no output)`。
- 非零退出、启动失败、超时、输出超限或执行中断时原地变为深红色，保留已经显示的安全
  输出，并在末尾显示 `exit N` 或固定失败原因。
- 完成后默认保留最后八行；更早内容用 `... (N earlier lines, ctrl+o to expand)` 折叠。全局
  展开已开启时，终态立即改为完整安全输出；运行中的实时预览仍保持八行上限。
- 动态输出仍受现有总字节上限、凭据清洗、取消和进程树回收边界约束。

### 11.5 `ask`

`ask` 是专用交互工具，不使用普通用户消息卡片。等待回答时在唯一底部交互覆盖层中显示带
浅青色上下分隔线的深色选择面板；上方 transcript 保持可见，普通状态条、composer 和 facts
暂时被覆盖。可选标题位于低调的灰色标签中，问题使用明亮文字，当前选项使用 `›` 和浅青色，
说明文字使用缩进灰色，推荐项必须由 Agent 明确提供。

```text
────────────────────────────────────────────────────────

 后续任务

你希望我接下来进行哪种工具测试？

› 1. 读取文件（推荐）
     使用读取工具查看刚才修改后的文档内容。

  2. 执行命令
     使用终端命令检查工作区文件及其基本信息。

  3. 再次编辑
     继续修改文档中的指定内容。

  4. 网络搜索
     使用联网搜索工具查询指定主题。

  5. Type something.

────────────────────────────────────────────────────────
Enter 选择 · ↑/↓ 移动 · n 添加备注 · Esc 取消
```

- 活动 Ask 将输入控制器切换为唯一 `ASK` 模式，独占 `↑`/`↓`、数字键、`Enter`、`n`、
  `Esc` 和自己的文本输入；终端失焦不改变该模式，恢复后的第一发方向键立即生效。
- `↑`/`↓` 移动，数字键直接定位，`Enter` 确认，`n` 为当前选择添加备注。
- 选择 `Type something.` 后在面板内打开文本输入；回答只进入 `ask` 工具结果，不形成普通
  USER 消息或新的 Run。
- `Esc` 取消当前 `ask` 并中断本轮 Run；`Ctrl+O` 只控制工具卡片，不改变 Ask。
- 活动交互层与 transcript 中的 Ask 记录职责分离。回答完成后覆盖层关闭，真实工具调用位置
  的记录折叠为绿色只读状态，例如
  `ask  问题` 与下一行 `→ 已选答案`；添加的备注显示在答案下方。
- 完成后的记录保持只读且不能重复提交；当前不提供重新展开原选项的快捷键。
- 取消或交互失败时折叠为红色记录；回答不会被渲染成用户消息卡片。

该界面所需的 `ask` 公共参数已经扩展为可选标题、问题、二至四个结构化选项、选项说明、
最多一个推荐项和是否允许自定义回答。没有结构化选项时，仍降级为单个自由文本问题，不伪造
选择项。

### 11.6 扩展与未知工具

没有专用展示实现的扩展或未知工具使用紧凑的通用兜底卡片，只显示工具名称和确有必要的安全
原因，不添加 `tool` 前缀或 `running/completed` 状态词。卡片继续复用统一状态色：准备/执行为
深蓝色，成功为深绿色，失败/取消为深红色；NO_COLOR 使用状态符号。

```text
● custom_tool
```

成功终态只通过绿色背景或 `✓` 表达；失败/取消保留固定安全原因。当前通用展示快照不包含
可安全显示的参数与结果正文，因此兜底卡片不创建空参数区、空结果区，不显示
`tool details are unavailable`，也不提供无内容可展开的 `Ctrl+O`。v1/v2 或缺少展示快照的历史仍使用
`tool <name> · recorded`。

通用卡片只是默认回退，不是扩展工具的永久视觉限制。前端卡片解析应保留单一、明确的工厂
或解析接缝：未来扩展系统可以为特定工具提供经过安全校验的展示快照与专用卡片，并在该接缝
优先匹配；未匹配或不支持自定义展示时才回落到通用卡片。当前阶段不建立扩展注册系统，不扩
展工具展示 wire，也不允许自定义卡片直接读取原始参数、ToolResult、Provider、Executor、
Store、工作区或进程状态。

### 11.7 权限确认面板

**已确认的呈现**：权限请求使用唯一底部交互覆盖层中的横向选择区，顶部用一条浅蓝色横线与
上方对话分隔；采用终端深色底色，不使用居中悬浮框。上方对话与待授权工具记录保持可见，
普通状态条、composer 和 facts 在等待期间被覆盖，已有草稿保留但不能接收输入。

- 面板按顺序展示操作类型、待授权命令或文件相对路径、可用的操作说明、确认问题、编号
  选项和底部按键提示。命令直接显示在面板中，用户不必离开权限区查找授权对象。
- 标题与当前选择标记使用 Mica 蓝色，正文使用普通前景色，说明和按键提示使用灰色。
- 选项采用 `› 1. Yes` 的纵向列表，初始定位到一次允许项；定位本身不提交响应。
- 活动权限交互将输入控制器切换为唯一 `PERMISSION` 模式，独占 `↑`/`↓`、ASCII 数字键、
  `Enter` 和 `Esc`；终端失焦不改变该模式，恢复后的第一发方向键立即生效。
- `↑`/`↓` 移动，ASCII 数字键定位，`Enter` 确认；`Esc` 请求取消当前 Run。
- 面板展示内容来自现有安全展示快照和公共权限事件；不从原始参数、工作区或 Shell 状态
  补造信息。缺少额外操作说明时省略该行，不生成虚假的模型解释。

**确认范围**：只显示 `1. Yes`（一次允许）和 `2. No`（拒绝该工具调用）；`Esc` 取消当前
Run，不等同于拒绝一个工具。`default` 仅在后端产生风险确认事件时显示，`solo` 不产生权限
询问；前端不自行判断命令风险，也不自动批准。记住允许规则、修改命令和请求解释不在本轮
范围，不显示对应选项或快捷键。面板关闭后不进入历史，由对应工具卡片继续更新；Run
