# Mica 第四阶段：仓库收口与旧实现清理

> 状态：已完成
> 上位约束：`PROJECT_PLAN.md`
> 前置阶段：`docs/phase3_plan.md`

## 1. 阶段目标

将仓库收口为只包含 Mica 的产品工程：移除此前仅作参考的应用实现及其资源，统一项目名称、文档和测试边界，并将本地工作目录改名为 `mica_agent`。

## 2. 构建范围

- 删除旧应用的根目录核心、启动器、前端、资源、记忆、自治和插件目录。
- 删除旧重构讨论文档，移除公开文档、阶段计划、测试与忽略规则中的历史项目表述。
- 保留 Mica 源码、测试、许可证、构建配置、阶段计划和构建日志。
- 将仓库内的项目说明统一为 Mica；`mica-agent` 保持为发布包名，`mica_agent` 保持为 Python 包名和当前本地工作目录名。
- 在 Git 当前版本中完成删除并提交；历史提交保留，且不进行历史重写。
- 在清理提交后将工作目录改名为 `mica_agent`，重建本地虚拟环境并复验。

## 3. 明确不包含

- 不实现工具、权限、TUI、配置系统、扩展或任何新的产品功能。
- 不改变已有 Mica 的公开运行语义、Provider 协议或会话格式。
- 不迁移旧应用的用户数据、配置或接口。
- 不重写 Git 历史、不推送远程仓库、不发布包。

## 4. 验收标准

- Git 当前版本中不再包含旧应用的源码、启动器、前端、资源、记忆或自治目录。
- `src/mica_agent/` 仍是唯一 Python 产品源码包，`mica` 仍是唯一终端入口。
- 文档、测试名称和仓库根目录中不再将当前产品描述为历史应用的重建或兼容版本。
- `uv run pytest`、`uv run ruff check src/mica_agent tests`、`uv run ruff format --check src/mica_agent tests`、`uv build --offline` 和 `git diff --check` 通过。
- 改名并重建环境后，`uv run mica --version` 与安装态基础验证通过。

## 5. 风险与注意事项

- 目录改名会使现有 `.venv` 中记录的绝对路径失效；必须重新执行 `uv sync --python 3.11`。
- 当前版本删除不等于抹除 Git 历史；旧内容仍可通过历史提交恢复。
- 本阶段不读取或改写第三阶段构建日志。
