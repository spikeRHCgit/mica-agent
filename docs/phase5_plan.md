# Mica 第五阶段：终端交互前端

> 状态：已完成；P5-01A～P5-11C、P5-10G1～G2 与 P5-11C-MR3 均已通过自动化、构建、master 复审和用户真实 Windows Terminal 验收
> 上位约束：`docs/PROJECT_PLAN.md`
> 视觉与交互事实源：`docs/tui_design.md`
> 前置阶段：`docs/phase4_plan.md`
> 实施原则：任务单默认覆盖一个可独立验收、提交和回退的中等体量完整功能块；只有跨越多层高风险契约、持久化迁移或明显不同的运行链路时才继续拆分。

## 1. 阶段目标

第五阶段把现有基础文字 CLI 升级为可持续使用的终端交互前端。首轮 Textual 全屏实现已建立
完整事件投影和视觉能力，但真实 Windows Terminal 反复暴露内部滚动、焦点和输入所有权问题；
默认前端因此迁移到主缓冲区上的轻量保留式渲染。界面继续只消费 MicaApp、SessionService 和
Engine 的公共契约，不读取 Provider、ToolExecutor、Store 或文件工具私有状态。

阶段完成后，用户可以在一个稳定终端界面中：

- 查看响应式 Mica Logo 和本次会话实际加载的启动资源。
- 查看当前会话已经持久化的用户、模型和工具历史。
- 使用支持软换行、多行增长和粘贴摘要的底部输入区提交文字指令。
- 观察唯一的动态 `Mica · working...` 状态、终态耗时、思考内容和正式模型回复。
- 查看 `read`、`write`、`edit`、`bash` 的动态工具卡片。
- 在专用面板中回答结构化 `ask` 和处理权限确认。
- 在输出、工具、权限或 ask 等待期间可靠取消，不留下后台任务；被中断或可恢复失败的轮次以
  明确的中断检查点保存，不冒充完整成功轮次。

## 2. 范围边界

### 2.1 本阶段包含

- 主缓冲区终端运行框架、保留式语义文档、差分渲染、主题和终端能力降级。
- 终端拥有背景、scrollback、鼠标滚动和退出后的历史；Mica 不进入 alternate screen，
  不捕获鼠标滚轮，也不维护第二套 transcript 视口。
- 启动头部、会话历史、用户消息、模型思考和正式回复。
- 底部输入框、粘贴摘要、动态环境事实，以及输出始终插入输入区上方的重绘协调。
- 唯一工作状态及 working、done、stop、error 状态。
- 已确认的五个内置工具呈现，其中 `ask` 使用交互面板。
- 权限确认窗口及与 InteractionBroker 的响应闭环。
- 用户确认的两模式权限重构：先完成后端与基础 CLI，再消费公共事件实现权限面板。
- 前端生命周期、事件流关闭、Provider 关闭和安装态终端验收。
- 保留基础文字 CLI 作为明确的降级入口；最终入口名称需由用户在本计划审查时确认。

### 2.2 本阶段不包含

- JSON 配置、首次配置向导、模型发现或切换、思考强度配置界面。
- 会话新建/重命名/分支/回退/清空的 TUI 命令界面。
- `/help`、`/model`、`/config`、`/compact` 等斜杠命令系统。
- 摘要压缩、上下文 token 计算、费用统计或 Prompt Cache 统计。
- 图片、文件附件和其他多模态输入。
- Skill、MCP、扩展发现或扩展管理界面。
- 工具并行调度、工作区副作用回滚、执行沙箱、网络隔离或两模式之外的权限能力。
- 除中断轮次恢复所需的一次受控会话版本升级外，不扩展会话命令、摘要压缩或其他持久化能力。

上述能力分别留给 Phase 6、Phase 7、Phase 8 或 MVP 后续迭代。TUI 可以预留普通布局位置，
但不得创建空命令、假数据、不可用按钮或未来扩展注册表。

## 3. 已确认的产品规则

具体颜色、文案、折叠行数和交互效果只以 `docs/tui_design.md` 为事实源，本计划不复制正文。
以下边界用于施工和验收：

- 用户消息和 Mica 回复均左对齐；用户消息使用蓝色左侧短线与轻灰背景，模型回复不使用卡片。
- 全界面只有一个工作状态条，固定在输入框正上方；Run 结束前动画持续存在。
- 思考正文与正式回复分流。完整、折叠或隐藏由用户设置决定；思考内容不响应 `Ctrl+O`，
  持久化偏好和设置界面留给 Phase 6。
- 一次工具调用只创建一张卡片，状态在原卡片更新；蓝色表示执行中、绿色表示成功、红色表示
  失败或中断。标题不添加 `running/completed` 状态词；无颜色模式使用稳定状态符号和安全原因。
- `Ctrl+O` 统一展开或折叠当前会话内所有具有合法安全展示快照的工具卡片；活动工具即使在
  展开模式下也只显示按工具类型确定的有界实时预览，终态后再显示完整安全结果。
- Engine 当前顺序执行工具，TUI 必须按真实事件顺序呈现，不模拟并行。
- 历史恢复只读取持久化消息和 v3 工具展示快照，不重放动画、不重新运行工具、不读取工作区
  推断旧差异。
- 所有凭据清洗、工作区边界、权限判断、取消和会话提交语义继续由现有后端负责。

## 4. 技术方案

### 4.1 依赖与迁移基线

- Python 最低版本继续为 3.11；`uv.lock` 固定阶段验收环境。
- P5-11A 先在现有安装中建立可真实运行的主缓冲区纵向闭环；如需增加输入、ANSI 解析或终端
  渲染依赖，必须说明它消除的实际复杂度并锁定版本，不引入 Web 或通用前端状态管理框架。
- 旧全屏前端已在 P5-11C 退役：默认 `mica cli` 使用主缓冲区终端前端，`--plain` 保留基础
  文字降级，临时 `--main-buffer-preview` 已删除。
- 测试以虚拟终端、原始输入字节、渲染帧和公共事件集成为主，不用固定 `sleep()`；框架级
  headless 结果不能代替真实 Windows Terminal 验收。

### 4.2 包边界

`src/mica_agent/tui/` 继续作为前端包。P5-11 在独立的 `main_buffer/` 子包中实现主缓冲区
渲染、输入和组件模块；旧全屏前端已删除，不得再引入第二套 transcript 视口：

```text
src/mica_agent/tui/
  main_buffer/
    screen.py       主缓冲区前端编排与公共动作
    renderer.py     语义文档、差分帧和终端控制
    terminal.py     原始输入、尺寸、能力与主缓冲区输出
    editor.py       composer、粘贴和底部事实区
    components.py   启动、消息、状态与基础展示组件
    interactions.py ask 与权限的独占输入模式
    runtime.py      单 Run、事件消费、响应、取消与关闭
    markdown.py     正式回复的安全 Markdown 渲染
    sanitize.py     不可信正文清洗接缝
    tool_views.py   工具专用折叠/展开呈现和工厂接缝
```

实际文件可在单个切片内按最小实现合并，但不得形成一个同时拥有布局、会话、工具、输入和权限
的巨型模块。新增或调整文件后同步维护 `docs/module_map.md`。

### 4.3 数据流

```text
CLI 装配与会话选择
  -> 冻结启动资源快照 + 已加载 StoredSession
  -> 主缓冲区终端前端
     -> 历史投影到保留式语义文档
     -> 用户提交文本到 MicaApp.run()
     -> EngineEvent 按 seq 投影到现有组件
     -> PermissionResponse / UserInputResponse 回到 MicaApp
     -> 组件变化产生差分帧并重绘应用文档
     -> Run 终态更新工作状态并恢复输入区
```

前端不拥有正式业务状态。组件展开偏好、编辑草稿、选择位置和动画帧属于界面状态；终端滚动
位置由终端拥有；会话、工具结果、权限和交互 pending 状态继续由现有服务拥有。

### 4.4 启动资源快照缺口

`ContextBuildResult` 当前提供消息与安全诊断，但没有直接说明哪些 AGENTS.md 成功加载。TUI 不得
解析 `<INSTRUCTIONS>` 内容或重新读取文件，因此在布局实现前增加兼容的不可变来源快照：

- 明确 global/workspace AGENTS.md 是否成功加载。
- 保持 `ContextBuildResult(messages, diagnostics)` 旧构造兼容。
- 不携带绝对路径、文件内容、系统提示词正文或原始异常。
- 系统提示词、工具名、Skill/扩展 `none` 状态由装配层使用已经存在的启动事实组合。

该契约已经由 P5-01A 完成，主缓冲区前端直接复用，不重新读取文件。

## 6. 关键行为与验收边界

### 6.0 两模式权限迁移

本节是已确认的目标，P5-07A 两模式后端迁移已完成；当前 TUI 权限交互仍由 P5-07B 独立实施，
不得与 Phase 6 配置系统或沙箱工程合并。

- 公开模式只保留 `default`、`solo`；删除 ACCEPT_EDITS 与 CLI 的 accept-edits，旧值由
  参数解析拒绝，不留静默别名。new/continue/resume 使用同一装配路径。
- default 普通 read/write/edit、Bash 日常操作自动允许；受保护文件路径（复用现有集中
  分类）需一次确认，不再在 handler 中永久拒绝已经批准的访问。自定义未知工具默认询问。
- solo 在合法工具与合法参数上直接允许，跳过命令风险规则、allow_rules 和 hard_denied
  等权限策略；不请求 PermissionResponse。模型不能自行切换模式。
- 保留文件工具的现有能力契约：工作区相对路径、普通 UTF-8 文件、大小限制和唯一匹配编辑。
  不在此任务新增绝对路径、父目录跳转、链接跟随、设备或二进制文件支持。这些是工具能力
  边界，不称为 solo 的宿主机隔离；跨工作区操作仍可通过 Bash 执行。
- Schema、未知工具、非法参数、OS 权限、超时、输出限额、取消、进程回收、脱敏和原子提交
  不因 solo 关闭。ask 需求交互不属于权限审批，继续保持。

命令分析使用独立纯函数模块，不调用模型、不执行探测命令、不读取脚本、不建立完整 Bash
解释器；结果只表达“未命中规则”“需要确认”，不能命名或宣传为已证明安全。

- 至少对删除命令 rm/rmdir/unlink/shred、磁盘格式化/块写入 dd/mkfs、提权 sudo/su、
  关机/重启、权限所有权修改 chmod/chown 请求确认；basename 识别路径形式及 .exe 形式。
- Git 的 reset --hard、clean、checkout/restore 丢弃修改、branch -D、push 请求确认；
  status/diff/log/show/add/commit 自动执行。保守地对全部 checkout/restore 询问可接受。
- 明显解释器内联执行（bash/sh -c、python -c、node -e 等）、eval/source、命令替换、
  不能可靠拆分的 Shell 结构或解析失败请求确认。普通脚本与测试运行不读取其内容审查，
  也不声称覆盖其中副作用。未知普通可执行程序不因名称未知而一律询问。
- 识别分号、换行、&&、||、管道中的各个命令；任一需要确认则整个原始调用只询问一次。
  处理引号和常见 env/command 包装，不能把 echo 的普通字符串误当执行命令；不支持的包装
  语义保守询问。只分析，不改写执行字符串。
- 普通 curl/wget 等网络访问不单独询问；管道交给 Shell 执行、明显写入受保护路径或动态
  重定向目标需确认。相对工作目录变化无法可靠解释时询问，不假装已正确推导目标。
- 本轮没有 OS 级文件/网络隔离，不保证拦截任意脚本、间接副作用、编码命令或数据外传；
  工作区 cwd 不是沙箱。风险规则是有限防误操作能力，不作为安全证明。

风险命中继续通过现有 Broker/PermissionRequested/PermissionResponse，Yes 仅批准该调用，
No 返回 PERMISSION_DENIED，取消沿用 Run 语义；不修改事件 Schema 或持久化版本。
受保护文件的展示仍可使用现有固定安全降级，不放宽快照中的路径和凭据过滤。注册文件工具
的直接 handler 是底层执行能力，产品统一通过 ToolExecutor 完成授权；不得并存两套互相
冲突的权限检查。现有 PolicyFactFactory 接缝若需要扩展，应保持旧位置参数兼容并补充默认值。

验收应同时覆盖普通操作不询问、风险操作执行前等待、拒绝不产生副作用、solo 不询问、
受保护路径批准后真实可用、取消无半轮、五工具顺序和安装态 new/continue；真实破坏性命令
只验证分类或使用记录调用的假 handler，真实文件操作只用隔离临时目录与虚构凭据。

### 6.1 事件投影

- 每个活动 Run 以 `run_id` 隔离，严格按 `seq` 消费；重复、倒序或迟到事件不得修改其他 Run。
- `run_id` 只标识整轮运行，不能作为唯一模型回复组件身份。一次 Run 内每个模型步骤拥有独立
  的思考/回复片段；首个 `ToolPrepared` 结束当前模型步骤，工具完成后的新 Delta 必须创建在
  上一批工具卡片之后。连续属于同一模型步骤的 Delta 仍更新同一组件。
- ToolPrepared 创建卡片，ToolStarted 更新执行态，ToolOutputDelta 只追加到匹配 Bash 卡片，
  ToolFinished 使用最终 presentation 原地收口。
- 一次模型返回多个工具调用时，卡片按 Engine 当前的顺序执行和显示；下一模型步骤的思考与
  回复只能出现在该批工具之后。测试必须断言语义文档与渲染行的真实顺序，不能只检查组件存在。
- RunCompleted、RunFailed、RunCancelled 只产生一个界面终态，不伪造模型文字或工具结果。
- 纯界面状态不进入 JSONL；P5-10G 允许 MicaApp 通过新的公共中断检查点原子保存真实用户指令
  和已经发生的安全进度，但不得把它伪装成现有完整 `TurnEntry`。

### 6.2 输入与取消

- 软换行只影响显示，不给提交文本增加换行；用户真实输入的换行保持原样。
- 大段粘贴占位属于当前编辑器状态，基础 TUI 完成后再讨论是否升级会话格式保存该元数据。
- `Esc` 在普通模型输出、工具执行、Ask 等待和权限等待期间都请求取消当前真实 Run；单次
  `Esc` 不退出 TUI，也不把取消伪造成拒绝或空回答。
- 第一次 `Ctrl+C` 不退出 TUI：活动 Run 中先请求取消，空闲时进入短时退出待确认状态；只有
  在约两秒内收到第二次可观察按键才退出。同一输入批次内由按键、原生信号或重复分发产生的
  近同步重复必须合并，不能计为第二次；超时后的下一次按键重新作为第一次处理。新终端输入
  层应保留可取得的按键身份；平台仍不提供 key-up 或重复计数时必须如实披露剩余限制。
- 普通 composer 必须支持左右/上下/Home/End 在可见文本中移动真实编辑光标，并能在中间插入、
  Backspace 或 Delete；不得破坏长粘贴片段的原子移动和删除规则。
- 取消、EOF、窗口关闭和事件流提前关闭必须等待 Broker、Engine、Provider 与 Bash 清理完成。
- 主动取消、Provider 流异常等可恢复终止还必须保留原始用户指令和截至终止点的结构完整安全
  进度。未执行的工具不得伪造成已执行，原始异常、未清洗参数和凭据不得写入上下文。

### 6.3 阻塞交互与输入所有权

- 输入层只有 `IDLE`、`RUNNING`、`ASK`、`PERMISSION` 等显式模式，不依赖 DOM 组件焦点或终端
  `AppFocus` 事件决定按键归属。失焦期间不改变模式，恢复后的第一发原始按键按当前模式处理。
- `RUNNING` 保留可见但禁用的 composer 与环境事实；Ask 或权限等待时，其交互组件替代整个
  工作状态、composer 和事实区域，并独占数字键、上下键、Enter、Esc 及自身文本输入。
- Ask/Permission 活动时隐藏 `Mica · working...`；交互完成且 Run 继续时恢复动态 working、
  禁用 composer 与事实区。已有 composer 草稿不得丢失或接收交互按键。
- 终端拥有 PageUp/PageDown、鼠标滚轮和右侧滚动条；前端不实现 transcript 或 Bash 卡片内部
  滚动，也不捕获鼠标滚轮。Ask/Permission 内容超过可视高度时采用终端宽度感知的紧凑呈现，
  不能重新建立应用级历史滚动区。
- Ask 的活动交互与完成记录职责分离；完成记录保留在真实工具调用位置。Permission 结束后
  不进入会话历史，既有工具记录继续按生命周期更新。

### 6.4 历史与安全

- v3 历史使用 `TurnEntry.tool_presentations`；v1/v2 缺少展示快照时只显示兼容的简化记录。
- UI 错误只显示稳定安全消息，不展示 traceback、Key、绝对 HOME、Provider 原始响应或工具
  未清洗参数。
- 工具卡片不显示 `running/completed` 等冗余状态词；彩色模式以大面积背景表达生命周期，
  NO_COLOR 下使用 `○/●/✓/×/■` 等稳定符号和安全原因，颜色不是唯一状态表达。

### 6.5 主缓冲区渲染与底部区域

- 首帧直接输出到终端主缓冲区，不发送 alternate-screen 或鼠标捕获控制序列；退出后对话内容
  保留在终端 scrollback。终端背景不得被全屏填色，只有用户消息、代码块和工具卡片等局部组件
  可以使用语义背景。
- 前端在内存中保留当前会话的安全语义组件文档。普通模型增量、工具输出和动画只差分重绘
  变化尾部；`Ctrl+O`、终端宽度变化或较早组件高度变化可以受控重绘更大范围，但不得丢失输入
  草稿、事件顺序或终端 scrollback。
- 新输出始终位于底部输入区上方。空闲时 composer 可编辑；Run 期间 composer 保持可见但禁用，
  下方事实区继续显示工作区/分支、模型和会话名称或短 ID。
- 环境事实区与工作状态分离。模型切换、会话重命名或会话切换后立即刷新；Git 分支在恢复输入
  状态时刷新，不使用 Timer 轮询，不访问 Provider、Store 或 Executor 私有状态。
- Run 开始到完整终态持续显示带原动态点效果的 `Mica · working...`，不显示阶段或进行中耗时；
  Ask/Permission 活动期间隐藏。成功后显示实际耗时 `Mica · done(8s)` 或
  `Mica · done(1m 24s)` 约两秒再消失；主动中断显示持久 `Mica · stop`，其他运行失败显示持久
  `Mica · error`，二者到下一次 Run 开始才由 working 替换。
- `Ctrl+O` 只统一控制全部工具卡片，不改变思考、Ask 或普通消息。活动工具始终使用各工具的
  有界实时预览；终态后才按全局展开状态显示完整安全快照。v1/v2 或被后端截断的内容不得补造。

## 7. 测试策略

每个任务先连续完成计划内的功能闭环，再运行一组覆盖关键公共行为的聚焦测试；只有测试暴露
问题时，才针对失败路径做最小修改并重跑相关测试。不要把验收矩阵机械拆成逐条 RED、逐条
测试或反复全量验证，也不要在没有不稳定证据时做多轮重复运行。

聚焦测试按任务实际风险选择纯组件渲染、虚拟终端、原始输入字节、公共事件集成、取消与资源
清理、安全不泄漏等代表场景。聚焦通过后，再统一执行一次兼容、分发、全量和质量门槛；只有
真实出现间歇失败、资源警告或时序竞态时，才增加稳定性复跑。

阶段安装态验收使用构建后的 wheel、隔离临时 HOME、Unicode 与空格工作区、loopback SSE 和
真实 Windows 终端能力。自动化测试不得访问真实 Provider、真实 Key、真实 HOME 或外部网络。

统一质量门槛：

```text
uv run pytest
uv run ruff check src/mica_agent tests
uv run ruff format --check src/mica_agent tests
uv build --offline
git diff --check
git diff --cached --check
```

涉及界面构图的任务还必须读取 `docs/assets/tui/README.md` 指向的正向目标和负向问题截图，在
相同或可比的终端尺寸、相同初始状态下生成实现截图并做并排审查。自动化测试、组件文档顺序
断言和构建成功不能替代截图对照与用户手工视觉验收。

P5-11A 必须证明首帧和运行期均不发送 alternate-screen 或鼠标捕获序列；真实 Windows Terminal
中鼠标滚轮、右侧滚动条和终端自身的 scrollback 快捷键由终端管理，长时间失焦后第一发
Ask/Permission 方向键仍由显式输入模式接收。P5-11B 必须同时验证：用户消息、思考、正式回复与
工具色块具有明确的视觉层级；终态正式回复完成 Markdown 渲染；`Ctrl+O` 同时改变全部历史工具
组件而不破坏事件顺序、当前视口、输入草稿和 NO_COLOR 状态表达。自动化通过后仍由使用者完成
真实终端复验。

P5-11C-MR2 的验收边界（自动化证据只是其中一半，真实 Windows Terminal 复验由使用者完成）：

- 真实 Windows Terminal 的普通物理 `↑`/`↓` 必须稳定进入 main-buffer 输入控制器；零字符
  VirtualKeyCode 记录走后备映射，标准 VT 字符序列与后备不得为同一个物理按键发两次键，
  key-up 不得成为第二次按键。
- 单独 `Esc` 经有界一次性 flush 后必须取消真实 Run；完整 `ESC[A`/`ESC[B` 不得被拆成
  `Escape` 加文本，也不得伪造拒绝回答或空回答。
- `ask` 的 `Type something.` 必须能提交真实自定义答案（`selected_option_index = None`），
  自定义状态可以返回固定选项并保留草稿，空答案与业务响应拒绝必须可见、可重试。
- 超高 Ask/Permission 面板必须保证当前选中项可见，不得依赖渲染器从顶部静默裁掉选中行，
  也不得为交互建立应用内部滚动区或捕获终端滚动键。窗口选择必须把当前选中行当作硬约束
  （`0 <= selected_row < len(visible)` 且该行就是当前选择），提示行、问题主句与上下隐藏
  计数只能是次级目标；多行拒绝提示不得挤掉当前选择。
- 提示清除只跟随被消费的有效输入（`↑`/`↓`、有效数字、文本编辑/`Backspace`/`Delete`、
  `Enter` 重试、备注/自定义状态转换）；`PageUp`/`PageDown`、未知功能键与越界数字不得清除
  拒绝提示，再次提交仍被拒绝时提示必须重新出现。
- P5-11C 的默认入口切换、旧前端退役与 `--plain` 兼容行为保持不变；Engine、Provider、
  权限策略、Broker 校验、事件 Schema 与会话格式不改。

P5-10G 的测试必须区分完整成功轮次与中断检查点，覆盖取消、Provider 流失败、工具批处理中断、
旧 v1/v2/v3 会话读取与升级、恢复后的 Provider 上下文顺序，以及不泄漏异常/凭据/绝对路径。
不得为了满足旧 `TurnEntry` 校验而伪造模型回复或把未执行工具标为成功。

## 8. 阶段完成标准

- `mica` 的已确认入口可以启动完整主缓冲区前端，并保留可用的基础文字降级入口；不进入
  alternate screen，不捕获鼠标滚轮，退出后对话仍在终端 scrollback。
- 启动页、历史、输入、工作状态、思考、模型回复、四类执行工具、ask 和权限窗口均符合
  `docs/tui_design.md`。
- 一轮真实 loopback 工具对话可以在终端前端中完成、写入当前会话格式、退出并恢复历史；中断轮次
  也能以不同于成功 `TurnEntry` 的检查点恢复。
- 运行中取消、权限等待取消、ask 等待取消、Bash 取消和窗口关闭都不写伪造的完整轮次、不留后台
  任务；需要继续工作的真实进度以中断检查点原子保存。
- 同一 Run 内多次模型调用、多个工具与最终回复按真实事件顺序交错显示，不把文字和工具分别
  聚合成两堆；Ask/权限交互在失焦恢复后仍可用，活动时不会把输入泄漏给 composer。
- 长时间失焦恢复后，Ask/权限和 composer 均按显式输入模式稳定工作；终端原生 scrollback
  保持可浏览。一次
  明确短按 `Ctrl+C` 不退出、两次明确短按才退出，持续按住时的延迟自动重复风险已如实披露；
  composer 可在任意普通文本位置编辑。
- 主动取消或可恢复 Provider 失败后，下一次模型调用和重启恢复都能看到原始用户指令及已经
  发生的安全进度，并明确知道该轮未完整完成。
- 终端宽度不足、无真彩色或禁用颜色时存在稳定降级，不影响主要操作。
- 所有工具卡片使用状态色块与无颜色符号；`Ctrl+O` 可统一展开/折叠当前会话内的全部合法工具
  快照，活动工具仍保持有界动态预览。
- 全量测试、安装态测试、离线构建和用户手工冒烟全部通过。

## 9. 用户审查结论

- Phase 5 的默认主缓冲区前端、历史与工具呈现、Ask/Permission、输入编辑、终端恢复、取消及中断进度恢复已经通过最终真实 Windows Terminal 冒烟；阶段正式完成。
- `mica cli` 默认进入主缓冲区终端前端，`--plain` 保留基础文字降级入口；旧全屏前端已退役。
- Phase 5 的底部事实区显示工作区与 Git 分支、当前模型、`sessions:` 加会话标题或短 ID；
  模型切换、会话重命名和会话切换后同步刷新。当前不显示权限、运行耗时、工具数和快捷键栏。
- Run 期间 composer 保持可见但禁用，事实区继续显示；Ask/Permission 替代整个底部交互区并
  隐藏 working、composer 和 facts，交互完成且 Run 继续时恢复。
- `Mica · working...` 保留动态点效果且不显示进行中耗时；成功终态以 `done(8s)` 或
  `done(1m 24s)` 显示实际耗时约两秒后消失；主动中断的 `stop` 与其他失败的 `error` 保留到
  下一次 Run 开始。
- 扩展/未知工具使用紧凑安全兜底卡片；未来扩展可以在统一解析接缝提供专用展示，当前阶段
  不建立扩展注册系统或扩展展示 wire。
- Ask 与权限确认采用统一底部阻塞式交互层，覆盖普通固定控制区并保持上方 transcript 可见；
  权限只提供一次允许和拒绝，记住规则、修改命令与解释按钮不在本轮范围。
- `Ctrl+O` 只统一展开/折叠所有工具卡片，不改变模型思考、Ask 或普通消息；思考内容仅服从用户
  设置。工具标题不显示 `running/completed`，彩色状态由整块背景表达，NO_COLOR 使用符号兜底。
