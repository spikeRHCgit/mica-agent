# Mica 配置与模型规格

> 本文是配置、登录、模型目录、连接选择、共享设置和恢复行为的主文档。规则已由 Phase 6 需求讨论确认，尚未实现，不是当前使用手册；改变规则先经用户确认。阶段交付和验收见 `docs/phase6_plan.md`。

## 1. 范围

本文管配置文件、来源、生效、安全保存、供应商、模型、接口、登录和会话恢复。菜单布局、键位、输入所有权和视觉规则见 `docs/tui_design.md`，不在本文另写一套。具体新增类型、wire 字段和认证依赖在对应交付项编码前审查，不授权改变已确认需求。

渠道只包括 ChatGPT 官方订阅、OpenRouter、DeepSeek、OpenCode Go 和自定义供应商，支持多个连接与同名模型，不扩充大量预置渠道。接口为 `openai-completions`、`openai-responses`、`anthropic-messages`；模型可覆盖供应商默认接口。取消内置工作模式及 `workMode` 字段，Mica 不与 aTa 捆绑。

## 2. 文件、字段与凭据

全局使用三份简单 JSON；工作区只使用 `<workspace>/.mica/config.json`。不增加配置 `version` 或版本迁移系统。

| 文件 | 内容 |
|---|---|
| `~/.mica/config.json` | `defaultModel`（`provider` + `model`）、`reasoningEffort`、`permissionMode`、`reasoningDisplay`。后三项默认分别为 `off`、`default`、`collapsed`。 |
| `~/.mica/models.json` | `providers` 按稳定供应商 ID 索引；供应商声明显示名称、渠道类型、`enabled`、`baseUrl`、默认 `api` 和 `models`。模型保存 `id`、可选名称、接口覆盖、`contextWindow`、`maxTokens`、`input`、`reasoning`、`thinkingLevelMap`。 |
| `~/.mica/auth.json` | 按供应商 ID 保存有类型的 API Key 或 OAuth 凭据；订阅记录含验证后的身份、issued client ID、tokens、授权范围、到期信息和本机稳定 host ID。菜单只显示安全标签与状态，不显示 token。 |

能力默认在读取时补，界面明确标注默认值，不把未知能力伪装成发现结果。`maxTokens` 是输出预算而非上下文长度；明确值约束请求，缺失时使用适配器有界默认，不能因上下文默认 200K 就请求 200K 输出。Messages 需要输出预算，ChatGPT 订阅 HTTP 路径不接受 `max_output_tokens`。精确类型和安全诊断在首批契约审查中固定，不开放任意 HTTP header 或原始响应路径配置。

工作区配置禁止存凭据；发现疑似凭据字段提醒并忽略，不回显值。全局认证文件使用实际可验证的用户权限保护；Windows 不以 Unix chmod 作为权限验收，必要时使用用户目录 ACL 并检查是否对其他用户开放。认证写入原子完成，失败不能截断旧文件。

## 3. 读取、来源与安全保存

唯一配置入口负责读取、校验、合并、来源说明和保存；CLI、应用和菜单使用同一解析结果，不各自读取环境变量或 JSON。有效设置、模型目录和凭据分开传递，凭据不进入可打印的普通配置快照。

| 类别 | 来源规则 |
|---|---|
| 当前供应商与模型 | 会话内明确 `/model` 选择最高；启动时显式 CLI 选择高于恢复记录，恢复记录高于环境连接。无显式或恢复选择时按环境、工作区默认、全局默认查找；不存在则保持未配置。 |
| 工作区共享设置 | 未显式覆盖时工作区字段高于全局和程序默认；不从历史会话恢复旧值。启动进程的显式 CLI 覆盖必须与 argparse 默认值区分并显示来源；用户明确修改该项后以新操作为准。其他进程的显式覆盖不被文件写入偷偷撤销。 |
| 模型能力与接口 | 当前模型显式字段高于供应商默认或官方发现值；缺失时使用已验证适配器默认与能力默认。刷新只补缺失项，不覆盖已保存的手工值。 |
| 凭据 | 始终绑定选定供应商。既有 `MICA_API_URL/MICA_API_KEY/MICA_MODEL` 是不写文件的临时连接，Key 不自动套给后来选择的其他供应商；不增加任意环境变量插值语言。 |

显式 CLI 模型选择只覆盖本次进程，不改已有会话保存的恢复选择；会话内通过 `/model` 明确切换时才写入选择（D-020）。后续成功或中断提交不得顺带把启动覆盖写回元数据。

未知键提醒后忽略；已知键值非法时提醒并使用该项程序默认，其他合法字段继续加载。字段缺失可继承低来源；存在但非法不能从另一层找值掩盖错误。连接必需字段无安全默认时该连接不可用，其他合法连接仍可用。

文件缺失是未配置；无法读取、JSON 根结构错误、语法损坏分别给出安全、可操作诊断。语法错误报错并阻止开始会话，不把整份错误文件当空配置继续对话；修好后可重新启动。运行中重载的失败规则见 §9。

保存前在锁内重读最新文件，只改目标项并保留无关字段；复用既有文件锁与临时文件原子替换，不另建通用事务框架。损坏文件不自动覆盖，写失败保留原字节。模型、认证和默认选择分步提交时，所需记录全部有效后才标记连接可用；默认值和运行状态不领先于保存结果。并发编辑不能无提示覆盖其他窗口刚保存的项。

## 4. 未配置启动与空闲切换

首次直接进入 TUI，显示介绍、缺少模型配置的提示和配置入口，由用户主动使用 `/login`。没有可用模型时提交普通消息只提醒配置，保留可编辑草稿，不产生 User/Turn/checkpoint 或 Run。

终端启动与连接可用性分离。应用侧配置协调入口拥有连接选择与装配，明确的应用所有者关闭 Provider；Runtime 仍只拥有唯一 Run 及其消费任务。TUI 不直接改 App/Engine 私有字段，不以假 Provider 或假成功事件表示未配置。直接 `run_interactive(...)` 显式连接入口及 `plain=True` 默认保持可用；`--plain` 使用同一配置入口，不能配置时输出文字诊断，不强行开 TUI 菜单。

空闲切换按“校验目标与历史 → 准备新连接 → 保存会话选择 → 安装运行选择并更新事实区 → 收口旧连接”。准备或保存失败保留旧选择并关闭候选资源；安装后旧资源清理失败单独报告，不伪装成目标配置未保存。下一 Run 固定开始时的连接、模型能力、思考与权限设置，不半轮替换；取消后等真实任务和检查点收口才算空闲。

切换不重读或替换会话已冻结系统提示词与 AGENTS，不新建会话、清空历史或重复工具。上下文缩小时先警告并确认；已知超限不悄悄删历史，确认也不代表可突破容量限制。容量只能估计时标明估计，服务端真实超限正常报错；本阶段不实现压缩。

## 5. 接口与模型能力

`Message/ToolCall` 表达供应商无关对话与工具事实；Provider 转换请求和流式响应，Engine 保持统一模型、工具、权限、取消循环。三个接口统一产出完整文本、独立思考事件、完整工具调用及真实终态，不各自建立 Agent Loop。

| 接口 | 适配规则 |
|---|---|
| `openai-completions` | 扩充现有适配器；合并工具参数碎片，处理独立 reasoning 字段及渠道明确要求的续接数据，不依据正文标签猜思考。 |
| `openai-responses` | 转换 input items，关联 function call/output，保留必要 phase 与受支持 reasoning items；失败、不完整、流结束缺少正常终态不冒充 Finish。 |
| `anthropic-messages` | 分离 system/messages，转换 tool_use/tool_result，完整组装 block 和 JSON 参数，处理 thinking/signature、输出上限和工具往返。 |

适配器复用 `httpx`，分别负责请求编码与响应解析，不引入第二套 HTTP 链路。供应商与模型 ID 决定能力，协议 ID 决定适配器；认证和官方请求要求在连接装配边界设置，不泄漏到工具执行或前端。

能力按手工声明、明确官方信息、默认值依次采用。未知上下文为 200000 tokens，默认文本输入、不支持多模态、不支持思考；图片能力只记录，不实现输入或传输。

`reasoning` 缺失或为 false 时只允许 `off`，不发送思考强度参数。为 true 且 `thinkingLevelMap` 缺失或为空时使用适配器经过测试的默认档位与映射；非空时只展示明确列出的档位。不配置原始响应 JSON 路径，由适配器统一独立思考事件。

## 6. 会话选择、历史与安全续接

通用会话事实保持唯一有序来源；必要的专属续接记录须有明确字段、长度上限、来源绑定和校验，不保存 SDK 对象、整个原始响应或任意字典。它关联对应供应商、模型和模型步骤，不能因接口名相同认定兼容。Engine 在同轮工具往返传递，App/SessionService 在安全边界提交，TUI 只使用允许展示的文字。

活跃请求所需未经改写协议内容只保留在有界运行上下文，不进入日志、repr 或普通持久化。签名/加密字段不能正则替换后仍声称有效。保存候选通过既有敏感边界且关联内容未被清洗改变才可标记回放；否则明确不可回放，只存清洗后的通用事实。不得为签名绕过凭据、路径、工具参数清洗；精确白名单、关联顺序和失败降级先审查再编码。

兼容原连接继续时完整回传协议要求数据；跨模型、供应商或接口过滤不兼容续接，重编码普通历史与真实工具事实，不承诺继承不兼容内部思考。不能合法转换的旧工具/思考组合用明确的 Mica 历史工作记录，保留实际行为结果，不伪造目标签名、思考或成功工具结果。切回原连接重新检查绑定上下文，不保证旧签名在混合历史仍有效。

工具调用与结果在目标请求中保持一一关联；ID 形式不同时只建请求内映射，不改保存的调用身份、不产生执行动作。系统指引与历史分开转换，中断提示保留来源，工具输出和历史正文不得提升为 system/developer 指令。

中断继续用 `RunCheckpoint`，保留用户指令、已完成结果、部分正文及真实状态，区分 SUCCESS/FAILED/IN_PROGRESS/NOT_STARTED；完整成功只提交 Turn。跨接口恢复不自动执行旧工具或为未完成工具补结果；可能产生副作用时提示先核对工作区。可见思考与不可见续接分离，显示模式不影响必需回传。

会话选择是独立字段，只保存稳定供应商 ID 与模型 ID，不存 URL、Key、工作区设置或菜单组件。继续、恢复、分支及元数据重写保留选择；清空内容保留选择，回退不擅改模型。

旧 v1～v4 保持可读。旧记录无选择时用明确启动选择或现行默认并告知来源；保存选择缺失或禁用时保留引用、要求处理，不静默换模型。环境临时连接恢复只能匹配本次实际提供的对应连接，否则重选，不把 Key 写会话。

JSONL 版本用于严格会话契约，不等于配置版本。新增字段需兼容读写设计，旧文件只读不改字节，业务写入锁内原子升级，新格式不伪称旧 v4。首批先审选择，协议批次审续接；可安全纳入同一新格式则复用，不能预塞未定义占位字段，精确 wire 版本和形状审查后固定。

## 7. 登录、目录与供应商维护

`/login` 提供订阅登录、内置 API Key、自定义供应商及已有连接维护。自定义连接填写名称、URL、Key、接口；稳定 ID 与名称分离，改名不破坏历史引用。Key 输入遮蔽，不进入 editor 历史、用户消息、截图或诊断。

保存连接后自动尝试有界、可取消的目录请求，不发额外推理测试。按渠道解析 ID、名称、明确能力；失败保留连接并允许手填模型 ID，空列表与失败区别显示。不因发现或历史恢复执行工具。

只保存用户勾选模型；刷新保留已有选中状态和明确字段，远端暂未返回的已有模型不自动删除。没有当前可用模型时转入 `/model` 明确选择；已有可用模型时返回草稿，不自动改当前或全局默认。

已有供应商可改 Key、重新授权、显式刷新、改显示名称、禁用、启用或确认删除；自定义可改 URL/API，内置订阅授权端点不任意改写。新认证验证和写入成功前保留旧记录。禁用保留连接、目录、凭据，不再可选或用于新请求；当前/默认/恢复引用保留并提示启用或重选。

确认删除只清理本地连接、目录与凭据，不删历史、不改用别的供应商、不声称远端撤销。刷新迟到不能重建已删配置；删除和 token 刷新用同一凭据归属锁。多文件部分失败报告未完成范围，残留不当有效连接。

内置渠道按官方文档确定目录、基址和认证，不把当前模型名称、额度或价格硬编码为承诺。OpenCode Go 按模型使用不同接口，发送 Mica 自己的 User-Agent 及稳定且不含工作区路径的会话标识，不冒充其他客户端。官方目录缺可靠接口信息时用已核实映射或让用户显式指定，不按名称猜协议。

## 8. ChatGPT 官方订阅

直接采用官方 Sign in with ChatGPT 开源客户端流程，不复用 pi/Codex 凭据或登录文件，不读密码，不依赖私有 backend-api 或启动 Codex app-server。

用户主动选择后在浏览器授权；本地回调只监听 `127.0.0.1`，每次独立 state、nonce、PKCE。保存实际 issued client ID 和本机稳定 host ID；成熟库验证 ID token 签名、issuer、audience、到期、nonce，确认权限允许 ChatGPT plan usage，不手写密码学。新验证依赖、许可证、锁文件和分发影响先按 code spec 审查。

每个记录绑定验证账号和注册身份，返回登录不串账号；可独立保存多组订阅连接。取消、拒绝、超时或无 plan usage 权限报告真实状态，不把身份登录当可推理。刷新在同一凭据锁内串行，锁内重读最新 token，原子替换整组更新，避免多进程轮换竞争；撤销或刷新失败提示重登录，不自动换渠道。

目录按账号实际可见项解析。HTTP 推理用官方 Responses 路径、`store=false`、`stream=true`、完整 input，不依赖 `previous_response_id`。冻结指引转成允许的 instructions/developer，不发送被拒绝的 system item；本地工具用允许的 namespace/additional_tools 形式，不照搬 API Key 字段。只有 `response.completed` 为正常完成，额度错误、failed、incomplete、中途断流按真实失败处理。

真实授权、可用性和工具请求需要用户参与；模拟 OAuth/SSE 不替代。遇到官方资格或额度限制及时说明，不靠非官方端点绕过。

## 9. 当前选择、共享设置与重载

四个入口为 `/login`、`/model`、`/settings`、`/reload`；不保留 `/config` 别名、不做文件监听。四命令只在空闲执行，Ask/Permission 属于运行中，忙时不排队、不取消、不发送模型。具体按键和提示见 TUI 规格。

`/model` 只读本地保存目录。当前会话切换与全局默认保存是独立动作；保存默认不同时切换当前。跨供应商提示后续历史会发送到目标渠道，不误称只发新一句话。

`/settings` 只管理三项：

| 项 | 值和生效 |
|---|---|
| `reasoningEffort` | off/minimal/low/medium/high/xhigh/max 中模型实际支持档位；按官方能力或明确映射。切换模型后重算有效值，保留偏好并解释当前有效值，不硬发旧档位。 |
| `permissionMode` | default/solo；下一 Run 用现有策略，不绕过注册、Schema、文件能力、取消或清洗；不复制权限矩阵到 JSON，不开放自定义策略编辑。 |
| `reasoningDisplay` | full/collapsed/hidden；当前界面立即采用，按既有视觉规格，不参与 Ctrl+O。 |

默认逐项存工作区并生效，明确全局操作将该项同时应用到全局，不整组复制、不改其他工作区覆盖；写失败不显示虚假生效。模式与来源在设置界面说明，事实区维持原布局，不加未确认字段。

设置作用于该工作区当前、新建、切换、恢复会话，不被历史旧设置覆盖。修改窗口立即生效，其他进程在下一 Run、打开设置或 `/reload` 读取；进行中 Run 固定不变。共享文件不撤销别的进程显式启动覆盖，界面解释来源。权限快捷切换同样保存工作区；运行中仅记待生效值，当前 Run 收口后提交，不能抢 Ask/Permission 输入。

`/reload` 重读 config/models/auth，不强制联网刷新目录，不重载 AGENTS、提示词或未实现扩展。成功更新当前设置、能力和事实；当前模型被删或禁用时保留引用但禁止新请求并提示。语法或读取错误保留旧显示快照，明确未成功重载并阻止错误配置下新请求，不半份更新、不声称错误配置可用于新 Run。
