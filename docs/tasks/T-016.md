## 契约与约束

### 1. 先分类，后修改

- 冻结当前等待清单，注明函数、等待目的和同步信号。master 已核对范围内 175 项（36/7/83/18/31），
  全仓 1725 项；worker 独立核对。
- 当前猜测性短等待为 9 处：CLI 无文本取消 1 处、session 外部取消 1 处、普通 Bash 取消 2 处、
  lifecycle 忽略 Ctrl+D 2 处、screen 运行态输入与 Ctrl+C 布防 3 处。
- `sleep(30)` 是会被取消的 hanging fake；`sleep(0)` 是事件循环让出；`wait_for` 是死锁上界。
  这些不能仅凭名字或数值判定为慢等待，不机械替换。
- `pump()` 与四个 started.marker 循环等待可观察状态且已有截止时间，应与单次猜测性等待区分。
  有现成通知时使用通知；若没有，保留窄小、有界轮询并说明理由，不为消灭 sleep 增加产品钩子或忙等。

### 2. 确定性同步与取消保护

- CLI/session 取消前等待测试 Provider 确实进入本轮流；Event 由测试 fake 发出，在正确运行阶段设置。
  不在 Provider 还没启动时取消，也不改变 checkpoint、stdout/stderr 或 close 次数断言。
- 普通 Bash 的两处取消必须发生在真实子进程启动后，可用安全的启动输出和已有 reporter 等接缝观察；
  不将真实 Bash 替换成 fake，不修改工具实现，不把子进程创建调用被触发当成启动已完成。
- TUI 的负向测试先确认对应按键已经由真实输入队列完成处理，再断言状态未变。
  输入被读取或排队不等于被处理；允许测试中的窄委托包装在原处理器返回后发出信号，原处理器必须执行。
  不直接调用处理器模拟用户按键，不 mock 掉被测分派，不依靠周期刷新次数代替按键处理证据。
- 使用 Event、队列或既有可观察状态，并用有余量的有界 `wait_for`。不得通过增大旧超时、加入重试、
  warning 过滤、吞错或放宽断言掩盖问题；新同步上界及其依据写入交接。
- helper 保持模块局部、职责窄小；不增加全局 fixture、万能等待工具或外部依赖。
- 修改涉及的注释/docstring 使用英文；不顺手清理文件中无关注释或重排无关测试。

### 3. 保留真实进程证据并注册 marker

- 以下四项保留原有后代进程脚本、2.3 秒墙钟观测、marker 未出现及取消/超时/上限断言：
  `test_bash_output_limit_reaps_real_delayed_descendant`、
  `test_bash_timeout_reaps_real_delayed_descendant`、
  `test_bash_token_cancellation_reaps_real_delayed_descendant`、
  `test_bash_handler_task_cancel_reaps_real_delayed_descendant`。
- 仅为这四项添加 `pytest.mark.slow` 和 `pytest.mark.process_tree` 并在 pyproject 注册；
  `process_tree` 表示真实 OS 进程树证据，不表示只可在 Windows 运行，不新增平台跳过条件。
- 默认 pytest 仍运行全部测试；不配置默认排除、warning 过滤或 addopts 改变原验证范围。
- README 说明 `-m "not slow"` 用于快速反馈，`-m process_tree` 用于单独运行真实进程树证据；
  明确前者不能代替最终全量，避免把选择性测试结果写成全部验收通过。
