## 具体实现目标

- 能表示一个模型步骤的续接记录：来源（供应商、模型、接口）、可否回放、按原始顺序排列的项；项只有计划表格列出的六种，每种只带白名单字段。
- 记录在构造时就拒绝非法内容：项不属于该接口、字段缺失或类型不对、ID 格式不合法、可回放却没有项、不可回放却带项、Chat Completions 记录不是恰好一项、`reasoning_details` 元素的内容字段与类型不符。
- 记录能转成计划规定的 JSON 形状，也能从不可信 JSON 严格解析回来；多余字段、缺失字段、未知 `type`、未知枚举值都报格式错误，不宽松接受。
- 能校验一条记录与这一步 assistant 消息的关联：工具调用引用和消息的工具调用顺序、集合一致；正文非空时恰有一个正文引用，为空时没有。
- 能把一轮内的全部记录按合计体量检查；超过 1 MiB 时全部改为不可回放，未超过时原样返回。
- 清洗判定：给定这一步的原始 assistant 消息和续接记录，消息或明文字段经过既有清洗会发生任何改变时，返回不可回放的记录，否则原样返回；不透明字段不做正则替换。
- 调试表示（repr）不显示思考文本、摘要、密文、签名和 `data` 的内容。

## 具体实现方案

**`src/mica_agent/continuation_contracts.py`**（不导入 `session_contracts`、`message_sanitizer`，避免循环依赖）：

- 枚举：
  - `ProviderApi`：`OPENAI_COMPLETIONS = "openai-completions"`、`OPENAI_RESPONSES = "openai-responses"`、`ANTHROPIC_MESSAGES = "anthropic-messages"`；
  - `ContinuationStatus`：`REPLAYABLE = "replayable"`、`UNREPLAYABLE = "unreplayable"`；
  - `TextPhase`：`COMMENTARY = "commentary"`、`FINAL_ANSWER = "final_answer"`；
  - `ReasoningDetailType`：`SUMMARY = "reasoning.summary"`、`ENCRYPTED = "reasoning.encrypted"`、`TEXT = "reasoning.text"`。
- 项（均为 `@dataclass(frozen=True, slots=True)`，集合字段转成 tuple，内容字段 `repr=False`）：

| 类 | wire `type` | 字段 |
|---|---|---|
| `ResponsesReasoningItem` | `reasoning` | `id: str`、`summary: tuple[str, ...]`、`encrypted_content: str` |
| `MessagesThinkingItem` | `thinking` | `thinking: str`、`signature: str` |
| `MessagesRedactedThinkingItem` | `redacted_thinking` | `data: str` |
| `TextItem` | `text` | `phase: TextPhase \| None` |
| `ToolCallItem` | `tool_call` | `call_id: str` |
| `ChatReasoningItem` | `chat_reasoning` | `reasoning_content: str \| None`、`reasoning: str \| None`、`reasoning_details: tuple[ReasoningDetail, ...]` |

- `ReasoningDetail`：`type: ReasoningDetailType`、`id: str | None`、`format: str | None`、`index: int | None`、`summary: str | None`、`data: str | None`、`text: str | None`、`signature: str | None`；按计划的规则校验，`index` 拒绝 bool 和负数。
- `ContinuationItem` 为以上六个项类的类型别名（Union）。
- `ModelStepContinuation`：`provider_id: str`、`model_id: str`、`api: ProviderApi`、`status: ContinuationStatus`、`items: tuple[ContinuationItem, ...] = field(default=(), repr=False)`。在 `__post_init__` 完成计划「项」「校验与关联」中不依赖消息的全部规则：每种接口允许的项、同一步 `text` 至多一项、`call_id` 不重复、可回放至少一项、不可回放为空、Chat Completions 恰好一个 `ChatReasoningItem` 且三个字段至少一个有内容、Messages 的 `TextItem.phase` 必须为 `None`。
- 字段约束：
  - `id`、`call_id`：非空，不含空白和控制字符，不超过 256 个字符；
  - `provider_id`、`model_id`：非空、非全空白；
  - 不透明字段（`encrypted_content`、`signature`、`data`，以及 details 的 `data`、`signature`）：非空，不含控制字符；
  - 明文字段：只要求是 `str`。
- 常量：`MAX_TURN_CONTINUATION_BYTES = 1024 * 1024`。
- 错误：`ContinuationFormatError(ValueError)`，用于不可信 JSON 解析失败；构造期的类型错误和值错误沿用 `TypeError`、`ValueError`。
- 公开函数：
  - `serialize_continuation(record: ModelStepContinuation) -> dict[str, object]`：输出计划规定的形状；每项字段齐全，缺省写 `None`；
  - `parse_continuation(value: object) -> ModelStepContinuation`：严格解析，所有失败（包括构造期的 `TypeError`、`ValueError`）都转成 `ContinuationFormatError`，不带出原始内容；
  - `continuation_size(record: ModelStepContinuation) -> int`：`json.dumps(serialize_continuation(record), ensure_ascii=False, separators=(",", ":"), sort_keys=True, allow_nan=False)` 的 UTF-8 字节数；
  - `apply_turn_size_limit(records: Sequence[ModelStepContinuation | None]) -> tuple[ModelStepContinuation | None, ...]`：非空记录的 `continuation_size` 合计超过上限时，每条非空记录改为同来源、`UNREPLAYABLE`、空项；`None` 保持不变；
  - `check_step_association(record: ModelStepContinuation, assistant_message: Message) -> None`：不满足计划「关联」规则时抛 `ValueError`；`assistant_message` 必须是 assistant 角色。

**`src/mica_agent/message_sanitizer.py`**：

- 新增 `sanitize_step_continuation(record: ModelStepContinuation, assistant_message: Message) -> ModelStepContinuation`，`assistant_message` 是这一步未经清洗的原始消息。依次判定：
  1. `record` 已是不可回放时原样返回；
  2. `assistant_message` 有工具调用，且 `sanitize_tool_message(assistant_message) != assistant_message`，返回不可回放；
  3. 任一明文字段（`summary` 各元素、`thinking`、`reasoning_content`、`reasoning`、details 的 `summary`、`text`）满足 `sanitize_presentation_text(value) != value`，返回不可回放；
  4. 否则原样返回。
- 不可回放的记录保留 `provider_id`、`model_id`、`api`，`items` 为空。函数不校验关联，关联由调用方用 `check_step_association` 检查。
- 加入 `__all__`。

**`tests/test_continuation_contracts.py`**：覆盖下方完成标准列出的行为；用固定的 JSON 字面量断言 wire 形状，不只做往返。

## 完成标准

- 六种项和 `ReasoningDetail` 各有一个合法样例，`serialize_continuation` 的输出与测试中的 JSON 字面量逐字段相等，`parse_continuation` 解析回来与原对象相等。
- 以下每种非法输入都有测试，并得到 `ContinuationFormatError`（解析）或 `ValueError`/`TypeError`（构造）：
  - 多余字段、缺失字段、未知 `type`、未知 `api`、未知 `status`、未知 `phase`；
  - 项不属于记录的接口；Messages 的 `text` 带 `phase`；
  - 可回放无项、不可回放有项；Chat Completions 零项或两项、三个字段都为空；
  - 两个 `text` 项、重复 `call_id`；
  - `id` 含空格或超过 256 字符；不透明字段为空串或含控制字符；
  - `reasoning_details` 元素的 `type` 与内容字段不符、`index` 为负数或 bool。
- `check_step_association`：顺序一致通过；顺序颠倒、缺一个、多一个、正文非空却无 `text` 项、正文为空却有 `text` 项，均抛 `ValueError`。
- `apply_turn_size_limit`：合计恰好等于上限时原样返回；超过 1 字节时全部非空记录变为不可回放空项，`None` 保持不变。
- `sanitize_step_continuation`：普通记录原样返回；工具参数含 `sk-` 形式的凭据、思考文本含本地绝对路径时，各返回不可回放；不透明字段含 `sk-` 字样不影响结果。
- 带思考文本、密文、签名的记录，`repr()` 不包含这些值；`parse_continuation` 的异常文本不包含输入值。
- `sanitize_tool_message`、`sanitize_presentation_text` 的既有测试不改且通过。
