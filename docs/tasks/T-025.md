## 具体实现目标

**命令候选（空闲时）**
- 单行草稿以 `/` 开头时，输入框下方、事实区上方出现候选列表；每行显示命令名和说明。本卡只登记 `/model`。
- 候选是名称以草稿为前缀的命令（不区分大小写）；继续输入实时筛选。
- ↑/↓ 移动高亮，Enter 执行高亮的命令并清空草稿；只输入或移动高亮不执行。
- Esc 关闭候选并保留草稿；草稿再次变化后候选按新草稿重新出现。
- 草稿去掉开头的 `/`、变成多行或没有任何匹配时，不显示候选。
- 没有匹配时 Enter 把完整原文作为普通消息提交，走原有提交路径，原文一字不改。

**运行中**
- 文字、粘贴、删除和光标移动照常编辑草稿；输入框保持禁用配色；不显示候选。
- Enter 不提交、不排队：草稿（去掉首尾空白后）恰好是一个已登记命令时，输入框上方出现一条约 2 秒的灰色提醒，说明命令要等当前任务结束；其他草稿无任何反应。两种情况草稿都保留。
- Esc 仍取消 Run，Ctrl+C、Ctrl+O 行为不变；Ctrl+D 运行中不退出。
- Ask/Permission 期间输入归交互面板独占，与现状一致。
- Run 结束后草稿和光标原样可用。

**`/model` 菜单**
- 打开时读取一次本地模型列表，不联网；菜单取代状态条、输入框和事实区，上方历史保持可见。
- 每行显示「模型名称 [供应商名称]」；当前模型和全局默认各有独立标记，可以同时出现。
- 输入文字按模型名称或供应商名称筛选（不区分大小写的子串），Backspace 删除筛选字符；↑/↓ 移动高亮；筛选结果为空时有明确提示。
- 初始高亮在当前模型上；没有当前模型时在第一项。
- 高亮项的供应商与当前供应商不同时，菜单内显示提示：切换后，本会话的后续请求会把已有历史发送到目标供应商。
- Enter 切换到高亮项：
  - 目标的上下文窗口小于当前模型时，先在菜单内显示警告并要求确认：写明两个数值；任一方是默认值时标明；说明历史可能超限。再按 Enter 确认，Esc 回到列表。没有当前模型时不警告。
  - 切换进行中菜单显示进行状态，不接受导航、筛选和再次提交；键盘和退出不被卡住。
  - 成功后菜单关闭；事实区的模型字段立即变为新模型；历史末尾追加一条灰色记录，内容是新的连接摘要；思考强度提醒按新模型更新；有清理警告时一并显示。
  - 失败时菜单保留，在菜单内显示 `ModelSwitchResult.message`；当前模型不变。
  - 高亮项就是当前模型时直接关闭菜单。
- Ctrl+S 把高亮项保存为全局默认：不切换、不关闭；成功后重新读取列表并更新默认标记，显示已保存的提示；冲突和失败各显示一条固定的安全文字，标记不变。
- Esc 只关闭菜单（确认步骤中是回到列表）；已保存的默认不撤销。
- 没有可用模型时菜单显示 `No models available`，只响应 Esc。读取列表失败时不打开菜单，在输入框上方显示固定的安全提示。
- 菜单超过可用高度时按现有面板规则降级，高亮行始终可见。
- 菜单打开期间 Ctrl+C 双击仍可退出；退出时未完成的切换被收口，不留下悬空任务。

## 视觉定稿 · 2026-10-07

本卡新增界面文案全部英文，视觉规则以 `docs/tui_design.md` §13.1「命令候选与 `/model` 的视觉约定」为准。下图只说明层级和标记，示例名称不是实际模型目录；蓝色当前模型与灰色其他模型需由 ANSI 样式断言验证。

```text
┌──────────────────────────────────────────────────────────────┐
│› /m                                                          │
└──────────────────────────────────────────────────────────────┘
  › /model    Switch model or set global default
  ~\workspace (main)                              current-model
  sessions: current session
```

候选无外框、无独立标题，最多五行；命令名列对齐，选中行蓝色，其他行灰色，窗口跟随高亮。本卡只登记 `/model`。

```text
────────────────────────────────────────────────────────────────
 Select model
 Type to filter...

 › ✓ model-a [Provider A]                        Current  Default
     model-b [Provider A]
     model-c [Provider B]

 Enter Switch · Ctrl+S Set default · ↑/↓ Move · Esc Close
────────────────────────────────────────────────────────────────
```

`›` 是导航位置，`✓` 是当前模型；两个标记各占固定列。当前模型始终蓝色，其他模型始终灰色，移动导航不改变当前模型。无容量列，标记靠右，筛选行常驻；空结果、跨供应商提示、缩小确认和操作结果按规格英文文案显示。

固定安全文字：
- 忙时命令：`Commands are available after the current task finishes.`
- 目录读取失败：`Unable to load models.`
- 空目录 / 空筛选：`No models available` / `No matching models`。
- 跨供应商：`Future requests will send this session's history to <provider>.`（供应商名称安全清洗）。
- 容量警告：`Context window will shrink: <current> → <target>`、`Existing history may exceed the new limit.`。
- 默认保存成功 / 冲突 / 失败：`Saved as global default.` / `Default changed elsewhere. Please reopen the menu and try again.` / `Unable to save global default.`。
- 默认保存成功但重新读取失败：`Default saved, but unable to refresh models. Reopen the menu.`；保留旧标记，不伪装成保存失败。
- 切换异常：`AppBusyError` → `The app is busy. Try again after the current task finishes.`；`AppClosedError` → `The app is closed.`；其他异常 → `Unable to switch model.`。业务返回失败仍展示安全的 `ModelSwitchResult.message`。

既有界面英文统一与 `docs/tui-design/` 文档拆分均不属于本卡。用户真实 Windows Terminal 验收安排在本卡验收之后，须确认颜色、导航与当前标记的区别、窄终端降级和 Ctrl+S 的真实输入。

## 具体实现方案

**`commands.py`**（纯数据和匹配，不持有终端、App 或 Run 状态）
- `Command`（frozen dataclass）：`name`（含开头斜杠）、`description`、`handler: Callable[[], None]`。
- `CommandRegistry(commands)`：
  - `candidates(draft) -> tuple[Command, ...]`：草稿不含换行且以 `/` 开头时，返回名称以草稿为前缀的命令，按登记顺序；否则为空；
  - `exact(draft) -> Command | None`：草稿去掉首尾空白后与某个命令名相等（不区分大小写）时返回它。
- `CommandCandidates`：候选的高亮和关闭状态。`sync(draft)` 在草稿变化时重算匹配、重置关闭标记并收拢高亮；`move(delta)`、`dismiss()`、`selected`、`visible`、`lines(width, palette)`。
- 候选列表和实际执行用同一个 `CommandRegistry`。

**`menus.py`**（本地菜单，与 Ask/Permission 语义分开；C1、D 的菜单以后也放这里）
- `MenuOutcome`（frozen dataclass）：`action: Literal["none", "close", "switch", "save_default"]`、`selection: SessionSelection | None = None`。
- `ModelMenu(choices: tuple[ModelChoice, ...])`：
  - `handle(key) -> MenuOutcome`：筛选、导航、确认步骤都在内部完成；只有需要 screen 行动时才返回 `close`、`switch`、`save_default`；
  - `panel(width, palette, *, limit=None) -> PanelView`：用 `PanelRow` 和 `fit_panel_rows()` 排版，写法参照 `PermissionInteraction.panel()`；
  - `set_choices(choices)`（保存默认后刷新标记，尽量保持高亮在同一选择上）、`set_hint(text)`、`set_busy(busy)`。
- 菜单不调用 App，不读配置；容量比较和跨供应商判断只用 `ModelChoice` 的字段。
- 所有显示的模型名和供应商名经 `sanitize_scalar` 清洗。严格遵守 `docs/tui_design.md` §13.1「命令候选与 `/model` 的视觉约定」：新增界面文案全部英文，上下分隔线和 footer 层级沿用 Permission 面板，但不改既有中文 footer。
- 标题 `Select model`，常驻筛选行（空时 `Type to filter...`，非空 `Filter: <text>`）；列表行分为导航 `›`、固定宽度当前标记 `✓`、名称与供应商、右侧 `Current` / `Default`。当前模型名称、供应商、对勾与 `Current` 使用 `interaction` 蓝色，其他模型名称与供应商以及 `Default` 使用 `muted` 灰色；导航标记使用蓝色，不随导航把非当前模型名称染蓝。不新增 Palette 样式，不改 renderer。
- 常规 footer 为 `Enter Switch · Ctrl+S Set default · ↑/↓ Move · Esc Close`；确认时为 `Enter Confirm switch · Esc Back`；切换中为 `Switching...`。容量只在缩小确认中出现，数值使用千位分隔，缺省值各自附 `(default)`，不增加列表容量列。
- 窄终端先压缩名称与供应商以保留标记；高度不足使用既有面板降级与高亮锚点，无色模式仍保留导航、对勾和文字标记。

**`editor.py`**
- `_KEY_NAMES` 增加 `Keys.ControlS: "ctrl_s"`。

**`screen.py`**（仍是唯一按键入口）
- `Mode` 增加 `"menu"`。
- `__init__` 建立 `CommandRegistry`，只登记 `/model`，处理函数是打开模型菜单的私有方法。
- `_handle_key()` 的分支顺序：`ctrl_c` → `ctrl_o` → Ask/Permission → 菜单 → Esc → 运行中 → 空闲。菜单模式下除 `ctrl_c`、`ctrl_o` 外的按键全部交给菜单。
- 命令的空闲判断只写一处：一个私有方法接收 `Command`，空闲时清空草稿并调用处理函数，否则设置提醒。候选 Enter 和运行中 Enter 都走它。
- 提醒：保存文字和到期时刻（用 `self._clock`），`_build_chrome()` 只在未到期时绘制；持续时间定义为模块常量。运行中已有刷新任务按间隔重绘，到期后自然消失，不新增定时器。
- 切换：菜单返回 `switch` 时，`asyncio.create_task(app.switch_model(selection))`，菜单置为进行中；任务完成后把结果或异常类别放进现有的 `self._queue`（新增一种队列项），由 `_loop()` 取出处理。处理时核对仍是同一个菜单和同一次请求，否则只丢弃展示。`AppBusyError`、`AppClosedError` 和其他异常都转成固定的安全提示，不显示异常原文。
- `_shutdown()` 在关闭 runtime 之前取消并等待未完成的切换任务，失败只记录固定标签到 `cleanup_errors`。
- 切换成功后的事实区：`self._session_snapshot` 是 `TuiSessionSnapshot` 时用 `dataclasses.replace` 更新 `model` 为 `"<model_id> (session)"`（与 CLI 启动时非直接来源的写法一致）。
- 保存默认：同步调用 `app.save_default_model(selection)`；`ConfigConflictError` 和其他 `ConfigError` 各对应一条固定提示；成功后 `app.model_choices()` 重新读取并 `set_choices()`。
- `_build_chrome()`：菜单模式与 Ask/Permission 一样返回面板、光标和高亮锚点；普通模式在输入框之后、事实区之前插入候选行（光标坐标不受影响）；提醒画在输入框上方，与既有配置提醒同一位置和配色。

**`docs/module_map.md`**
- 终端前端组加入两个新源码文件和两个新测试文件，各一行职责。
- 应用入口组 `app.py` 的职责补上模型目录、空闲切换和默认保存（T-024 遗留）。

## 实现要求

- 前端只调用 `MicaApp` 的公开接口；不访问 `_provider`、`_connection`、`_config_service` 等私有状态，不自己读配置文件。
- 菜单、候选、提醒和历史记录中不出现 URL、Key 或异常原文；测试用假 URL、假 Key 直接断言。
- 不新增输入线程、定时器、全屏框架或常驻输入消费器；不新增第二个忙状态来源，空闲与否以 `self._mode` 为准。
- 不提前登记 `/login`、`/settings`、`/reload`，不做命令参数、别名和插件机制。
- 不改变 Ask/Permission 的任何按键行为，不改变 Esc 取消 Run 的行为。
- 既有断言改写授权仅限两处：`test_running_state_ignores_composer_input_and_second_submit` 的「运行中输入不进入草稿」改为新行为（草稿保留、不产生第二次请求）；`test_escape_cancels_active_run_without_committing_turn` 的取消后 `screen.composer_text == ""` 改为 `screen.composer_text == "x"`，同步运行中输入与取消后草稿保留规格。后者的取消状态、历史、无成功 turn 和 CANCELLED 检查点断言全部保留；其他既有测试需要改动时仍停下汇报。
- 另授权同步 `tests/test_distribution.py` 的 wheel 精确文件清单，仅加入本卡新增的 commands 与 menus 两个模块路径；不改变 `==` 为包含检查，不删旧成员，不修改其他分发断言或打包配置。
- 新模块属于终端前端包内部，不加入顶层 `mica_agent` 公共 API；是否从 `tui/main_buffer/__init__.py` 导出不在本卡范围（不改该文件）。

## 完成标准

- `CommandRegistry`：前缀匹配、大小写、多行和非斜杠草稿返回空、`exact()` 对首尾空白的处理，各有直接断言。
- 候选：输入 `/` 出现、继续输入筛选、无匹配消失、Esc 关闭后草稿保留、草稿变化后重新出现；↑/↓ 在候选可见时不移动编辑光标。
- 空闲时 Enter 执行高亮命令，草稿清空，没有产生 Run 和用户消息行。
- 无匹配的 `/xyz 你好` 按 Enter 作为普通消息提交，Provider 收到的用户消息与原文逐字相等。
- 运行中：输入进入草稿；完整命令 Enter 出现提醒，假时钟越过到期时刻后提醒消失；普通草稿 Enter 无反应；两种情况都只有一次 Provider 请求；Esc 仍取消 Run；Run 结束后草稿仍在。
- 菜单排版：上下分隔线、英文标题与 footer、常驻筛选行、名称与供应商格式、独立 `Current` / `Default`、固定列 `›` / `✓`、无容量列，各有直接断言；启用颜色的 Palette 下直接断言当前模型蓝色、非当前模型灰色，移动导航不改变当前标记与名称颜色；无色模式仍能区分导航、当前与默认。
- 候选排版：位置在输入框与事实区之间，无额外外框和标题，英文说明、命令名列对齐、高亮蓝色与其他灰色；用登记超过五项的纯组件样本验证至多五行且高亮始终可见，不在实际 registry 中提前登记未实现命令。
- 筛选名称和供应商、空结果英文提示、跨供应商英文提示、窄终端保留标记、高度不足时高亮行可见，各有断言。
- 容量确认：目标更小时先警告，Enter 确认后才返回 `switch`，Esc 回到列表；默认值标注有断言；目标不更小或没有当前模型时不警告。
- 切换成功（经 `ScreenHarness` 和真实 `MicaApp`）：菜单关闭、模式回到空闲、事实区模型字段更新、历史追加连接摘要、下一次提交使用新 Provider。
- 切换失败：菜单保留并显示安全文字，当前模型不变。
- 切换进行中：导航和 Enter 被忽略；此时退出前端，切换任务被收口，`cleanup_errors` 为空或只有固定标签。
- Ctrl+S：全局默认写入、默认标记刷新、菜单不关闭、当前模型不变；冲突时显示固定提示。
- 读取列表失败不打开菜单并显示固定提示；空列表菜单只响应 Esc。
- 菜单打开期间 Esc 不取消任何 Run、不退出；Ask/Permission 既有测试全部通过且未改动。
- 安全断言：全部新增显示文字中不含假 URL 和假 Key。
