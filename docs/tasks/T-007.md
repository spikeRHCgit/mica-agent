# T-007 App 测试临时目录清理竞态

状态：待开始 · 阶段：阶段间治理 · 负责：外部 worker · 分支：`task/T-007-app-tempdir-cleanup` · 基线：`a538040`
依赖：T-005、T-006 已验收 · 提交授权：否，交付未提交改动

## 目标

定位并消除 `tests/test_app.py` 在 Windows 上清理 `mica-app-test-*` 临时目录时偶发
`OSError: [WinError 145] 目录不是空的` 的根因，使测试资源的创建、使用和释放具有明确所有者与确定顺序。
不得通过固定等待、无边界重试、忽略清理错误、减少测试或降低运行次数来制造表面稳定。

## 已有证据

- T-005 master 审查时，`tests/test_app.py` 的 45 个测试正文均通过，但 autouse fixture 在
  `test_reasoning_is_visible_per_run_but_not_saved_or_restored` 后调用 `TemporaryDirectory.cleanup()` 时
  报 `WinError 145`；进程结束后残留目录为空。
- T-006 的一次全量测试中，相同错误出现在已由 T-005 删除的
  `test_cancelled_run_does_not_submit_a_turn` 后；进程结束后残留目录同样为空。
- T-005/T-006 组合主线随后一次全量为 `1775 passed, 2 skipped`。这次绿色不推翻前两次在不同测试上
  已经发生的竞态，说明问题属于共享临时目录生命周期，而不是某个测试的稳定失败。
- 共同入口是 `_TEST_TEMP_DIRS`、`_cleanup_test_tempdirs()`、`_make_session_components()`；会话文件由
  `JsonlSessionStore` 原子写入。当前尚未证明问题属于测试所有权、产品资源释放还是 Windows 文件系统时序。

## 诊断与实现约束

- 先画清临时目录的所有权：谁创建 `TemporaryDirectory`，哪些对象持有引用，哪些代码可能写入或持有会话
  文件，测试正文、async generator 收口、App/provider 关闭和 fixture teardown 的实际顺序是什么。
- 用只读源码、失败 traceback、目录内容/句柄时序或仓库外诊断探针定位根因；允许在根因明确后做有上限的
  定向压力验证，但不允许先反复运行直到碰巧失败或通过。
- 如果根因可以在 `tests/test_app.py` 的 fixture/helper 内消除，采用职责最清晰的最小修复；测试资源应由
  pytest fixture 或一个明确对象拥有，清理应在所有使用者完成后发生一次。
- 如果证据指向产品代码仍持有文件、后台任务或异步生成器，停止修改并报告 master；不得越界在测试任务中
  修产品，也不得用测试层等待掩盖产品泄漏。
- 保持全部测试的公共输入、断言、取消入口、持久化语义和测试名称不变；本任务只修测试资源生命周期。
