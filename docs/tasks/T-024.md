# T-024：应用侧模型目录、空闲切换与全局默认保存

状态：已完成 · 主线：Phase 6 · 交付项：`docs/phase6_plan.md` A2 第 1 步（共 2 步）· 风险：高

## 目标概览

`MicaApp` 自己用 Provider 工厂创建连接，并向前端提供三项公开能力：列出可切换的模型、在空闲时切换当前会话的模型、把某个模型保存为全局默认。切换成功会写入会话选择，失败时旧连接原样可用。下一张卡（T-025）的 `/model` 菜单只调用这些接口。

## 具体实现目标

- 前端能拿到当前可切换的模型列表：每项有模型名称、供应商名称、上下文窗口及其是否为默认值、是否为当前模型、是否为全局默认；只列出能实际连接的模型；按模型名称、再按供应商名称排序。
- 空闲时切换到另一个模型：成功后当前会话保存新的供应商和模型 ID，下一 Run 使用新连接；以后恢复这个会话也使用新选择。
- 切换失败不破坏现状：目标不存在、被禁用或不能连接，创建连接失败，保存会话选择失败，都报告安全的失败原因，旧连接和旧选择继续可用，新创建的连接被关闭。
- 旧连接关闭失败不影响切换结果：切换仍算成功，但单独报告清理问题。
- 忙时（有 Run 预留或正在运行）和应用已关闭时拒绝切换，不改任何状态。
- 切换到当前模型是成功的空操作，不写会话、不重建连接。
- 没有模型的未配置启动也能切换到第一个可用模型，切换后可以正常开始 Run。
- 切换后事实区摘要、思考强度的有效值与提醒按新模型的能力重算，保留用户的思考偏好。
- 切换不改变已冻结的系统提示词和 AGENTS，不新建会话、不清空历史。
- 可以把某个模型保存为全局默认；不切换当前模型；保存冲突和失败报告安全原因，不显示虚假成功。
- 现有启动行为不变：CLI 的启动选择、初始选择保存、`--plain` 诊断和退出码保持原样。

## 具体实现方案

**Provider 创建移到 App**：
- 把 `ProviderFactory: TypeAlias = Callable[[str, str], Provider]` 移到 `app.py`；`cli.py` 从 `app.py` 导入，保持 `run_interactive(..., provider_factory=...)` 的参数不变。
- `MicaApp.__init__` 新增关键字参数 `provider_factory: ProviderFactory | None = None`。
- 规则：`provider` 为 None、`connection` 不为 None、`provider_factory` 不为 None 时，App 在构造时用 `provider_factory(connection.api_url, connection.api_key)` 创建 Provider，模型取 `connection.selection.model_id`；已显式传入 `provider` 的旧用法照常可用。
- `cli.py` 的连接装配不再自己调用 factory，改为把 `provider_factory=factory` 和 `connection` 交给 `MicaApp`；构造失败时仍输出既有的 `mica: unable to initialize provider` 并退出 2（App 构造异常要能和工厂异常区分，或统一用这条安全诊断，二选一，在汇报中说明）。

**新增公开类型**（放 `app.py`）：

```python
@dataclass(frozen=True, slots=True)
class ModelChoice:
    selection: SessionSelection
    model_name: str
    provider_name: str
    context_window: int
    context_window_is_default: bool   # capabilities.sources 里没有 "contextWindow" 时为 True
    is_current: bool
    is_default: bool

@dataclass(frozen=True, slots=True)
class ModelSwitchResult:
    switched: bool                    # 目标已经生效（包括切换到当前模型的空操作）
    message: str                      # 可直接展示的安全文字，不含 URL、Key 或异常原文
    cleanup_warning: str | None = None
```

**新增 `MicaApp` 公开方法**：
- `current_selection: SessionSelection | None`（属性）：当前连接的选择；未配置时为 None。
- `model_choices() -> tuple[ModelChoice, ...]`：调用 `config_service.load()` 取最新快照，对每个 `enabled` 供应商的每个模型调用 `config_service.resolve(snapshot, explicit=model.selection)`，只保留 `status == "ready"` 且有 `connection` 的项。`config_service` 为 None 时返回空元组。读取配置失败时抛出 `ConfigError`（由前端展示其安全文字）。
- `async switch_model(selection: SessionSelection) -> ModelSwitchResult`，顺序固定：
  1. 已关闭抛 `AppClosedError`，忙抛 `AppBusyError`；
  2. 与 `current_selection` 相同 → 返回 `switched=True` 的空操作；
  3. `load()` + `resolve(explicit=selection)`；不是 ready 或没有 connection → `switched=False`；
  4. 用 `provider_factory` 创建新 Provider；`provider_factory` 为 None 或创建失败 → `switched=False`；
  5. `session_service.update_selection(session_id, selection)`；失败 → 关闭新 Provider（有界等待 `close_timeout`），`switched=False`；
  6. 安装：替换 `_provider`、`_model`、`_connection`、`_engine`、`_capabilities`，`_selection_source` 改为 `"session"`，`_connection_status` 改为 `"ready"`、`_connection_diagnostic` 置 None，按新能力重算 `_effective_effort`（复用 `__init__` 里的同一段计算，抽成私有函数，不复制两份）；
  7. 关闭旧 Provider（有界等待 `close_timeout`）；超时或异常 → 在 `cleanup_warning` 写安全文字，不抛出。
  - 第 3～5 步期间 App 不能被另一 Run 预留：在方法开始时占用一个内部切换标记，`prepare_run()` 看到该标记时按忙处理，方法结束时释放。
- `save_default_model(selection: SessionSelection) -> None`：`load()` 取当前 `default_model` 作为 `expected_value`，调用 `config_service.save_default_model(selection, expected_value)`；异常原样抛出 `ConfigError` / `ConfigConflictError`；`config_service` 为 None 时抛 `ConfigError`。

**`SessionService` 新增**：
- `update_selection(session_id: str, selection: SessionSelection) -> None`：用 `JsonlSessionStore.update(session_id, transform)` 在锁内只替换 `meta.selection`，其他元数据和全部条目不变；旧 v1～v4 会话借 `update` 既有的升级路径升到 v5；会话不存在或损坏时抛出既有的会话异常类型。

## 实现要求

- `switch_model`、`save_default_model`、`ModelSwitchResult.message` 和所有异常文字不得包含 URL、Key、token 或底层异常原文；`ConnectionBinding` 不进入任何 repr 或返回值。
- 不在 App 外新增第二个持有当前 Provider 或忙状态的对象。
- 不实现历史 token 估算、上下文缩小确认和跨供应商提示（由 T-025 在前端做，数据来自 `ModelChoice`）。
- 不改 `for_run()`；切换后它收到的 `current` 就是新连接。
- 新增的公共类型和方法属于 `docs/code_spec.md` §1.3 的公共 API 变化：按本卡定稿的形状实现，形状需要改动时停下汇报。
- 测试全部用隔离临时目录和假 Provider/假工厂，不读取真实 `~/.mica`，不访问网络。

## 完成标准

- `model_choices()` 只返回能连接的模型，排序、当前和默认标记、上下文默认标记有直接断言。
- `switch_model()` 成功路径：会话文件里的选择变为目标，下一次 `prepare_run()` 的 Provider 和模型是新的，旧 Provider 的 `aclose()` 被调用一次。
- 以下失败路径各有一个测试，且断言旧 Provider 和旧选择不变：目标不可连接、工厂抛异常、会话保存抛异常（并断言新 Provider 被关闭）。
- 旧 Provider 关闭超时或抛异常时 `switched=True` 且 `cleanup_warning` 非空。
- 忙时、关闭后调用分别抛 `AppBusyError`、`AppClosedError`，状态不变；切换进行中 `prepare_run()` 被拒绝。
- 切换到当前模型不写会话文件（文件字节不变）。
- 未配置启动的 App 切换后能 `prepare_run()`。
- 切换后 `connection_summary`、`reasoning_notice` 反映新模型的能力。
- `save_default_model()` 成功写入全局默认，冲突时抛 `ConfigConflictError`。
- `update_selection()`：只改选择、v4 会话升级到 v5、会话不存在时抛异常，各有测试。
- 所有返回文字和异常文字中不出现测试用的假 URL 和假 Key（直接断言）。
- 现有 CLI 启动测试全部通过，无需放宽断言。
