  请求次数、重试/退避次数、诊断清洗和资源关闭责任。

### 2. 必须先迁移的独有或更强边界

在删除旧文件前，以下行为必须由 `tests/test_openai_provider.py` 通过实际公共 Provider 入口继续保护：

- full endpoint 作为 `base_url` 时，真实 HTTP 请求路径不重复追加 `/chat/completions`；
- system/user/assistant 消息中的 Unicode、换行和引号按原值编码进请求 JSON；
- `choices` 为 dict 的结构错误，与空 list 等其他畸形输入分别保持安全终态；
- HTTP 418 映射为 unknown Provider error；
- 含嵌套 credential 和 trace 的响应正文不进入异常文本、事件或 repr；
- HTTP 408 同时保持 timeout 分类和可重试行为；
- 配置 retries 后，malformed JSON 仍不重试；
- HTTP 500 且 `max_retries=2` 时恰好发送三次请求、调用两次退避，并保留最终错误分类；
- response 在成功、错误、取消三条路径都关闭；
- 显式 `provider.aclose()` 在成功、错误、取消三条路径都关闭 transport/client；
- 成功、错误和取消前已产生的公共事件都不会泄漏 `httpx.Response` 或其他 transport 私有对象。

### 3. 可合并的重复行为

按 T-004 已核实映射，把请求 method/body/header、普通 SSE 增量顺序、finish reason、DONE 去重、heartbeat、
null content、DONE-only、畸形 SSE、HTTP 分类、常规重试上限和取消传播归入现有行为测试。可以扩充现有参数
矩阵或断言，但不得为了复用而造出同时验证多个不相关生命周期的巨型测试。

### 4. 共享 helper 边界

`tests/sse_transport_helpers.py` 只能描述 HTTP transport、响应流和可观察的 close 状态。它不得构造业务层
Provider 结果、替代 Provider 解析逻辑或隐藏失败/取消的关键步骤。若无需调整即可迁移资源测试，则保持该
文件不变；若调整，报告必须说明新增的最小协议及其唯一使用者。
