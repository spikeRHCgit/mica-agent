# T-012 Windows subprocess transport 生命周期诊断

状态：待开始 · 阶段：阶段间治理 · 负责：外部 worker · 分支：`task/T-012-subprocess-lifecycle` · 基线：`1dbb951`
依赖：T-007 已验收；阻塞 T-011 · 提交授权：否，交付未提交改动

## 目标

定位 T-011 首次全量测试中 `ResourceWarning: unclosed transport <_WindowsSubprocessTransport ... running>`
对应 transport 的真实创建 node 和未收口边界；仅当根因明确落在授权文件内时，完成最小生命周期修复与回归验证。

本任务不从全量测试开始，不通过重复运行、强制 GC、固定等待、warning 过滤或放宽 `-W error` 碰运气。完成时必须
得到以下二者之一：

1. 可复现的创建 node、create / close / `__del__` 证据、根因和最小修复；
2. 候选集合内全部 create / close 账目闭合、原 warning 未复现的受限结论，并明确尚不能证明什么。

## 契约与约束

### 1. 候选范围先收敛

- 当前仓库只有 `src/mica_agent/runtime_tools.py` 调用 `asyncio.create_subprocess_exec`；测试侧直接解析并执行 Bash
  handler 的主体位于 `tests/test_runtime_tools.py`。
- `tests/test_engine.py` 与 `tests/test_p4_08_integration.py` 只作为候选调用链核对，不因出现
  `register_runtime_tools()` 就预设它们创建了真实子进程。
- 不再从 1725 项全量测试启动追踪；T-011 的三次重型追踪在到达任何 create 记录前中止或超时，不能提供创建者证据。

### 2. 轻量逐测试追踪

- 复用或重写仓库外追踪插件，但本任务禁止设置 `PYTHONTRACEMALLOC` 和 `PYTHONASYNCIODEBUG`。
- 记录每个 `asyncio.create_subprocess_exec` 返回对象的 PID、创建时 `PYTEST_CURRENT_TEST`、裁剪调用栈、
  `transport_id`，以及 transport `close()` / `__del__()` 的 node 和状态。
- 只保存标量和文本，不持有 Process / transport 强引用；不记录完整命令参数、环境变量或凭据。
- 增加会话末尾账目：按 `transport_id` 列出 create 后无 close、未关闭 `__del__`、以及完整闭合的记录。
- 插件必须调用原始实现，不吞异常或 warning，不调用 `gc.collect()`，不加入 sleep、自动重试或资源修复。

### 3. 定向运行顺序

1. 先用一个现有、确定会启动 Bash 的单 node 冒烟，证明插件能记录 create 与 close；该冒烟只运行一次。
2. 再运行一次以下候选组，保留原始输出和追踪日志：
   - `tests/test_engine.py`
   - `tests/test_p4_08_integration.py`
   - `tests/test_runtime_tools.py`
   - `tests/test_tui_main_buffer_markdown.py::test_capped_streaming_block_keeps_cursor_finish_and_split`
3. 若出现未闭合记录或 warning，只允许再运行一次对应创建 node，确认生命周期边界；不得循环复现。
4. 若候选组所有 create 均有 close 且没有未关闭 `__del__`，停止诊断并报告受限结论；不要因此宣布原 warning
   不存在、已解决或与 T-011 无关。

### 4. 有条件修复

- 只有追踪明确指出 `src/mica_agent/runtime_tools.py` 或 `tests/test_runtime_tools.py` 内的责任边界时才允许修改。
- 修复前说明进程、stdout reader、wait task、cancel task、taskkill helper 和 subprocess transport 分别由谁创建、
  谁等待、谁关闭，以及异常 / token cancel / task cancel / timeout 下的结束顺序。
- 优先加强命中场景的现有测试；不得为一个生命周期分支堆叠多个近似单元测试。
- 不使用私有属性轮询作为产品同步机制；诊断读取私有状态不等于允许产品逻辑依赖它。
- 不以额外重试、固定等待、GC、warning 过滤、异常吞掉或平台跳过作为修复。

## 验收

### 仅诊断、未修改产品或测试时

- 仓库外插件冒烟与候选组各只运行一次；必要时单个命中 node 再运行一次。
- 报告 create / close / `__del__` 账目、创建 node、调用栈和证据边界。
- `git diff --check`、`git diff --cached --check` 通过；暂存区为空，仓库内只修改任务卡允许区域。

### 找到根因并实施修复时

- 命中 node 通过，且追踪账目完整闭合。
- `uv run pytest tests/test_runtime_tools.py -q -W error` 通过。
- 上述四项候选组通过，追踪日志不存在 create 后无 close 或未关闭 `__del__`。
- `uv run ruff check src/mica_agent tests` 与 `uv run ruff format --check src/mica_agent tests` 通过。
- 最终只运行一次 `uv run pytest -q -W error`；失败时保留首次现场并停止，不盲目重跑。
- `git diff --check`、`git diff --cached --check` 通过；暂存区为空，修改范围符合任务卡。

本任务不要求 `uv lock --check`、`uv build --offline`、真实 Provider 或真实终端验收。
