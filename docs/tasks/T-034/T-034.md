## 具体实现目标

- 三接口的新会话、继续/选择恢复和空闲模型切换都使用实际目标适配器；供应商接口继承、模型覆盖与明确渠道生效，不因 URL 相同误用 Provider。
- 来源、能力、思考和权限在单轮工具往返中保持不变；显示与有效请求一致。磁盘接口或渠道变化不再让旧 Provider 发送按新来源计算的请求。
- 已保存消息与续接从同一恢复快照进入请求；本轮成功及中断记录携带正确的逐 assistant 续接，跨供应商/模型/接口不回放不兼容私有字段。
- 保留选择优先级、不回退、原子提交、取消、资源收口和敏感诊断；失败不冒充完成，不重放旧工具或伪造结果。

## 具体实现方案（2026-10-20 用户审查通过）

### 工厂与渠道（D-028 已确认）

- `ProviderFactory` 改为 `Callable[[ConnectionBinding], Provider]`。构造和切换均传入一个完整绑定，迁移全部授权调用侧；不保留双签名分流、运行时 arity 探测或捕获 TypeError 后重试旧签名。
- 在 app 模块提供 `default_provider_factory(connection)` 和唯一固定接口到适配器表：Completions → OpenAICompatibleProvider，Responses → OpenAIResponsesProvider，Messages → AnthropicMessagesProvider；从各现有模块导入，不扩大 providers 或顶层包导出。CLI 使用该默认工厂，不另维护选型表，仍允许注入同签名工厂作网络边界替身；保留手工传入 Provider 的既有 MicaApp 用法及无工厂时不能切换的边界。
- ConnectionBinding 末尾新增 `channel: str = "custom"`，保留现有五个位置参数及脱敏 repr；ConfigService 将已校验的供应商 channel 写入保存连接，direct/environment 临时连接仍为 custom 和 Completions。默认工厂仅在 Completions 且 channel 为 deepseek/openrouter 时传入现有 `continuation_channel`；custom、opencode-go 和其他渠道不启用此选项。不按供应商 ID、URL、模型名或响应内容推断渠道，不实现 C1/C2 的渠道头、OAuth 或登录。
- 地址与 Key 原样交对应适配器按其现有规则处理；预算和映射按每轮请求提供，不把能力值固定在 Provider 构造参数中。

### 有效能力与来源冻结

- 在 config_service 模块提取纯函数 `effective_model_options(api, capabilities, settings)`，返回 `(budget, mapping, effort)`，复用现有 `_API_DEFAULTS` 和算法。`for_run` 保留原签名和五项返回结构；选择/磁盘校验及显式容量冲突检查仍在原边界执行，不因供展示复用而提前改变校验时机。
- App 初始化和切换后的有效思考、预算显示使用同一计算入口，不再把 Completions 默认映射套给其他接口；保留显式映射、sources、偏好与每轮 override 的既有语义。prepare_run 继续通过 for_run 刷新能力和设置；不建立第二套能力默认表，不导入配置模块私有默认表，也不为展示重载整份配置。
- `for_run(current=...)` 在现有 URL/Key 变化保护中加入实际 `model.api` 和 `channel` 比较，失配时安全拒绝并要求重启，不在 prepare_run 隐式创建/替换 Provider。原 ConfigService 接口重载测试应迁移为拒绝来源漂移、偏好不变的断言；无 current 的配置查询仍按磁盘实际接口计算能力。
- RunBinding 增加冻结的 `provider_id` 和 `api: ProviderApi`，由已安装的 ConnectionBinding 派生；模型、预算、映射、思考、权限、工具及 Engine 保持既有冻结。无绑定的手工 Provider 用法维持 Completions 默认、`provider_id=None`，不猜测或捏造供应商身份。请求只使用 binding 中的来源，不在 run 中读取可变化的当前选择拼装来源；半轮修改目录不影响本轮，下一轮按变更保护处理。
- 切换仍先校验/构造候选、保存会话选择，再安装 Provider/连接/Engine 和有效能力，最后关闭旧资源。候选能力和显示设置从本次解析连接及同一配置 snapshot.settings 计算，保存成功后一起安装；所有可失败的能力准备放在持久化前，保留失败/取消时候选关闭、旧状态不变和 busy 门禁；不顺手改变“切到当前模型为空操作”的规则。

### 历史输入、完成与中断提交

- 每轮 run 仅调用一次 `model_context_snapshot(session_id)` 取得同一次读取的 messages/continuations，再附系统头和本轮 user；不要先调用旧 messages 入口、再另读续接。CLI 启动检查与 App.history 可以继续使用已有投影入口，但不缓存启动历史代替之后每轮的新快照。
- ProviderRequest 同时传入快照的续接及 binding 的 provider_id/api。保留 assistant 槽位对齐；复用 Engine 已有的供应商 + 模型 + 接口 + replayable 过滤，不在 App 或 CLI 另写一套过滤，不删除保存文件里的旧续接。
- 接入 Engine 的 `completed_continuations_sink`，与 completed_messages/tool_presentations 一起收口；成功提交要求各 sink 完整、仅提交一次，续接数与本轮 transcript 的 assistant 数一致，再写入 TurnEntry.continuations。只提交本轮记录，不把历史续接再写入新 Turn；缺失/错位不能通过默填空槽掩盖。沿用 Engine 原消息清洗及 TurnEntry 契约兜底，不重新解释、修补或拼造签名。
- 中断继续提交 RunProgressSnapshot 中已有的 continuation；未 Finish 的部分输出不附续接。保留统一快照对完整步骤、部分批次和部分正文的投影，不自动执行旧工具。保存失败仍只产生安全 STORAGE 失败，文件不出现半轮或虚假的 RunCompleted；取消/关闭路径保留既有一次提交与资源收口语义。
- CLI new/continue/resume 和 plain/主缓冲区共用该装配；启动模型标签从实际解析连接取得，不再把保存模型显示为 unconfigured。只使用现有 TUI 数据入口，不改渲染/输入逻辑。同步 app/cli 附近说明与 README，明确三接口自动化与用户真实验收的区别。

## 实现要求

- 当前 main 串行施工，不建分支、不暂存、提交、推送、stash 或还原。范围外失败先定位交回，不自行扩大授权。
- 使用隔离 HOME/USERPROFILE、临时配置/会话目录、受保护假 Key 和模拟 transport/本地回环；不读取真实凭据、真实 ~/.mica，不访问真实渠道。默认工厂的链路验证只能替换网络/终端等边界，不能注入已选好的适配器来代替被测的实际选型。
- 凭据、地址、原始响应、密文/签名、思考与未清洗工具参数不得进入新增错误、日志或 repr；既有允许展示的思考只经现有事件/前端通道，不附私有续接。英文用户文案和注释语言遵循项目规范及 D-026。
- 不通过 skip/xfail、删参数、吞错、放宽断言或自动剥离续接重试取得通过。不机械复制此前适配器的整套测试；本卡重点证明实际装配与持久化链路。

## 完成标准

- 默认工厂不依赖测试手选适配器：三接口通过 CLI 保存配置启动，请求抵达各自真实编码入口和预期端点，模型覆盖生效，预算/思考字段正确；同一基址仍能区分接口。DeepSeek/OpenRouter 的明确渠道启用既有 Completions 续接；custom/opencode-go 和临时连接不误启用。
- startup、switch、prepare_run 的能力显示/实际请求一致：Messages 默认 minimal 降为 OFF，显式 minimal→low 生效，其他接口及无思考降级保持；保存偏好、来源和文件字节不因计算变化。渠道字段透传、旧五参数 ConnectionBinding 和脱敏 repr 有证据；保存连接的 API/渠道/URL/Key 在轮间漂移安全拒绝且无请求/无新提交，普通能力更新仍在下一轮生效，轮内更新不改变已冻结来源和能力。
- 三接口各有实际 App→Engine→适配器→模拟 SSE→TurnEntry→重新读取/下一轮请求的工具往返；断言本轮/历史续接不重复、纯思考无正文步骤和逐 assistant 空槽不丢失、来源匹配才回放。CLI continue/resume 使用保存选择与续接，显式选择和临时连接仍按原优先级，不偷偷回退。
- 三接口六个有向切换组合均验证通用对话、真实工具调用/结果关联及私有续接过滤；另覆盖同接口跨供应商、跨模型及切回原连接。切换本身不执行/改写历史，回切重新检查绑定，不承诺签名一定有效；服务端签名拒绝保持真实失败，不剥离后重试。
- 代表性取消/可恢复失败、部分工具批次、未完成流以及保存失败经产品路径验证：完整步骤续接保留、未 Finish 无记录、旧工具不重放、未完成结果不伪造；Turn/检查点写入在终态之前且最多一次，失败字节保护及副作用警告保留。不要求将每种失败与六个方向做无意义笛卡尔积，但三接口都必须有中断恢复证据。
- 既有空闲/预留/运行/关闭门禁、构造失败、保存选择失败/取消、候选和旧 Provider 的关闭次数/有界关闭、全局默认与当前选择分离均保留；授权调用侧完成工厂迁移，未降低原保护。默认 CLI/TUI 标签和能力提示来自真实所选模型，未引入视觉改版。
