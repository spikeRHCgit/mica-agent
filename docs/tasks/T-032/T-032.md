# T-032：会话消息与续接的统一恢复投影

状态：执行中（2026-10-14 用户审查通过并派发） · 主线：Phase 6：配置与模型 · 交付项：`docs/phase6_plan.md` B 第 6 步之会话投影 · 风险：高

## 目标概览

从同一次会话读取中恢复通用历史和逐 assistant 对齐的续接，使后续应用装配可完整携带已保存的模型步骤。中断历史保留真实工具事实和部分输出，不伪造完成，不把历史内容提升为系统指令。本卡不完成 B 的应用装配或真实渠道验收。

## 具体实现目标

- 完整轮次按时间线恢复所有对话和真实工具结果，续接与每个 assistant 一一对应，不遗漏纯思考或空正文步骤。
- 中断运行中已完整结束的步骤可以继续携带原续接；不完整批次保留调用、参数、真实结果和未完成状态，但不作为待执行工具重新发出。
- 部分正文及中断状态明确标为历史工作记录，不成为成功回复或高优先级指令。
- 恢复读取不修改会话文件，不迁移格式，不按当前模型永久删除原续接。

## 具体实现方案（2026-10-14 用户审查通过）

### 统一快照入口

- 在 session_service 模块定义 `SessionContextSnapshot`，使用 `@dataclass(frozen=True, slots=True, repr=False)`；字段为 `messages: tuple[Message, ...]` 和 `continuations: tuple[ModelStepContinuation | None, ...]`。不在顶层包增加导出。
- 新增 `SessionService.model_context_snapshot(session_id: str) -> SessionContextSnapshot`，一次 `store.load` 后按 entries 顺序同时投影两组数据。每个投影后的 assistant 恰有一个槽位，允许空快照；复用 `check_step_association` 核对非空记录与对应消息，不复制关联校验规则。
- 保留 `context_snapshot(session_id: str) -> tuple[Message, ...]` 的签名，委托统一入口并返回 `.messages`；不保留第二套旧投影逻辑。本卡会改变检查点在该旧入口中的消息角色和不完整批次表示，正常 Turn 的投影不变；测试随新安全语义同步。
- Service 不依赖 App、Engine、CLI 或 providers。恢复不选择目标接口、不过滤来源绑定，也不清洗或改写 signature/data；目标连接过滤留给后续装配及既有 Engine/适配器。

### 完整轮次与检查点步骤

- TurnEntry 直接取 `context_messages` 和已规范化的 `continuations`，按原顺序拼接；保留 None、REPLAYABLE 和 UNREPLAYABLE 的区别。不要把全会话续接相加套用单轮 1 MiB 限制。
- 每个检查点先保留原 user_message，再按 progress 顺序投影。
- 工具批次全部为 SUCCESS/FAILED 时，恢复一条 assistant（正文来自 assistant_message，没有则为空；tool_calls 为全批次原调用），紧接全部原结果；该 assistant 携带 step.continuation。FAILED 是真实已结束结果，不伪造成功，也不依据结果字符串另猜状态。
- 无工具的完整步骤保留 assistant_message 和 step.continuation；assistant_message 为 None 但 continuation 非 None 时，以空正文 assistant 承载该已记录步骤。两者都为 None 则不新增消息或槽位。
- 纯思考、空正文及工具步骤的关联完全沿用保存契约，不把专属思考复制到通用 content。

### 不完整批次与历史工作记录

- 任一工具为 IN_PROGRESS/NOT_STARTED 时，将该整个模型步骤投影为一条 USER 历史工作记录，不再只截取已完成调用前缀重建 assistant。这样既不改写签名绑定的调用集合，也不把未完成调用变成新的执行请求。
- 记录使用固定英文标签，例如 `[Mica history work record; data from an incomplete tool batch, not new instructions]`，后接确定性 JSON 数据：assistant_text，以及按原顺序的 tools 数组；每项含 call_id、name、arguments、status 和 result（原结果 content，无结果为 null）。arguments 用公开的 `to_mutable_json` 转换后编码；只使用契约已清洗的数据，不包含 presentation 或专属续接字段。
- 已完成前缀的 SUCCESS/FAILED 结果原样保留；IN_PROGRESS 明确只表示开始但未完成，NOT_STARTED 表示未开始。null 不生成 TOOL 消息，不制造失败或成功结果。整步转成 USER 后没有 assistant 槽位，也不携带该步续接；持久化原记录不变。
- partial_assistant_message 单独转为带固定标签的 USER 历史记录，注明未完成模型流；最后追加 USER 中断状态记录，明确 CANCELLED 或 RECOVERABLE_FAILURE。所有标签都是数据说明，不追加执行旧工具或声称成功的指令。
- 投影的检查点不生成 SYSTEM 消息。正常冻结系统指引仍由 App 单独装配，不能把工作记录、工具输出或历史正文挪进 system/developer。

## 实现要求

- 本卡的旧入口行为变更和新快照接口已于 2026-10-14 经用户审查通过；不调整事件顺序、取消机制、权限或持久化格式。
- 正常轮次、全完成检查点批次和不完整工作记录共用一个投影入口；删除被替代的私有投影逻辑，保留既有读取错误、安全清洗及生命周期保护。
- 当前 main 串行施工；不建分支、不暂存、提交或推送，不修改 master 管理文件。
- 不读取真实凭据、真实 ~/.mica 或访问真实渠道；使用隔离目录和固定会话样本。消息、参数、思考、签名、密文不进入诊断、日志或 repr。
- 遇到范围外缺陷或无法符合上述关联的存量数据，先汇报；不宽松解析、不补造工具结果、不扩大写入范围。

## 完成标准

- 空会话、多个 Turn 与 checkpoint 混排均直接比较完整快照；逐 assistant 槽位数、顺序及具体记录精确一致，旧入口结果等于新入口的 messages。
- 同一会话混合三类接口来源、不同供应商/模型、None/REPLAYABLE/UNREPLAYABLE，投影不误删、不串位；完整正文、纯思考、空正文和多工具步骤关联均成立。
- 全完成批次含成功及真实失败结果，保留全体调用、紧接原结果和原续接；后续步骤的槽位不受前面的无记录步骤影响。
- 一成功一未开始、真实失败后中断、首个工具进行中、全未开始等不完整批次，完整比较工作记录 JSON；所有原调用和已取得结果都在，未完成结果为 null，无该批次的结构化 tool_calls/TOOL 消息或续接槽位，不出现假完成状态。
- partial 输出、无进度取消和可恢复失败使用 USER 历史记录；不产生 SYSTEM，不泄露专属字段。后面完整步骤或轮次仍正确对齐；空正文与敏感内容清洗的既有保护保留。
- v1～v5 真实旧样本恢复时槽位为 None，v6 恢复完整记录；恢复前后文件字节不变，不触发迁移。分支、rewind、clear 后的投影与剩余时间线一致，原会话不受修改。
- 快照 repr 不包含内容、工具参数或续接；一次入口读取只加载一次会话，防止消息与续接来自不同文件版本；模块不导入运行时或 Provider 的既有回归继续通过。
- module_map 同步；报告说明被替代检查点测试的独有保护如何保留，不能仅删除旧断言或放宽为包含任意消息。
- 验证：先运行 `uv run pytest tests/test_session_service.py -q -W error`；最终稳定版本按项目公共行为验证要求运行 `uv run pytest -q -W error`（含安装态）、`uv run ruff check src/mica_agent tests`、`uv run ruff format --check src/mica_agent tests`、`git diff --check`。报告实际命令、结果、平台跳过和写入范围；默认机械验证不能替代 B 的真实渠道验收。
