## 目标概览

新增独立的 Responses 适配器，能转换通用历史与兼容续接、完整处理流式正文/思考/工具调用，并向既有 Engine 交回真实终态。只交付 API Key 的标准 Responses 路径；App 装配由 B 第 6 步完成，ChatGPT 订阅差异由 C2 接入。

## 具体实现目标

- 普通推理、工具往返和纯思考步骤都能向 Engine 返回完整结果；思考与正文分开，签名和密文不作为可见文字。
- 历史工具调用与真实结果一一关联，兼容续接按保存顺序回放；绑定不兼容时只转换通用历史。
- 输出项完成不能冒充整响应完成；失败、输出不完整、流内错误、断流和取消都保留真实状态。
- 未知专属输出或不可表示的续接使该步不可回放，保留支持的正文和真实工具事实；不能把未执行的服务端工具伪装成本地工具调用或成功结果。
- 请求、流式续接和网络资源有明确边界，不无限累计专属内容，不泄漏原始响应或凭据。

## 具体实现方案（待用户审查）

### 入口与请求

- 新模块定义 `OpenAIResponsesProvider`，使用 httpx；直接从该模块导入，本卡不扩充公共导出。
- 构造参数采用已有 Provider 的风格：`api_key`、`base_url`（默认 `https://api.openai.com/v1`），以及 timeout、max_retries、retry_backoff、sleep、transport、thinking_level_map 关键字参数；默认超时 30 秒、重试 1 次、退避 1 秒。凭据仅进入 Authorization 头，repr 和诊断不得显示它或 URL 中的敏感部分。
- 模块自己的 `resolve_endpoint`：已以 `/responses` 结尾的完整端点只去尾斜杠，否则在基址路径后追加 `/responses`，不重复追加。
- 请求固定 `model`、`input`、`stream=true`、`store=false`、`include=["reasoning.encrypted_content"]`；发送完整 input，不用 previous_response_id。普通 API Key 路径发送 `max_output_tokens`，取 request.max_tokens 或默认 4096。
- 系统指引保持 system message，与用户/工具历史分开；不得把工具输出或历史正文提升为 system/developer。本卡不把系统指引转换为订阅专用 instructions。
- 工具编码为扁平 `{type:"function",name,description,parameters,strict:false}`，参数直接取 ToolSpec schema，不为了 strict 改写 required 或 additionalProperties；不启用服务端内置工具。
- reasoning_effort=off 时不发送 reasoning 参数；非 off 时发送 `reasoning:{effort:<映射值>,summary:"auto"}`。非空 thinking_level_map 用显式映射，缺失/空映射用经测试的 minimal/low/medium/high/xhigh/max 同名默认映射；不发送未经确认的 reasoning.context。不支持的档位用固定诊断 ProviderErrorEvent 结束。
- request.api 必须为 OPENAI_RESPONSES；其他接口请求以安全错误结束，不按模型名猜接口。

### 历史转换与续接

- 无兼容续接时：system/user 为简易 message；assistant 非空正文为简易 assistant message；每个 ToolCall 编码 function_call（call_id/name/JSON 字符串 arguments），每条 tool message 编码显式带 call_id 的 function_call_output。空 assistant 且无调用时用空正文 message 保留该步骤。
- 兼容条件沿用 T-029：供应商 ID 已知，record.provider_id、model_id、api 三者一致且 replayable。槽位与 assistant 一一对应，无论是否兼容都消费对应位置。
- 兼容时按记录 items 顺序编码：reasoning 的 id、summary_text 列表、encrypted_content 原值；text 从对应通用消息取正文，phase 非 None 时原样带上；tool_call 引用从同一步通用消息取调用。不可回放记录不输出任何 reasoning/phase 专属字段。
- 工具 call_id 不修改、function_call 的输出项 id 不代替 call_id。本卡标准 Responses 不做猜测式 ID 改写；工具结果有且仅有关联调用才可编码，同一调用不重复生成结果。缺失结果的历史调用可以保留，但不得补造结果或执行它。
- 通用消息无法合法转换（例如孤立工具结果）时固定诊断拒绝请求，不删除真实事实后假装请求有效。其他接口的内部思考不进入 Responses input。

### SSE 与终态

- 正确读取 SSE 帧：支持注释、空行、event 字段、同帧多行 data；JSON 的 type 为事件类型，event 字段存在时应与 type 一致。不把每一行 data 单独当一条完整 JSON。复用现有测试传输替身；本卡无需抽取共用 SSE 模块。
- 以 output_index 维护输出项顺序，并核对 item_id；function_call 的 arguments.delta 按事件顺序拼接，done 的完整 arguments 与累积片段一致（无 delta 时以 done 完整值为准）。元数据冲突、重复调用身份、非法 JSON/非对象参数按 malformed 错误结束。
- `response.output_text.delta` 产生 TextDelta；reasoning_summary_text.delta 和 reasoning_text.delta 产生独立 ProviderReasoningDelta，不通过正文标签猜思考。done/完整快照只补未通过 delta 发出的内容，已发部分必须一致，不能重复展示。
- `response.output_item.done` 是项收口，reasoning 的最终密文从这里或 completed 的最终项取，不能使用 added 的不完整值。`response.completed` 的 response.status 必须 completed；最终 output 与已收集的身份、次序、正文、工具及参数核对，无增量事件的完整项可从该快照补齐。
- 只有 response.completed 产出一次 Finish 并停止；reason 统一使用 `completed`，待执行工具调用放入 tool_calls。纯 reasoning、无正文无工具的完整步骤也能 Finish。
- response.failed、response.incomplete、顶层 error 为最后一个 ProviderErrorEvent，绝不发 Finish；[DONE] 或 EOF 无 completed 同样为 malformed。终态后停止消费，取消传播 CancelledError，关闭响应及客户端资源。
- 对 HTTP 401/403、429、408、500/502/503/504 和连接超时/错误使用既有错误类别；其他 HTTP 状态保留安全固定诊断。流内错误按明确 code 分类，未知 code 使用 ProviderError；incomplete 使用明确但不含原始值的错误，不能剥离续接后重试。
- 只对尚未产生任何正文、思考、工具碎片或专属输出的连接失败/连接超时和临时 HTTP 失败做有界重试；HTTP 响应建立后消费流时断流/超时为 malformed，不重试。未知原始 error.message/body 不直接进入诊断。

### 输出续接和上限

- provider_id 已知时，正常 Finish 携带绑定本次请求的 ModelStepContinuation；未知来源时 continuation=None。通用正文和工具仍可完成。
- 支持的输出按原 output 顺序构造 ResponsesReasoningItem、TextItem 和 ToolCallItem。非空正文恰有一个 text 引用；正文为空不放 text。收到多个正文输出项/不能用既有一个 text 槽位忠实表示的多块正文时，通用文字可合并展示，但整步续接标为不可回放。
- reasoning 只保存白名单 id、summary、encrypted_content；完整 reasoning 缺少有效密文、未知 phase、未知项类型或新增语义字段导致无法忠实回放时整步不可回放。输出项的 type/id/status/role/content 等已知协议包装字段不因未持久化而误判为未知；不得把任意新增字段悄悄丢弃后仍声称可回放。
- 遇到 refusal 时保留拒绝文字作为通用正文，整步不可回放，不伪造 output_text 或成功工具结果。未知服务端工具输出不转成 ToolCall。
- 单步续接按 continuation_size 的紧凑 JSON UTF-8 字节数控制，超过 1 MiB 时释放专属累计内容并保持 unreplayable。完成快照不得重新装回超限记录；只暂存处理当前事件所需内容，不保存整个原始 response 副本。通用正文和工具参数按现有 Engine/工具约束处理。
- 清洗判定仍由 Engine 用完整原始消息负责；适配器不修改签名或密文。本卡不改变续接契约的白名单和关联规则。

## 实现要求

- 全部模型/工具循环继续由 Engine 负责，适配器只做单次请求和协议转换。
- 不新增依赖，不继承或调用 Chat Completions 的私有方法；确有共用抽取需求留待后续卡，不扩大范围。
- 原始响应、密文、摘要、思考和工具参数不进入错误、日志或 repr。网络测试使用 fake key 和 transport/本机模拟服务，不访问真实渠道或真实 ~/.mica。
- App 选适配器、SessionService 投影和跨接口应用装配由第 6 步负责；本卡测试通过直接实例化新适配器证明真实编码与解析。

## 完成标准

- 请求字面量测试覆盖普通对话、system、输出预算、工具 schema、off/默认/显式思考映射，以及基址/完整端点；断言 store=false、完整 input、无 previous_response_id。
- 两步工具往返的固定 SSE 样本通过真实适配器与既有 Engine：多调用参数碎片完整组装，第二次请求中的 reasoning/text/工具调用及结果顺序和 call_id 正确；Finish 与下一请求逐字段对照字面量。
- 纯思考、无正文、文本 phase、无 delta 只有最终快照、增量与 done 一致分别正常完成，不重复正文或思考；reasoning 的密文取最终值。
- 同源模型接口一致才回放；三类绑定不符、None 槽位、unreplayable 保留通用历史、不回传专属项。孤立工具结果拒绝，未完成工具不补结果或自动重执行。
- 参数非 JSON/非对象、调用身份冲突、item_id/index 冲突、delta/done/completed 不一致产生安全 malformed 错误，工具不执行。
- output_item.done、failed、incomplete、error、[DONE]、自然 EOF 和断流均不能单独产生 Finish；错误流没有第二个终态，诊断不含假凭据、路径、思考或原始 error 内容。
- unknown output、未知 phase、多个 text 输出、缺失密文、refusal 均按方案降级；未知服务端工具不进入本地执行，通用正文和实际工具事实保留。
- 恰好 1 MiB 可回放，超出 1 字节与 UTF-8/转义边界按真实 wire 字节数降级；超限后不重新累计或被 completed 恢复，密文不展示。
- SSE 覆盖同帧多行 data、注释、event/type 核对；超时、取消、失败关闭响应，aclose 幂等；重试有界且输出后不重试。
