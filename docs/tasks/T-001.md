## 契约与约束

- 本任务只处理 `#` 注释和 docstring。界面文本、错误消息、日志、提示词、协议值、测试样本和其他
  运行时字符串不是注释，不得机械翻译或改写。
- 所有保留的源码注释和 docstring 使用简洁、准确的英文。允许删除无价值注释，不要求给每个私有
  函数补 docstring。
- 删除阶段号、任务号、worker 名称、返工过程、临时结论、失效未来时、分区装饰线、复述代码的
  注释以及没有背景和移除条件的 TODO/FIXME。
- 保留并准确表达设计原因、不变量、状态所有权、外部限制、兼容条件、安全边界以及取消和清理语义。
- 模块与类 docstring 只概括角色和边界；公共类型、协议和入口在确有必要时说明输入输出、失败语义和
  关键限制；不要把现有中文逐字扩写成更长的英文。
- 统一使用 run、turn、session、checkpoint、tool call、provider、terminal event 等现有领域术语。
- `noqa`、`type: ignore`、`pragma` 和覆盖率排除必须留在原本的精确位置；现有原因若为中文，只翻译
  原因，不改变指令、错误码或覆盖范围。
- 不得修改标识符、导入、类型注解、装饰器、默认值、产品文本、异常文本、wire value、公共导出、
  控制流、表达式、数据结构或代码格式；发现真正的实现问题只记录，不在本任务修复。
- 不更新冻结中的 `docs/module_map.md`，不开始测试精简、TUI 注释修整或源码架构重构。

## 执行要求

1. 开始时只读记录 Git 分支、HEAD、上游和工作区；确认 `04b86b9` 是当前 HEAD 的祖先，且从该产品
   基线到任务起点没有修改 `src/mica_agent/**`。若存在不明改动或写入范围与其他任务冲突，立即
   停下报告。
2. 用 Python `tokenize` 与 AST 分别识别注释和 docstring；不要用“搜索所有中文字符串”的结果替代
   注释审计，以免误改产品数据。
3. 分文件完成清理，并保留一份“删除 / 重写 / 保留”的简短分类结果；不需要逐条记录翻译流水。
4. 对每个修改后的 Python 文件，将工作树版本与基线 `04b86b9` 中的同一路径解析为 AST，移除模块、
   类和函数的 docstring 节点后，以 `ast.dump(..., include_attributes=False)` 比较；任何不等价都必须
   视为越界并恢复该实现改动。
5. 再用 token 与 AST 级扫描确认允许范围内没有中文注释或中文 docstring，也没有阶段号、任务号、
   worker/返工等施工历史。扫描只针对注释/docstring，不扫描全部字符串字面量。
6. 不使用自动翻译器或无审查的批量替换；每条英文必须与相邻实现和当前契约一致。

## 验收

- 修改文件全部位于允许范围；没有产品实现、测试、TUI 或治理文档越界改动。
- 修改前后去除 docstring 的可执行 AST 对所有改动文件完全等价。
- 允许范围内中文注释和中文 docstring 为 0；施工历史标记为 0；合法指令注释仍在原位置。
- `uv run ruff check src/mica_agent` 通过。
- `uv run ruff format --check src/mica_agent` 通过。
- `uv run pytest tests/test_public_api.py tests/test_distribution.py -q -W error` 通过。
- `git diff --check` 与 `git diff --cached --check` 通过；暂存区必须为空。
- 本任务不要求全量 pytest 或离线构建，它们留到全部源码注释完成后的全局收口；如聚焦验证暴露
  真实失败，应报告而不是扩大修复范围。
