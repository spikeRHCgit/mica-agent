## 迁移契约

### 1.冻结迁移前事实

- 记录 6 个源文件各自的顶层测试函数、参数化收集项和总收集项。
- 当前已核对的基线为：源文件合计 54 项，连同现有 `test_tool_session_integration.py` 1 项共 55 项；全仓
  1725 项。worker 必须独立复核，数量不一致时先说明原因，不为命中预期数字而删改测试。
- 建立“源测试函数/参数项 → 最终目标文件”的完整映射；迁移完成前不得删除源文件。

### 2.按稳定行为归档

- `test_p4_07_integration.py` 与 `test_p4_12_integration.py` 全部并入
  `test_tool_session_integration.py`，与现有工具批次 checkpoint 场景共同形成工具执行、持久化和恢复闭环。
- `test_p3_05_integration.py` 中 App/SessionService 持久化场景迁入 `test_session_integration.py`；CLI
  new/continue/resume/preflight 场景迁入 `test_cli_startup.py`。
- `test_p4_09_integration.py` 全部迁入 `test_cli_startup.py`，与 CLI 会话选择场景共同保护装配顺序、header
  单次构建、失败短路和 Provider 不应启动的边界。
- `test_p4_11_integration.py` 迁入 `test_reasoning_integration.py`。
- `test_p5_07_permissions.py` 迁入 `test_permission_integration.py`。
- 完整迁移后删除 6 个阶段命名源文件；最终不得同时保留阶段命名副本和行为命名副本。

### 3.行为与安全边界全部保留

- Session：成功轮次、两轮恢复、失败/取消/consumer close 不提交成功 turn、storage failure 不留下半轮、
  AGENTS 上下文和 JSONL 结果均保留原证据。
- CLI：空 EOF、上下文 preflight、continue/resume、无健康会话、非法选择、安全诊断、header 单次构建、
  session 选择和 system prompt 失败先于 Provider 构造的顺序均保留。
- Tool session：工具失败后模型恢复、退出重载后的完整脱敏上下文、真实 write/edit 的安全展示和持久化、
  已完成工具前缀与未开始工具不伪造结果均保留。
- Reasoning：reasoning 允许穿过 Provider 与 Engine/App，但不得写入成功会话历史的边界保持不变。
- Permission：风险命令的 default/solo 矩阵、allow/deny、受保护文件、等待取消不执行 handler、日常 Bash/网络
  fake handler 和 solo 文件能力限制全部保留。
- 兼容、安全、凭据清洗、取消和资源清理断言不得因“只是迁名”而弱化。

### 4.装配与命名约束

- 优先在同一目标文件内合并完全相同的局部 Provider、Input、Recorder、session 或事件收集 helper；只有状态、
  生命周期和失败语义完全一致时才能共享。
- 不建立全局 `conftest.py`、万能 App factory 或跨领域共享测试框架；不同取消入口和不同资源所有权不得为了
  减少行数强行合并。
- 不新增产品测试场景，不主动删除收集项。若发现严格重复或当前行为与 T-004 审计不符，记录证据并停下请求
  master 裁决，不在本任务内自行扩大为新一轮测试去重。
- 新建或改写的模块 docstring、注释和测试名称使用简洁英文；删除阶段号、任务号和施工历史措辞，但不把本任务
  扩大为其他测试文件的注释清理。
- 不加入固定 sleep、自动重试、warning 过滤、跳过标记或放宽断言。
