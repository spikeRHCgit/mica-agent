# T-033：配置接口与有效模型能力

状态：已完成（2026-10-15 第二轮验收通过） · 主线：Phase 6：配置与模型 · 交付项：`docs/phase6_plan.md` B 第 6 步之配置接口与能力 · 风险：高

## 目标概览

使本地保存的三类接口模型都能解析出连接，并按模型实际接口提供每轮默认输出预算与思考档位。保留显式能力、来源说明和用户偏好，不能把无思考或不支持的偏好硬发给模型。本卡只完成配置层，不代表 App/CLI 已能通过新接口运行；Provider 选择、续接装配及真实渠道验收留给下一卡。

## 具体实现目标

- 保存目录中的合法三类接口连接均可选用；供应商默认接口和模型显式覆盖都生效，未知接口、禁用、缺凭据及重复模型仍不可用。
- 缺失或空思考映射按实际接口提供默认档位；非空显式映射只提供明确声明的档位，不被默认值扩充或覆盖。
- 不支持思考或不支持当前偏好时，每轮有效思考为 off；保存偏好和来源说明不因降级被改写。
- 原选择优先级、不回退、安全诊断、临时 Completions 身份及预算保护保持不变；调用侧测试继续保护真正未知接口的过滤与失败回滚。

## 具体实现方案（2026-10-15 用户审查通过）

### 保存连接与接口默认值

- 在 ConfigService 模块内使用一张固定的接口默认值表，结构为 `api -> (默认输出预算, 默认思考映射)`。三项分别引用对应适配器的公开 `DEFAULT_MAX_TOKENS` 和 `DEFAULT_THINKING_LEVEL_MAP`，必要时用明确导入别名；已支持接口集合取该表的键，不另维护一份列表。
- 不复制默认表，不实例化 Provider，不引入可注册框架，不跨模块依赖私有符号。当前三接口输出预算均为 4096；Completions/Responses 默认含 minimal、low、medium、high、xhigh、max，Messages 默认不含 minimal。
- `_parse_directory` 保留现有供应商及模型接口校验、模型覆盖和凭据保护；对已校验合法的模型，只要供应商启用且受保护 API Key 可用，就建立 `ConnectionBinding`，移除仅 Completions 才绑定的限制。绑定保留实际 model.api、原始合法基址和既有 selection/source，不在配置层改写 endpoint。
- `for_run` 使用本次解析出的 `connection.model.api` 查默认值表。显式 max_tokens 优先；缺失时用该接口预算。保留显式 contextWindow 与输出预算冲突检查，不把输出预算当成上下文长度。

### 显式能力、来源和降级边界

- 保持 `load`、`resolve`、`for_run`、`save_default_model` 的公共签名及返回结构不变。`ModelCapabilities` 仍保存解析后的显式映射，默认映射只在 for_run 计算时补齐，不回填配置或伪装成显式来源。
- 保持当前映射解析规则：未知档位忽略且合法邻居保留；已知档位目标不是非空可打印字符串时，整份映射回退接口默认并给安全 warning；非字典映射同样回退。缺失、空或解析后为空的映射取实际接口默认。
- 合法非空映射原样用于本轮，不按默认映射的键或值筛掉。例如 Messages 可显式声明 `minimal -> low`；Completions/Responses 的自定义目标字符串仍保留。配置层只校验通用结构，不新增 Messages 专属目标值校验；Messages 仅接受 low/medium/high/xhigh/max 目标的限制继续由既有适配器校验，不能为了容纳非法目标而放宽适配器。本卡的本地 ready 不等于远端请求已验证。
- reasoning 缺失或 false 时有效映射为空、有效 effort 为 OFF；reasoning 为 true 但偏好不在有效映射中时也为 OFF。settings 中原偏好及 sources 保留，不写盘。sources 继续区分 explicit、adapter default 和原设置来源，不新增一套来源格式。
- `direct_connection` 和环境临时连接仍固定 Completions；保留其现有 endpoint 归一、稳定身份、密钥无关及 env/direct 域分离，不新增协议参数或改变身份计算。

### 两项直接调用侧测试

- 模型目录测试中的 `unsupported` 模型改用 `unknown-protocol`，保留排序、供应商、容量默认标记、current/default 分离、保存全局默认不切换当前及敏感文本断言。
- 失败切换测试的 `protocol` 参数改用 `unknown-protocol`，其他参数不变；保留 Provider/连接/选择/summary、保存文件字节、资源关闭次数及 busy 状态断言。
- 这里只修正已改变的“未知接口”输入样本，不将失败改成成功、不降低断言强度、不提前测试尚未完成的新接口 App 装配。三接口可解析和默认能力由 ConfigService 专项直接证明。

## 完成标准

- 三种供应商默认接口分别可继承；每种默认下模型可覆盖为三种接口，解析出的 ModelConfig 和 ConnectionBinding 精确保留目标 api、选择、基址及来源，不依赖联网。
- 三接口均覆盖 disabled、缺 Key 和未知模型接口的不可用性；未知供应商接口不会被模型覆盖绕过，重复模型的既有拒绝及合法邻居保护保留。
- Responses/Messages 的 explicit、saved、default 选择及保存全局默认可以成功；失效 explicit/saved 不回退，原 environment 优先级和临时身份回归继续通过。
- 对三接口逐项比较缺失及空映射的完整有效映射与预算。Messages 默认下 minimal 偏好降为 OFF，其他五档可用；Completions/Responses 的 minimal 可用。expected 明确列出协议值，不从被测默认值表生成。
- 非空显式映射完整相等，不补默认邻居；未列出的偏好降为 OFF。覆盖 Completions/Responses 自定义目标及 Messages 的 `minimal -> low`，证明显式键不受默认档位集合限制。
- reasoning 缺失和 false 均返回空有效映射与 OFF；有效降级不改变 settings 的保存偏好、来源或配置文件字节。
- 非字典、已知档位非法目标和仅未知档位的映射按既有规则采用实际接口默认；混合未知档位与合法邻居时保留合法项。warning 不回显输入值。
- 三接口显式输出预算优先且 sources 正确；保留正整数/拒绝 bool、默认上下文和显式容量冲突的保护。capabilities、sources 和默认映射的既有只读保证不受破坏。
- 两项 App 测试仅迁移授权样本且原保护继续通过；module_map 同步，报告区分本地配置可用、自动化通过和未完成的产品装配/真实渠道验收。
