## 目标概览

用户于 2026-10-24 明确要求停止 master 逐项推进探测，改由 worker 自行诊断并进行针对性修复。本卡合并定位、最小修复和回归验证，worker 可在下述范围内连续完成，不为每个普通实现选择等待 master 确认，也不只交下一轮实验方案。

修复必须来自可复现的具体缺陷；不得为交差制造补丁。如果没有确认本地缺陷，或证据只指向真实渠道，应如实交回阻塞与已完成部分，不能把诊断完成、报错改善或模拟通过写成用户问题已解决。

## 具体实现目标

1. 交出至少一个与 A 或 H 直接相关的确定性输入，明确实际结果、预期结果与依据；或明确证明现有证据不足以认定本地缺陷，不把猜测包装成复现。
2. 对范围内确认的缺陷实施最小根因修复，保持正确的工具关联、事实历史、正常终态、取消、安全清洗及资源收口；不是只改善错误文案。
3. 回归能在旧实现上暴露该具体问题，并在修复后通过；保护普通文本无工具、正常工具往返和拒绝/中断等受影响边界，不能让 Engine 从普通文本推断并执行工具。
4. A、H 分别说明哪些已经定位/修复，哪些仍待真实渠道确认；本地修复不能自动解释另一个现象。

## 具体实现方案与自主权限

- 以现有 Messages 适配器为唯一协议边界，沿用现有 ProviderRequest、Finish、Message、ToolCall、续接及单一 Engine Loop；不新增工具选择公共 API，不为渠道另建 Agent Loop。
- 优先检查 T-035 最小样本尚未覆盖、且与现象有直接联系的实际请求编码/工具历史组合，以及流响应与错误边界。先找到反例并写失败回归，再修改实现；不要为了制造“缺陷”而改协议期望。
- 可以自行选择定位方法、补充合成边界样本、调整模块内实现、执行必要专项和最终验证，不逐步请求 master 决定变量或普通代码细节。用户本次要求覆盖此处“定位后直接修复”的连续施工，不另派纯调研卡。
- 回归期望必须有独立协议依据或既定契约，不能由被测编码器生成答案再与自身比较。公开文档无法抓取时如实标记；继续完成不依赖它的源码定位和验证，不反复抓取同一失败入口，不用镜像绕过访问限制。
- 只在网络边界使用 MockTransport/RecordingTransport；被检查的编码、解析、Engine、ToolExecutor 与真实产品 read 不得 fake。需要执行工具的回归仅允许读取自己创建的指定临时文件，禁止其他 Agent 工具执行。
- 不默认发送强制 tool_choice，不通过调提示词、关闭校验、降级其他协议、剥离历史/续接、400 后重试、伪造工具结果、吞错或放宽终态断言“修好”现象。若真正修复需要改变既定行为，交回具体设计影响，不擅自实施。
- 错误分类或安全诊断若确有独立缺陷可修复，但须单独标注，不能据此宣称原工具问题已修复。
