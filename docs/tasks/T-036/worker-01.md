### 检查结果与协议依据

本轮实际读到了 Anthropic 官方 [Define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools) 与 [Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls) 正文。官方规则支持以下检查：auto 不保证选工具；工具 input 为对象；关联结果位于紧随 assistant 的 user 消息中；该消息中的工具结果先于文字。Mica 相关出站路径符合这些规则。本轮不把官方 Claude 规则外推成当前第三方渠道的已验证支持。

本轮还读到了 [Create a Message](https://platform.claude.com/docs/en/api/messages/create) 正文，但该页展示当前 API 版本，不据此更换产品 `2023-06-01` 版本头；`text-block-param` 子页仍无法抓取，没有换抓取器或镜像绕过。因此没有把空 text 的服务端精确限制升级成确认结论。H 的历史实测已经明确无空 text，本轮也没有用这个候选解释此前 400。

历史矩阵使用两批三次合成 read 调用，**不执行历史工具**。组合维度为三组 ID（合法、含斜线/点及保留名碰撞、Unicode/冒号及保留名碰撞）× 有/无 assistant 正文 × 工具结果正/逆序 × 四类续接（空、匹配原生引用、模型错绑且含私有思考、不可回放）。在真实 HTTP 请求边界比较手写预期，检查两个批次的关联、对象参数及嵌套 JSON、中文/转义文本、工具结果在用户正文之前、ID 映射不碰撞、错绑私有内容不发送、不推断 is_error，以及输入历史不变。48 组全部通过；模型错绑保留事实但过滤私有内容。

Engine 矩阵使用仅注册 read 的真实 ToolExecutor 和产品 read handler；只允许读取该用例创建的 `probe.txt` 一次。网络边界分别返回 gzip/非 gzip 的三字节切片流，覆盖：普通文本提及 read、正常 JSON 分片工具往返、缺 message_stop、工具参数为数组、refusal。10 组通过：仅正常工具组各执行一次 read，第二请求包含实际读取结果；其余 8 组零执行。所有响应和客户端收口。它证明这些输入下的编码、解压后 SSE 解析、Finish/Engine 交接及终态有效，不能代替真实渠道响应。
