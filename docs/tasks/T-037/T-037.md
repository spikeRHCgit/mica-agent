## 目标概览

实现 C1 登录及连接维护所需的真实产品存储能力：按稳定供应商 ID 新增、更新和删除模型目录条目，安全保存、更换和删除 API Key。保存必须抗并发覆盖、保留无关记录，写失败不破坏旧数据；保存结果能被现有 ConfigService 正常读取和解析。

## 具体实现目标

1. 对 models.json 的指定供应商条目完成新增、字段更新和删除。更新显示名、enabled、URL、接口或 models 时不改变稳定 ID，不丢失其他供应商、根未知字段和目标条目的未修改字段。删除不删除会话或擅自重写 config.json 默认选择。
2. 对 auth.json 的指定 API Key 条目完成安全新增、更换和删除。使用既有 `{"providers": {"<id>": {"type": "api_key", "apiKey": "<key>"}}}` 形状，不增加版本或新认证格式。原始 Key 不进入异常、repr、日志或普通配置快照。
3. 同目标并发写入出现明确冲突；不同目标在锁内重读合并，不互相覆盖。损坏或结构无效文件不自动重建，序列化、权限、写入或替换失败如实报告。
4. 真正新建、保存及替换后的凭据文件可通过既有 read_credentials 读取；不允许先写明文再补安全权限。真实 Windows ACL 和 POSIX 权限分别验证，不以 Mock 或 Windows chmod 冒充实际保护。
5. 保留已验收的默认模型保存、严格 JSON、配置只读、无凭据启动和既有凭据保护行为。

## 实现边界与方案

### 模型目录保存

在 ConfigStore 增加以下内部业务入口，不新增顶层导出：

```python
def update_provider(self, provider_id: str, changes: Mapping[str, object], *,
                    expected_value: Mapping[str, object] | None) -> None: ...

def delete_provider(self, provider_id: str, *,
                    expected_value: Mapping[str, object]) -> None: ...
```

- expected_value 是调用方此前读取的该条完整记录；None 表示预期不存在。锁内重读后比较完整目标记录，冲突用既有 ConfigConflictError，不能无提示覆盖。对缺失值与显式无效值做区分。
- changes 只更新所给条目字段，保留未提供字段；models 列表是显式整体替换值，不在本层实现远端目录合并。输入校验、保留 ID 前缀及有效类型与既有配置规则一致；文件中已有 providers 或目标结构不合法时拒绝写入，不把它当空目录。
- 使用已有 models.json.lock；config.json 的默认保存保留其现有目标比较语义。抽取模块内最小非凭据原子替换步骤供 config/models 共用，不能把凭据直接送入普通临时文件路径，不建立通用存储框架。
- 保留严格 parse_json 的重复键、大小、非有限数字及根对象检查；写入同样受限，不能成功写出下一次不能读取的文件。所有失败诊断不回显未信任输入或路径。

### 凭据存储

新增 `CredentialStore(data_root: Path | str)`，至少提供：

```python
def save_api_key(self, provider_id: str, api_key: str, *,
                 expected_record: Mapping[str, object] | None) -> None: ...

def delete(self, provider_id: str, *,
           expected_record: Mapping[str, object]) -> None: ...
```

- expected_record 来自既有受保护 auth 读取；None 表示预期不存在。锁内重读、比较目标完整记录、保留其他供应商和无关未知字段，更新目标 API Key 时保留其未知字段。不引入第二套普通凭据读入口或凭据快照到公共配置。
- 保存/删除共用固定 auth.json.lock（未来刷新复用相同归属锁，本卡不实现刷新）。重读 auth 必须经既有 read_credentials 与 parse_json；不能绕开 ACL 直接 read_bytes。无效 API Key、ID、认证类型或结构在写入前拒绝，不静默把其他认证类型改成 API Key。
- 新目录在写明文前具备所需实际权限；POSIX 新目录 0700、凭据文件 0600，拒绝链接/非普通文件及不安全可替换父目录。Windows 使用实际 Win32 安全描述符/ACL 创建并验证，不用 chmod 代替 ACL，不把现有不安全目录静默改权限后继续。
- 临时文件在受控目录内以安全权限创建，独占打开，限制链接/重解析点；先验证保护、再写入假/实际业务数据，flush/fsync 后验证临时文件可受保护读取，再原子替换；替换后经现有受保护入口复核。敏感内容不写到普通 mkstemp 后再设 ACL；只复用必要低层能力，不复制整套读取安全逻辑。
- 写入和替换前失败时旧 auth 字节保持不变，清理自身临时文件。替换已经提交但后验验证失败时如实报告已提交/保护未确认，不谎称旧记录仍在，不擅自回滚覆盖并发变化。
- 删除仅移除 auth 内目标记录并原子保存其余内容；不声称远端 Key 已撤销，不自行删除 models/config/会话。多文件完整连接业务编排由后续 C1 卡负责，本卡不增加跨文件事务、删除墓碑或配置版本。
