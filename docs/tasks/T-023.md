## 调研问题

每个问题回答现状，引用 `文件:行号`；凡是问「落点」的，给出一到两个可选方案和各自的代价，不替 master 选。

### A2：统一命令入口与 `/model`

1. TUI 现在怎么处理一次提交：从按键到提交普通消息经过哪些函数；Ask/Permission 模式怎么接管输入和底部区。斜杠命令的识别、候选列表和分派可以挂在哪里。
2. 底部区现有哪些组件可以复用做菜单（列表、选择、筛选）；要新增菜单组件的话放在哪个文件。
3. App 怎么装配和持有 Provider 连接；Runtime 怎么冻结每轮设置。在两轮 Run 之间更换连接，现有代码缺哪些接口。
4. A1 交付的配置入口：`config_service`、`config_store` 对外提供哪些函数和类型；会话选择保存在会话的哪个字段、哪个 wire 版本，由哪个接口更新。

### B：三类接口与历史续接

5. Provider 协议（`providers/base.py`）的请求、流式事件、错误和生命周期接口；`openai_compatible.py` 怎么把 Chat Completions 映射成这些事件。
6. `Message`、`ToolCall`、`TurnEntry`、`RunCheckpoint` 现在能否携带供应商专属的续接数据（例如 Responses 的 reasoning item、Messages 的 thinking signature）；如果不能，要加在哪一层，涉及哪些模块。
7. 会话 JSONL 的版本判断和升级代码在哪里，新增字段时现有的兼容读写怎么走。

### C1、C2：登录、目录与订阅

8. 现有的文件锁、原子写和凭据权限保护（`_file_lock.py`、`config_store.py`、`_credential_permissions.py`）能否直接用于写 `models.json` 和 `auth.json`；缺什么。
9. 遮蔽输入（输入 Key）、多选列表这类交互，现有 TUI 能不能支持；不能的话缺什么。
10. 现有运行依赖只有 `httpx`、`jsonschema`、`prompt-toolkit`、`rich`。本地回调服务器、浏览器打开用标准库是否够；ID token 签名验证没有现成依赖，列出可选的成熟库（名称、许可证），不安装。

### D：共享设置与重载

11. `reasoningEffort`、`permissionMode`、`reasoningDisplay` 现在从哪里读、在哪里生效；运行中修改需要排到下一轮时，现有代码有没有可以用的挂点。
