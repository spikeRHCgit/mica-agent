### 1. TUI 提交路径、Ask/Permission 与统一命令入口

**现状**：

- `MainBufferScreen.run()` 打开终端输入并挂上唯一读取回调；`_on_input_ready()` 调用 `Terminal.drain_keys()`，`_enqueue_keys()` 经 `normalize_key()` 将按键排入 `_queue`；`_loop()` 串行处理 key/event，再重绘。证据：`src/mica_agent/tui/main_buffer/screen.py:241`、`src/mica_agent/tui/main_buffer/screen.py:265`、`src/mica_agent/tui/main_buffer/screen.py:409`、`src/mica_agent/tui/main_buffer/screen.py:433`、`src/mica_agent/tui/main_buffer/terminal.py:515`、`src/mica_agent/tui/main_buffer/editor.py:68`。
- 普通输入走 `_handle_key()` → `_handle_composer_key()`；Enter 调 `_submit()`，从 editor 取完整 `submit_text()`，然后 `MainBufferRuntime.submit()` → `MicaApp.prepare_run()` → 创建消费任务 → `MicaApp.run(binding=...)`。只有 runtime 接受后才清草稿、追加 User 行并进入 running；拒绝保留草稿且不创建 User/Run。长粘贴显示摘要与真实提交内容不同，命令识别不能只看显示摘要。证据：`src/mica_agent/tui/main_buffer/screen.py:465`、`src/mica_agent/tui/main_buffer/screen.py:502`、`src/mica_agent/tui/main_buffer/screen.py:514`、`src/mica_agent/tui/main_buffer/screen.py:548`、`src/mica_agent/tui/main_buffer/editor.py:185`、`src/mica_agent/tui/main_buffer/runtime.py:75`、`src/mica_agent/tui/main_buffer/runtime.py:130`。
- `UserInputRequested`/`PermissionRequested` 建立 Ask/Permission 状态并互相清除；该模式先接管按键，`_handle_interaction_key()` 将回答交 runtime/broker，拒绝则保留交互；Esc 取消 Run，关闭面板后回到 running。底部 `_build_chrome()` 在这两种模式直接返回 panel，取代 composer/facts/status。证据：`src/mica_agent/tui/main_buffer/screen.py:475`、`src/mica_agent/tui/main_buffer/screen.py:554`、`src/mica_agent/tui/main_buffer/screen.py:573`、`src/mica_agent/tui/main_buffer/screen.py:659`、`src/mica_agent/tui/main_buffer/screen.py:946`。
- **未找到**斜杠命令登记、候选或分派实现；查过 `screen.py`、`editor.py`、`interactions.py`、`runtime.py`、`cli.py`，并在 `src/`、`tests/` 搜索 `/model`、`/login`、`/settings`、`/reload`、`command_registry`。现有 `_handle_key()` 在 running 分支直接返回，composer 渲染也仅 idle 启用，因此只在 `_submit()` 添加命令处理会使「忙时可编辑命令草稿并提醒」仍不可达。证据：`src/mica_agent/tui/main_buffer/screen.py:482`、`src/mica_agent/tui/main_buffer/screen.py:981`。

**候选落点**：

1. 在 `screen.py` 的既有按键/提交入口增加单一命令登记和匹配函数，编辑后派生候选，Enter 在普通 Run 提交前统一判断命令及真实空闲状态；候选导航仍由 `_handle_composer_key()` 协调，展示接 `_build_chrome()`。代价：文件职责仍集中，但菜单增多后编排体量增加；必须调整 running 输入门禁并保持 Ask/Permission 优先，不能仅补一个提交函数。
2. 拟新增 `tui/main_buffer/commands.py`（现不存在）承接小型固定登记、识别、可用性和分派；screen 保持唯一按键入口，并调用同一登记派生候选。代价：多一个内部接口，需明确命令执行结果与异步菜单生命周期；不能发展成插件框架或第二个 Run 状态所有者。

两种方案都可复用注入时钟与受控刷新，做忙时短暂提醒（`src/mica_agent/tui/main_buffer/screen.py:125`、`src/mica_agent/tui/main_buffer/screen.py:899`）；取消后的空闲必须以消费任务及 App 预留释放为准，见第 3、11 条。

### 3. App 连接所有权、Runtime 冻结与连接切换缺口

**现状**：

- Provider 创建目前在 CLI：从解析后的 connection 取 URL/Key 调 factory，随后把 provider、model、ConfigService、ConnectionBinding、启动设置交给 `MicaApp`；默认 factory 只创建 `OpenAICompatibleProvider`。证据：`src/mica_agent/cli.py:450`、`src/mica_agent/cli.py:462`、`src/mica_agent/cli.py:919`。
- App 持有 `_provider`、`_model`、`_connection`、`_config_service`、`_settings`、`_engine`；系统提示词与 AGENTS 固定为 `_header_messages`。Provider 关闭归 App 的 `aclose()`，有界关闭且记录无法确认的清理失败；Runtime 的关闭最终调用 App，而非直接拥有 Provider。证据：`src/mica_agent/app.py:151`、`src/mica_agent/app.py:155`、`src/mica_agent/app.py:165`、`src/mica_agent/app.py:191`、`src/mica_agent/app.py:316`、`src/mica_agent/tui/main_buffer/runtime.py:201`。
- 冻结由 **App** 的 `prepare_run()` 完成，Runtime 在创建 task 前同步取得 `RunBinding` 并持有它。Binding 为不可变 dataclass，固定 engine（其中持有 Provider）、model、预算、映射、有效思考、设置、工具与能力；配置路径每次 `for_run()` 重读，权限 executor 也绑定本轮策略。证据：`src/mica_agent/app.py:73`、`src/mica_agent/app.py:250`、`src/mica_agent/app.py:269`、`src/mica_agent/app.py:292`、`src/mica_agent/tui/main_buffer/runtime.py:88`、`src/mica_agent/tool_executor.py:113`。
- `_reservation` 是 App 忙状态依据；App 的 run-finally 与 Runtime 的 task-release 收口，`wait_idle()` 等消费完成。screen 收到终态会先显示 idle，不能只用该显示状态决定允许切换。证据：`src/mica_agent/app.py:247`、`src/mica_agent/app.py:459`、`src/mica_agent/tui/main_buffer/runtime.py:163`、`src/mica_agent/tui/main_buffer/runtime.py:171`、`src/mica_agent/tui/main_buffer/screen.py:860`。
- **未找到**空闲准备候选连接、安装连接、切换并保存选择、独立关闭旧 Provider 的业务接口；查过 App/CLI/ConfigService/SessionService/Runtime 的完整方法入口，并搜索 `switch_connection`、`install_connection`、`update_selection`。`for_run()` 遇到保存连接 URL 或 Key 与当前不同会要求重启，尚不能重装；配置虽认识三种协议，只有 completions 进入可用连接表。证据：`src/mica_agent/config_service.py:459`、`src/mica_agent/config_service.py:354`。

**候选落点**：

1. 扩充 `MicaApp` 的空闲配置协调接口，并将 CLI factory 装配接缝交给 App 使用。动作顺序为校验目标/历史、准备候选、调用会话选择保存、安装选择与能力、更新安全事实、关闭旧连接；准备或保存失败关闭候选。代价：App 增加连接切换职责和 factory 注入，必须区分保存失败与安装后清理失败，保留冻结 header 与原会话。
2. 拟新增应用层连接协调模块（例如 `connection_service.py`，现不存在），供 CLI 与 App 共用解析/准备能力，App 仍负责安装、预留门禁与最终资源关闭。代价：职责拆分较细，但新增内部接口和候选资源移交约定；协调对象不能与 App 各自维护当前 Provider 或第二份忙状态。

两者都缺历史容量估计/确认和跨渠道告知接缝，现有 `prepare_run()` 的显式上下文预算检查仅校验预算大小关系，不是历史 token 容量检查（`src/mica_agent/config_service.py:474`）。

### 8. 锁、原子写与凭据权限能否用于 models/auth

**现状与结论**：
