## 契约与约束

### 1. 明确语言边界，先分类再修整

- 用户最新要求为 tests/ 中文、src/ 英文；旧任务中的“测试注释使用英文”不再适用。
- Master 只读扫描：51 文件，519 条 COMMENT token，其中 278 条含中文；153 个正式 docstring，
  其中 138 个含中文；非正式裸字符串 0。含中文不等于质量合格，纯 ASCII 也不一定是英文说明。
- 扫描中有 187 条匹配 noqa/type: ignore/pragma 的指令注释。指令与自然语言说明分别分类，
  不能把所有剩余纯 ASCII 注释算成待翻译 prose，也不能只靠“含中文”判定完成。
- 使用 tokenize 区分真实注释与样本字符串，使用 AST 只识别模块/类/函数/方法 body 首节点的正式
  docstring。不把三引号包裹的协议样本、测试脚本或普通裸字符串当成说明翻译。
- 标识符、异常名、协议名、路径、命令、技术术语与示例表达式保持原始形式；自然语言说明用中文，
  不追求消灭所有英文字母。无法自行判断是否为运行数据时，保持原样并在交接中说明。

### 2. 翻译保持语义，不顺手重写测试

- 准确保留被测行为、前置条件、不变量、安全边界、取消与清理语义、兼容约束以及真实平台证据。
- 已有简洁中文保留；中英混杂的说明修整为清楚的中文。无价值的复述或施工噪声只在本次涉及的
  注释内精简，不补写不存在的设计原因，不增加大段教学、逐句代码翻译或成套新 docstring。
- 正式 docstring 只改内容，保留其所属符号和存在性，预期总数仍为 153；不得通过删除 docstring
  或注释掉测试绕过语言检查。删除纯噪声 `#` 注释须说明类别，保留原有必要约束。
- noqa、type: ignore、pragma 等机器指令的头部、参数、所附代码和相对作用位置必须保持不变；
  自然语言原因可以按中文要求重写，但不得加入新排除、过滤、skip、xfail 或改变指令范围。
- 所有普通字符串、断言消息、预期输出、脚本和测试数据保持原值；正式 docstring 是唯一允许
  改动的 AST 字符串节点。若测试确实依赖某个 docstring 的运行值，先报告，不擅自修改断言。
- 使用明确绑定当前 worktree 的编辑路径，保留既有文件编码和换行，不触及主工作区。
