## 做法与约束

### 第一关：编码前方案交回

根据现有实际调用链，在「进展与交接」提交以下五项，然后停止，等待同卡审查：

1. **字段和类型**：三份全局 JSON、工作区 JSON 的最小有效样本（仅虚构凭据）、对应 Python 类型和校验/安全诊断；区分缺失、未知、非法值、损坏与不可用连接。不加配置 `version`，不提前定义未确认 OAuth 私有字段。
2. **来源与装配**：CLI 显式值/默认值、恢复选择、环境临时连接、工作区/全局默认的实际合并位置；配置入口、App、Runtime 和 Provider 各自拥有的状态/资源；无连接启动及直接/plain 入口的调用链。
3. **切换失败路径**：校验、上下文检查、准备候选、保存选择、安装新连接、关闭旧资源的顺序；候选失败、原子保存失败、旧客户端关闭失败、取消未收口时的处理。
4. **选择 wire**：精确版本、字段、校验、真实 v1～v4 读取及首次业务写入升级；继续/恢复/分支/清空/回退对选择的处理。不改 Turn/checkpoint 事实，不给 B 预塞未定义续接占位。
5. **实现落点与证据**：逐文件新增/修改清单、最小内部接口及公共面影响、已有测试保护与必要新增场景、物理输入/重绘验收办法；说明不同接口暂不可执行及 `/login` 尚未交付时如何诚实提示。

已有规格不重新投票；发现不能满足既定规则时列出证据、影响和备选方案，不自行降低保证。

### 第二关：审查通过后完成 A

- **单一事实源**：配置统一读取/校验，凭据不进入普通快照；能力默认标明来源，当前选择与全局默认分别保存；有效设置不从历史会话倒灌。
- **安全保存**：复用锁内重读、目标项修改和原子替换；保留无关/未知字段，损坏文件不覆盖。Windows 凭据保护验证实际 ACL，不以 chmod 冒充；测试只用隔离临时目录和虚构 Key。
- **兼容不造假**：只装配已有 Chat Completions 路径；其他接口不冒充可用，不隐藏发送连接测试。旧会话只读字节不变，失效选择保留引用并提示，不静默换模型或跨供应商套用 Key。
- **装配不分叉**：App 拥有连接和关闭，Runtime 仍是唯一 Run 消费者，菜单不操作业务私有状态；新 Run 冻结开始时设置。无配置普通提交不创建 Run、Turn 或 checkpoint，并保留可编辑输入。
- **菜单用现有输入链**：落实 `/model` 的筛选、导航、Enter/Ctrl+S/Esc 和忙时提示；恢复草稿/物理光标，不抢 Ask/Permission 输入。只为 A 的真实需求调整输入路径，不借机实现其他菜单。
- **测试克制**：优先加强既有行为资产；新增配置与选择测试按稳定行为命名，避免逐函数重复。代码注释英文、测试说明中文；不带施工历史标签。
