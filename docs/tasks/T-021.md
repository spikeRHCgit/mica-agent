#### 1. 字段和类型

四份 JSON 的职责与 `docs/configuration_spec.md` §2 一致；A 只读取/校验/合并/安全保存，不实现 `/login`、`/settings`、`/reload` 的写入流程。

**1.1 `~/.mica/config.json`（全局设置）最小有效样本**

```json
{
  "defaultModel": {"provider": "deepseek", "model": "deepseek-chat"},
  "reasoningEffort": "medium",
  "permissionMode": "default",
  "reasoningDisplay": "collapsed"
}
```

**1.2 `~/.mica/models.json`（模型目录）最小有效样本**

```json
{
  "providers": {
    "deepseek": {
      "name": "DeepSeek",
      "channel": "deepseek",
      "enabled": true,
      "baseUrl": "https://api.deepseek.com/v1",
      "api": "openai-completions",
      "models": [
        {
          "id": "deepseek-chat",
          "name": "DeepSeek Chat",
          "api": "openai-completions",
          "contextWindow": 128000,
          "maxTokens": 8192,
          "input": ["text"],
          "reasoning": false,
          "thinkingLevelMap": {}
        }
      ]
    }
  }
}
```

**1.3 `~/.mica/auth.json`（凭据）最小有效样本（虚构）**

```json
{
  "providers": {
    "deepseek": {"type": "api_key", "apiKey": "sk-fictional-not-a-real-key"}
  }
}
```

A 只认 `type: "api_key"`。OAuth 私有字段按卡片要求**不在此轮定义**；未知 `type`（例如将来 C 的订阅记录）按“该供应商凭据不可用”处理，其他供应商照常可用，且保存时原样保留该条目，不删不改。

**1.4 `<workspace>/.mica/config.json`（工作区设置）最小有效样本**

```json
{"reasoningEffort": "high"}
```

工作区文件与全局设置同形，只允许那三个设置项；**禁止任何凭据字段**。发现疑似凭据键（键名小写后包含 `key`/`token`/`secret`/`password`/`authorization`/`credential`）时提醒并忽略该项，不回显值。

**1.5 Python 类型（新增 `src/mica_agent/config_contracts.py`，风格对齐 `session_contracts.py`）**

- `ProviderChannel(Enum)`：`chatgpt-subscription` / `openrouter` / `deepseek` / `opencode-go` / `custom`。
- `ProviderApi(Enum)`：`openai-completions` / `openai-responses` / `anthropic-messages`（A 只装配第一种）。
- `ModelDefinition`（frozen/slots）：`model_id`、`name: str | None`、`api: ProviderApi | None`、`capabilities: ModelCapabilities`。
- `ModelCapabilities`（frozen/slots）：`context_window: int = 200_000`、`max_tokens: int | None = None`、`input: tuple[str, ...] = ("text",)`、`reasoning: bool = False`、`thinking_level_map: Mapping[ReasoningEffort, str]`；并带逐字段来源标记，供界面明确标注默认值，不把未知能力伪装成发现结果。
- `ProviderDefinition`（frozen/slots）：`provider_id`、`name`、`channel`、`enabled`、`base_url: str | None`、`default_api`、`models`。
- `ModelSelection`（frozen/slots）：`provider_id`、`model_id`，两者都必须非空非空白。
- `GlobalSettings`（frozen/slots）：`default_model: ModelSelection | None`、`reasoning_effort: ReasoningEffort`、`permission_mode: PermissionMode`、`reasoning_display: ReasoningDisplayMode`。程序默认分别为 `None`、`OFF`、`DEFAULT`、`COLLAPSED`（沿用现有 `reasoning.py`、`permissions.py`、`tui/models.py` 三个枚举，不另造近义枚举）。
- `ConfigSource(Enum)`：`cli_explicit` / `session_selection` / `environment` / `workspace` / `global` / `program_default`。
- `Sourced[T]`（frozen/slots）：`value: T`、`source: ConfigSource`，用于把“值 + 来源”一起交给界面。
- `ConfigDiagnostic`（frozen/slots）：`kind: ConfigDiagnosticKind`（`missing` / `unreadable` / `root_shape` / `syntax` / `unknown_key` / `invalid_value` / `credential_in_workspace` / `unavailable_connection`）、`file: str`（只放安全相对标签，如 `~/.mica/config.json`、`./.mica/config.json`）、`detail: str`（固定安全文案，不含原文、绝对用户路径、凭据）。
- `ResolvedConfiguration`（frozen/slots）：`models`、`settings: dict[str, Sourced]`、`selection: Sourced[ModelSelection] | None`、`connection: ResolvedConnection | None`、`diagnostics`。**不含任何凭据明文**，可安全进入日志/界面快照。
- `ResolvedConnection`（frozen/slots，`repr=False`）：`provider_id`、`base_url`、`api: ProviderApi`、`display_name`；**不持有密钥**。
- 凭据只经 `CredentialHandle`（私有，`api_key` 字段 `repr=False`，自定义 `__repr__` 不泄露）在装配瞬间交给 `ProviderFactory`，不进入 `ResolvedConfiguration`、会话、日志或界面。

**1.6 校验与诊断分类（对应 §3）**

| 情形 | 处理 |
|---|---|
| 文件缺失 | 视为未配置，不报错 |
| 根结构不是 JSON 对象 | `root_shape` 错误，阻止开始会话 |
| JSON 语法损坏 / 非法 UTF-8 / 非法常量 | `syntax` 错误，报错并阻止开始会话；**不把整份错误文件当空配置继续**，也不自动覆盖 |
| 无法读取（权限/IO） | `unreadable` 错误，给出安全、可操作诊断 |
| 未知键 | `unknown_key` 提醒后忽略，其他合法字段继续加载 |
| 已知键存在但值非法 | `invalid_value` 提醒并对**该项**使用程序默认，**不**回落低来源掩盖错误 |
| 键缺失 | 继承低来源（工作区→全局→程序默认） |
| 连接必需字段无安全默认 | `unavailable_connection`：该连接不可用，其他合法连接仍可用 |
| 工作区文件出现疑似凭据 | `credential_in_workspace` 提醒并忽略该项，不回显值 |

**1.7 保存规则（复用现有锁与原子替换）**

保存走“锁内重读最新文件 → 只改目标项 → 保留无关/未知字段 → 临时文件原子替换”（对齐 `jsonl_store._write_snapshot` 的 `mkstemp`+`fsync`+`os.replace`，锁复用 `_file_lock.locked_file`）。**不新建通用事务框架**。目标项之外的键、其他供应商条目、未知键原样保留；损坏文件不自动覆盖，写失败保留原字节。

#### 2. 来源与装配

**2.1 现状调用链（只读核对结论）**

- `main()` → `_main_cli(session_mode, permission_mode, plain)` → `_load_config()`（只读 `MICA_API_URL/MICA_API_KEY/MICA_MODEL`，任一缺失则打印诊断并返回 `2`）→ `run_interactive(api_url, api_key, model, ...)` → `_assemble_session` → `_select_session` → `_run_selected_session`。
- `_run_selected_session` 用 `factory(api_url, api_key)` 建 `Provider`，再建 `MicaApp(provider=..., model=..., tool_executor=PolicyEngine(permission_mode))`；`plain=True` 走 `_interact`，否则 `_run_main_buffer` 建 `MainBufferScreen`。
- 所有权现状：`MicaApp.aclose()` 关闭 provider（幂等）；`MainBufferRuntime._close()` 调 `app.aclose()`；`_run_main_buffer` 在 screen 未收敛时兜底关 app。Runtime 是唯一 Run 消费者（`_active` 单实例）。
- `ProviderFactory = Callable[[str, str], Provider]`；`_default_provider_factory(api_url, api_key)` → `OpenAICompatibleProvider(api_key=..., base_url=api_url)`（只支持 Chat Completions 路径）。
- `MainBufferRuntime.submit(prompt)` 调 `app.run(prompt, cancellation=token)`，**没有**传 `reasoning_effort`（默认 `OFF`）。
- 会话无选择字段；`SessionMeta` 无 `provider/model`；`SessionService` 无 selection 操作。

**2.2 配置入口与合并位置**

新增单一配置入口 `ConfigService`（`src/mica_agent/config_service.py`），在 `_main_cli` 内按 `default_data_root()` + `resolve_workspace(cwd)` 构造一次；`run_interactive` 接受可选 `config_service`，二者只读同一解析结果，不在别处另读环境变量或 JSON。

**2.3 来源优先级（严格对齐 §3）**

1. 会话内明确 `/model` 选择（当前进程内已切换值）——最高；
2. 启动时显式 CLI 选择（新增 `--provider` + `--model`，两者同时给出才算显式）；
3. 本会话保存的恢复记录（v5 `session_meta` 选择）；
4. 环境临时连接（`MICA_API_URL/MICA_API_KEY/MICA_MODEL`，三者齐全才算）——**该连接不写文件**；
5. 工作区默认（`<workspace>/.mica/config.json` 的 `defaultModel`）；
6. 全局默认（`~/.mica/config.json` 的 `defaultModel`）；
7. 都不存在 → 保持未配置。

工作区/全局的 `reasoningEffort`、`permissionMode`、`reasoningDisplay` 合并规则：未显式覆盖时工作区高于全局和程序默认；`--permission-mode` 用 argparse `default=None` 区分“用户显式传入”与“默认值”，未显式时由合并结果决定。

**2.4 各层拥有的状态/资源**

| 层 | 拥有 |
|---|---|
| `ConfigService` | 四份文件的读取/校验/合并/来源/安全诊断；目标项安全保存（默认模型）；凭据句柄的构建；不持有 provider、不发起网络 |
| `MicaApp` | 当前 provider、当前模型、连接生命周期（装配/替换/关闭）；Run 唯一性仍归 Engine/Runtime |
| `MainBufferRuntime` | 唯一 Run 任务与取消令牌；在 submit 时**冻结**该 Run 的思考强度设置 |
| `MainBufferScreen` | 终端、渲染器、编辑器、菜单与交互模式；只调用 App 的公开方法，不碰 App/Broker/Store 私有字段 |
| `Provider` | 自身 HTTP 客户端与协议适配，`aclose()` 幂等 |

**2.5 无连接启动与直接/plain 入口**

- 默认 TUI：没有可用连接时不再 `return 2`，而是进入未配置状态：照常渲染启动首屏；就绪区显示固定提示，说明尚无可用模型以及可用的配置方式。
- 未配置时提交普通消息：只给提醒、**保留可编辑草稿**，不创建 User/Turn/checkpoint/Run（`MainBufferRuntime.submit` 在无连接时直接拒绝，`_submit` 检测到拒绝后不清空编辑器）。
- `/model` 入口在未配置时同样可打开，只读本地目录，提示尚无可选连接。
- `--plain`：使用同一配置入口；无法配置时输出固定文字诊断并 `return 2`，不强行开 TUI 菜单（保持现有 plain 语义）。
- 直接 `run_interactive(api_url, api_key, model, ...)` 显式连接入口保持可用：三个位置参数非空白时构成“显式直连”，优先级等同 CLI 显式选择。
- `ProviderFactory` 形状**不变**（`Callable[[str, str], Provider]`）：配置解析出的连接与原直连都走同一个 factory 与同一条装配路径，避免“装配不分叉”被破坏，也避免大规模改测试替身。

**2.6 诚实提示边界**

- A 只装配 `openai-completions`。目录中声明 `openai-responses` / `anthropic-messages` 的连接标为“接口尚未在本版本交付”，不可选作当前模型，不伪装可用、不发送任何测试请求。
- `/login`、`/settings`、`/reload` 尚未交付：在未配置提示与命令识别处以固定文案说明“尚未交付”，不使用假成功事件、不创建假目录、不写任何占位配置。
- `/model` 只读本地保存目录，切换过程**不发送推理测试消息**。

#### 3. 切换失败路径

**3.1 顺序（空闲时执行，严格对齐 §4）**

触发点：空闲（`mode == "idle"` 且 App 无 active run）提交 `/model` 后，在菜单内 Enter 选中项。执行顺序：

1. **校验目标与历史**：目标 `ModelSelection` 必须在本地目录中存在、`enabled`、且其供应商有可用凭据（A 只接受 `api_key`）且 `api == openai-completions`。否则拒绝并给出固定安全原因，不建候选、不改状态。
2. **上下文检查**：若目标 `contextWindow` 为明确值且小于当前 `service.context_snapshot` 的估算占用，则先警告并要求确认；已知超限不悄悄删历史，确认也不代表能突破容量。容量为估计时明确标明估计；服务端真实超限照常报错。A 不实现压缩。
3. **准备候选**：用 `ProviderFactory` 建候选 provider。任何异常 → 关闭已建候选（已拿到对象时）→ 保留旧选择与旧连接，不写会话。
4. **保存会话选择**：`SessionService.update_selection(session_id, selection)` 锁内重读、只改选择、原子替换。失败 → 关闭候选 → 保留旧选择与旧连接，提示“选择未保存”；**不安装**。
5. **安装运行选择并更新事实区**：通过 App 公开方法替换当前 provider/model；更新 `TuiSessionSnapshot`（模型标识）并重绘事实区。此后的下一 Run 冻结新选择；当前若存在已开始的 Run 不可能（仅空闲可达）。
6. **收口旧连接**：`await old_provider.aclose()`。失败 → **单独报告**“旧连接未确认关闭”，不回滚、不声称目标未保存；同时保证旧连接不会被再次关闭（App 只保留新 provider）。

**3.2 失败与取消边界**

- 候选失败/保存失败：闭候选、保旧态。验证方式：注入 fail-close/fail-save 的替身，断言旧 provider 仍可服务下一次 Run、旧选择未变。
- 旧客户端关闭失败：新态生效、旧连接泄漏只报告；不重复关闭（`aclose` 幂等，断言调用次数）。
- 取消未收口：菜单只在空闲可达，而“空闲”定义沿用现有语义（`_active is None` 且终止事件已至）。取消中的 Run 不切换；`/model` 在运行中提交只给忙时提醒，不排队、不取消 Run、不送模型、不创建第二 Run。
- 关闭中（`runtime.is_closed`）：拒绝切换并拒绝新 Run。
- 保存失败不得领先于连接可用：反向地，安装前必先保存成功；若保存成功而安装后的重绘失败，仍以已保存的选择为准并重试重绘，不逆向回写。

**4.1 版本与字段**

```json

```

下表固定解析后的类型和缺失默认；工作区字段缺失先继承全局，表中默认用于最终缺失或存在但非法的项。JSON `null` 是非法值，不等同缺失；整数必须 `type(value) is int`，不接受 bool、浮点或数字字符串。重复 JSON 键直接拒绝整文件，避免读写产生不同解释。

| 字段 | 精确类型 / 缺失默认 / 非法处理 |
|---|---|
| `defaultModel` | 对象，已知必需键 `provider`、`model` 都为非空、非空白、无控制字符字符串；缺失最终 `None`，非法整项 `None`；合法但引用失效则保留引用、阻止新请求，不能回落另一个默认 |

#### R3 请求预算、能力与唯一冻结节点

撤销前轮“只给 Runtime 加 reasoning 参数”的方案。唯一计算并冻结节点是 App.prepare_run：调用 ConfigService 获取当前合法设置（下一 Run 重读共享设置，保留本进程显式覆盖），生成 RunBinding，包含 provider/model、模型能力及来源、输出预算、偏好/有效 reasoning、明确映射、permission mode 和绑定 Engine/executor。TUI/plain 只显示或消费同一结果，不在 UI 降档、不在 Provider 再算有效偏好。显示模式是界面设置，不进入持久化历史，也不影响请求必需内容。

- ProviderRequest 加 `max_tokens: int | None = None` 和 `thinking_level_map: Mapping[ReasoningEffort, str] | None = None`，校验正整数拒绝 bool，映射复制成只读；连接详情仍不进入 request。App 产出的 request 总给出实际预算和映射；`AgentEngine.run` 每次工具往返构造 current_request 时原样携带两者。
- Chat Completions `_build_payload` 输出 `max_tokens=4096`（直接低层 request 没有预算时的同一适配器默认）或 App 冻结的明确值；不无界请求，不发 Responses 的 max_output_tokens。4096 只保证本地有界，不承诺所有远端支持或有额度；服务端拒绝照常失败，无隐式请求重发或自动扩大。若明确 contextWindow <= 预算，prepare_run 拒绝并要求修正，不擅改手工预算。
- `reasoning=false`：有效 OFF、映射为空，不发送 reasoning_effort；保留用户偏好并固定文案解释。true + 非空合法映射：可用档位 OFF 加映射键；偏好不在映射则有效 OFF 并解释，不硬发旧档位。true + 缺失/空映射：复用并公开读取现有适配器经过测试的默认 minimal/low/medium/high/xhigh/max 同名映射（`openai_compatible.py` 当前常量），标适配器默认；OFF 总不发送参数。true 不证明远端兼容全部档位，远端错误保持真实失败。
- Provider 只编码冻结的有效 effort 到 request 映射，不再为 App 请求选择档位；低层直接 ProviderRequest 未给映射时维持现有 constructor thinking_level_map/default 行为，属于显式适配器入口兼容，不成为第二套配置解析。
- 双参数 ProviderFactory 可保留，因为模型预算/映射已真实进入 ProviderRequest，不被丢掉；默认 factory 和测试注入 factory 都只装配 HTTP 连接。适配器默认只定义一次，App/ConfigService 引用公开的不可变默认说明；不复制数字/映射到 UI。
- 权限：`ToolExecutor.bind_policy(mode)` 返回本次冻结策略的 executor 视图，内部共享 registry、InteractionBroker、policy_input_factory 和同一 output_routes（保证已注册 runtime_tools 的 output_reporter 仍通），只替换 PolicyEngine；App 用它构建本次 Engine，并向它回应交互。不改权限矩阵，不在进行中修改原策略；ToolExecutor 自己管理共享接缝，App 不访问私有字段。

验证落点：provider contract 拒绝 bool 预算；mock HTTP 检查真实 max_tokens/映射及 OFF 缺参；Engine 两次模型请求预算/映射一致；App 工具往返时共享文件变更不改变本 Run、下一 Run 采用新设置，权限/思考对 plain 与 TUI 一致。只扩充已有 Chat Completions 请求，不实现 B 的新协议或续接。

补全选择保留路径：`jsonl_store.py::append_turn`、`append_checkpoint`、`_as_current_snapshot` 的所有 SessionMeta 重建均保留 latest.meta.selection；用 dataclasses.replace 或显式 selection 参数，不能从 App 当前有效模型推导。SessionService.rename/rewind/clear 保留锁内 current.selection；branch 继承源快照 selection；create 默认 None。`update_selection` 仅调用既有 `store.update(session_id, transform)`，transform 在锁内基于最新 meta 修改 selection/updated_at，保留 entries 和其他 metadata，不做 load 后无锁 rewrite。serializer 每条写 v5；Store 拒绝混合版本、截断、重复键，原子失败保留原字节。

纠正前轮 §5.4：真实 v1/v2/v3 旧固定样本完全不改，包括 v3 字节样本版本；仅修改“业务写入升级结果”期望为 v5，并新增 v5 样本与上述 v4 checkpoint 固定样本。读旧数据前后比原始 bytes，升级后断言 Turn/checkpoint、工具事实及顺序等价。旧工具/失败/中断保护继续由既有契约资产覆盖，不用本轮无工具样本替代。

环境 provider ID：在配置入口对无 userinfo/query/fragment 的 URL 调用同一 `resolve_endpoint` 取得实际 Chat Completions endpoint，再按 httpx URL 规范化 scheme/host 大小写及默认 port，保留路径大小写/编码，不跨路径归并。哈希输入是固定 UTF-8 紧凑 JSON 数组 `["mica-env-v1","openai-completions",canonical_endpoint]`，provider_id = `mica-env:` + 完整 SHA-256 小写十六进制；model_id 单独保存环境 MICA_MODEL 原 ID。Key 不参与身份，也不写任何文件；哈希不是授权凭据，不证明远端身份或模型真可用。

#### R5 确认、真实空闲和资源收口

替代前轮 §3：跨 provider（包括环境/直连到目录）必须先显示“后续请求将把可用历史与指引发送到目标渠道”，要求明确确认，不误称只发新一句话。目标 contextWindow 小于当前值就提示确认，**不以估算已经超限为前提**；默认 200000 与明确值都展示来源，未知真实容量时标“默认估计”。无旧连接时展示目标容量与来源，不假造旧容量。两种提示合并一次确认，可 Esc 放弃，未确认不建候选、不写选择。

本地占用估算由 App.preview_selection 与 prepare_run 复用同一个函数：冻结 system/AGENTS、SessionService.context_snapshot（含 checkpoint 重编码）、待提交 prompt（预览菜单时尚无新 prompt）、工具 schema 与消息角色/工具调用 ID/参数 JSON 全部计入；以 UTF-8 字节数加固定结构余量估算，不引入 tokenizer。具体估算为 `ceil(total_utf8_bytes / 3) + 16 * message_count + 256`，加冻结输出预算；标明粗略估算而非测得 tokens，不能证明远端会接受。prepare_run 再计入真实新 prompt。

明确 contextWindow 与预算单独已冲突（预算 >= 容量）直接拒绝；粗估总量超明确容量时保守阻止本地新请求、告知“按本地估算超限”，不删历史、不压缩。确认可以完成切换，但不能解除该阻止；用户可另选容量或修正预算。使用默认容量时只报告估算风险，不声称服务端有这个硬限；远端真实超限仍正常失败。跨渠道普通历史与真实工具事实照既有编码发送，不执行历史工具、不继承未实现的思考续接。

真实空闲须同时满足 Runtime 消费 task 已完成并 release、App generator finally 已释放预留（含 checkpoint 提交）、没有 reconfigure/关闭操作。screen 的终态事件只能更新显示，不能授权切换；操作前调用公开 Runtime.wait_idle 并检查关闭/忙状态，不等活跃 Run 结束后自动排队执行命令。收到终态但 task 未 release 时仍按忙时处理，灰色提示后不排队。Ask/Permission 不抢交互输入。

保存/安装窗口：候选 provider、候选 Engine 和新不可变运行绑定全部在保存前准备好。最后检查关闭/确认/预期原选择后，同一事件循环同步执行 `SessionService.update_selection`（既有同步锁内原子操作）和绑定安装，中间**无 await、无用户回调、无可取消线程写入**；安装只做已验证绑定赋值，事实区快照由已安装绑定派生。文件替换失败保旧态；替换成功则安装后再进入下一 await。Ctrl+C/退出在保存前可放弃；保存中取消只能在该同步区间结束后处理，此时磁盘和运行态都是新选择，随后 App 关闭新资源。进程硬终止只能保证磁盘为完整旧/新文件；下次启动按磁盘恢复，不能承诺进程死亡后的内存状态。

重配操作由 App 拥有独立 task，外层用 shield 等其确定结果；外层取消不能放弃候选/关闭任务。App.request_shutdown 先置 closing 禁止新动作，再等待该操作跨过保存/安装边界后关闭安装资源；不启动第二个 Run。候选准备/保存失败、未保存取消都由 App 关闭候选；close 调用有单一记录，不把 CancelledError 当普通失败吞掉。

旧 provider 安装后转入 App 的 retired 资源列表，逐对象记录 close_task/status（pending/closed/failed）。最多发起一次 aclose，不丢引用、不盲重试；close 失败保留 failed 归属并返回固定安全告警“选择已保存，旧连接未确认关闭”。超过 2 秒的等待标 pending 并保留仍由 App 拥有的 task，不把超时当释放完成；后续切换受阻直到已在执行的清理结束，避免累积资源。当前已成功安装模型可使用，App 关闭时等已有 close_task，不重复调用失败对象；最终仍失败/未完成则明确返回未收口结果，真实终端退出报告，不能声称全部关闭。Runtime._close 不再把新增配置资源清理失败静默 pass，而将安全结果交给 screen/CLI；App 仍唯一 Provider 所有者。

渲染异常与资源异常分开：绑定安装成功后一次渲染失败报告“选择已生效，界面更新失败”，走既有 screen 关闭/错误边界；不重试重绘、不反向写回旧选择。资源关闭失败也不触发渲染或 aclose 重试。测试用 Event 阻塞真实 task/generator/保存前及关闭阶段，覆盖终态先到仍忙、退出在保存前/后、候选失败、保存失败、retired 关闭失败和延迟完成；检查磁盘/当前绑定/下一请求一致与单次关闭。

### 修订差异 R6：安全与精确拟范围

#### 凭据权限和诊断

A 只读取 auth，先验证保护再取凭据，不隐式修复用户 ACL、不提前提供认证编辑。新增内部 `_credential_permissions.py` 集中平台检查，标准库 ctypes 调 Win32 API，不加第三方包，也不调用 shell 拼接凭据/路径。

- Windows：以进程 token 取得当前用户 SID；对 auth 使用 Win32 文件 handle 查询 owner/DACL（GetSecurityInfo），检查当前用户的实际读取/写入权。必须为当前用户所有，DACL 非空且存在，不接受 NULL DACL。允许有数据读取/修改/删除/WRITE_DAC/WRITE_OWNER 的主体只限当前 SID、SYSTEM、Administrators；发现其他用户、Everyone、Users、Authenticated Users 等有效授权就拒绝取 Key，未知/无法解析 ACE 同样失败关闭。不以 chmod 或 icacls 文本的“看似成功”替代查询结果；拒绝 reparse point 和不支持的文件系统安全描述符。
- 读取与 ACL 检查使用同一已打开 handle，share 仅 READ，限制检查后替换/写入的竞争；通过该 handle 读取 bytes 后关闭。不用先 stat/ACL 后换路径再 open 读取。目录 ACL 同样核对 owner 与替换/创建子文件的授权，拒绝可被其他普通用户替换 auth 的父目录权限。Windows ACL 的当前用户/SYSTEM/Administrators 属受信本机管理边界，不承诺抵御管理员或当前用户自身恶意操作。
- POSIX：同一打开 fd 上 fstat 验 owner == 当前 UID、无 group/other 权限，拒绝符号链接；文件至少允许 owner 读。目录的其他用户写入同样失败关闭。不把这项结果推用于 Windows。
- 验证失败/权限不足/查询 API 失败：固定 `credential_permissions` 诊断，给“请保护认证文件和目录后重启”的操作方向，不带 SID/用户名/绝对路径/原始 OS 文案。该凭据不可用，其他安全凭据来源仍能独立工作；不自动换 provider，恢复选择仍保留。文件级 unreadable/syntax/root 错误按既定配置错误阻止开始会话。
- 原子替换**不自动保证 ACL**：未来 C 的 auth 写入须锁内重读，在已验证的私有目录先以受保护 DACL（当前用户 + SYSTEM + Administrators）创建空临时文件，查询确认后才写凭据，fsync 后替换，查询新目标 owner/DACL 再声明保存完成；临时/lock 文件及目录同样保护。权限设置失败在替换前清理候选、保留旧 auth 字节；替换后查询失败报告“数据已替换但保护未确认”，禁用该凭据并要求处理，不假称原文件未改变。A 不实现这条 C 写入 API，配置默认保存临时文件不含凭据；原始 config/models 若出现凭据未知字段不进入打印快照。
- Windows 自动化须在隔离临时用户目录查询真实 owner/DACL，用 Win32 API 给虚构 auth 增加 Everyone READ 后证明拒绝、收紧后证明读取；模拟 API failure 另证失败关闭。未来 C 实际替换后的 ACL 验收不得由本轮方案或 mock 自批。本轮只交方案，未做真实 ACL 实验。

安全快照修正：前轮 ResolvedConfiguration 不再携带 connection URL；只含安全标签、选择、来源、状态和诊断。URL/credential 属 App 装配私有对象，repr 固定 redacted；ProviderRequest 的新映射/预算不带秘密。OpenAICompatibleProvider.__repr__ 当前含 endpoint，拟改为不打印 endpoint（即使合法 URL 也不输出路径）。URL 校验拒绝 userinfo/query/fragment，不回显坏 URL；任何 HTTP/OS/JSON 异常对外只用固定类别/允许的数字 HTTP status，禁止 str(exc)/原异常 cause repr 进入配置告警、screen diagnostics 或日志。未知键、非法枚举、模型重复 ID 的错误不拼原键或值；必要显示名称走既有控制字符/敏感内容清洗，不显示 auth 条目原文。

### 实施限定（优先于前轮方案的不一致部分）
