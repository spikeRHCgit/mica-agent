#### 1. 字段和类型

四份 JSON 的职责与 `docs/configuration_spec.md` §2 一致；A 只读取/校验/合并/安全保存，不实现 `/login`、`/settings`、`/reload` 的写入流程。

**1.1 `~/.mica/config.json`（全局设置）最小有效样本**

```json
{
  "defaultModel": {"provider": "deepseek", "model": "deepseek-chat"},
  "reasoningEffort": "medium",
  "permissionMode": "default",
  "reasoningDisplay": "collapsed"
}
```

**1.2 `~/.mica/models.json`（模型目录）最小有效样本**

```json
{
  "providers": {
    "deepseek": {
      "name": "DeepSeek",
      "channel": "deepseek",
      "enabled": true,
      "baseUrl": "https://api.deepseek.com/v1",
      "api": "openai-completions",
      "models": [
        {
          "id": "deepseek-chat",
          "name": "DeepSeek Chat",
          "api": "openai-completions",
          "contextWindow": 128000,
          "maxTokens": 8192,
          "input": ["text"],
          "reasoning": false,
          "thinkingLevelMap": {}
        }
      ]
    }
  }
}
```

**1.3 `~/.mica/auth.json`（凭据）最小有效样本（虚构）**

```json
{
  "providers": {
    "deepseek": {"type": "api_key", "apiKey": "sk-fictional-not-a-real-key"}
  }
}
```

A 只认 `type: "api_key"`。OAuth 私有字段按卡片要求**不在此轮定义**；未知 `type`（例如将来 C 的订阅记录）按“该供应商凭据不可用”处理，其他供应商照常可用，且保存时原样保留该条目，不删不改。

**1.4 `<workspace>/.mica/config.json`（工作区设置）最小有效样本**

```json
{"reasoningEffort": "high"}
```

工作区文件与全局设置同形，只允许那三个设置项；**禁止任何凭据字段**。发现疑似凭据键（键名小写后包含 `key`/`token`/`secret`/`password`/`authorization`/`credential`）时提醒并忽略该项，不回显值。

**1.5 Python 类型（新增 `src/mica_agent/config_contracts.py`，风格对齐 `session_contracts.py`）**

- `ProviderChannel(Enum)`：`chatgpt-subscription` / `openrouter` / `deepseek` / `opencode-go` / `custom`。
- `ProviderApi(Enum)`：`openai-completions` / `openai-responses` / `anthropic-messages`（A 只装配第一种）。
- `ModelDefinition`（frozen/slots）：`model_id`、`name: str | None`、`api: ProviderApi | None`、`capabilities: ModelCapabilities`。
- `ModelCapabilities`（frozen/slots）：`context_window: int = 200_000`、`max_tokens: int | None = None`、`input: tuple[str, ...] = ("text",)`、`reasoning: bool = False`、`thinking_level_map: Mapping[ReasoningEffort, str]`；并带逐字段来源标记，供界面明确标注默认值，不把未知能力伪装成发现结果。
- `ProviderDefinition`（frozen/slots）：`provider_id`、`name`、`channel`、`enabled`、`base_url: str | None`、`default_api`、`models`。
- `ModelSelection`（frozen/slots）：`provider_id`、`model_id`，两者都必须非空非空白。
- `GlobalSettings`（frozen/slots）：`default_model: ModelSelection | None`、`reasoning_effort: ReasoningEffort`、`permission_mode: PermissionMode`、`reasoning_display: ReasoningDisplayMode`。程序默认分别为 `None`、`OFF`、`DEFAULT`、`COLLAPSED`（沿用现有 `reasoning.py`、`permissions.py`、`tui/models.py` 三个枚举，不另造近义枚举）。
- `ConfigSource(Enum)`：`cli_explicit` / `session_selection` / `environment` / `workspace` / `global` / `program_default`。
- `Sourced[T]`（frozen/slots）：`value: T`、`source: ConfigSource`，用于把“值 + 来源”一起交给界面。
- `ConfigDiagnostic`（frozen/slots）：`kind: ConfigDiagnosticKind`（`missing` / `unreadable` / `root_shape` / `syntax` / `unknown_key` / `invalid_value` / `credential_in_workspace` / `unavailable_connection`）、`file: str`（只放安全相对标签，如 `~/.mica/config.json`、`./.mica/config.json`）、`detail: str`（固定安全文案，不含原文、绝对用户路径、凭据）。
- `ResolvedConfiguration`（frozen/slots）：`models`、`settings: dict[str, Sourced]`、`selection: Sourced[ModelSelection] | None`、`connection: ResolvedConnection | None`、`diagnostics`。**不含任何凭据明文**，可安全进入日志/界面快照。
- `ResolvedConnection`（frozen/slots，`repr=False`）：`provider_id`、`base_url`、`api: ProviderApi`、`display_name`；**不持有密钥**。
- 凭据只经 `CredentialHandle`（私有，`api_key` 字段 `repr=False`，自定义 `__repr__` 不泄露）在装配瞬间交给 `ProviderFactory`，不进入 `ResolvedConfiguration`、会话、日志或界面。

**1.6 校验与诊断分类（对应 §3）**

| 情形 | 处理 |
|---|---|
| 文件缺失 | 视为未配置，不报错 |
| 根结构不是 JSON 对象 | `root_shape` 错误，阻止开始会话 |
| JSON 语法损坏 / 非法 UTF-8 / 非法常量 | `syntax` 错误，报错并阻止开始会话；**不把整份错误文件当空配置继续**，也不自动覆盖 |
| 无法读取（权限/IO） | `unreadable` 错误，给出安全、可操作诊断 |
| 未知键 | `unknown_key` 提醒后忽略，其他合法字段继续加载 |
| 已知键存在但值非法 | `invalid_value` 提醒并对**该项**使用程序默认，**不**回落低来源掩盖错误 |
| 键缺失 | 继承低来源（工作区→全局→程序默认） |
| 连接必需字段无安全默认 | `unavailable_connection`：该连接不可用，其他合法连接仍可用 |
| 工作区文件出现疑似凭据 | `credential_in_workspace` 提醒并忽略该项，不回显值 |

**1.7 保存规则（复用现有锁与原子替换）**

保存走“锁内重读最新文件 → 只改目标项 → 保留无关/未知字段 → 临时文件原子替换”（对齐 `jsonl_store._write_snapshot` 的 `mkstemp`+`fsync`+`os.replace`，锁复用 `_file_lock.locked_file`）。**不新建通用事务框架**。目标项之外的键、其他供应商条目、未知键原样保留；损坏文件不自动覆盖，写失败保留原字节。

#### 2. 来源与装配

**2.1 现状调用链（只读核对结论）**

- `main()` → `_main_cli(session_mode, permission_mode, plain)` → `_load_config()`（只读 `MICA_API_URL/MICA_API_KEY/MICA_MODEL`，任一缺失则打印诊断并返回 `2`）→ `run_interactive(api_url, api_key, model, ...)` → `_assemble_session` → `_select_session` → `_run_selected_session`。
- `_run_selected_session` 用 `factory(api_url, api_key)` 建 `Provider`，再建 `MicaApp(provider=..., model=..., tool_executor=PolicyEngine(permission_mode))`；`plain=True` 走 `_interact`，否则 `_run_main_buffer` 建 `MainBufferScreen`。
- 所有权现状：`MicaApp.aclose()` 关闭 provider（幂等）；`MainBufferRuntime._close()` 调 `app.aclose()`；`_run_main_buffer` 在 screen 未收敛时兜底关 app。Runtime 是唯一 Run 消费者（`_active` 单实例）。
- `ProviderFactory = Callable[[str, str], Provider]`；`_default_provider_factory(api_url, api_key)` → `OpenAICompatibleProvider(api_key=..., base_url=api_url)`（只支持 Chat Completions 路径）。
- `MainBufferRuntime.submit(prompt)` 调 `app.run(prompt, cancellation=token)`，**没有**传 `reasoning_effort`（默认 `OFF`）。
- 会话无选择字段；`SessionMeta` 无 `provider/model`；`SessionService` 无 selection 操作。

**2.2 配置入口与合并位置**

新增单一配置入口 `ConfigService`（`src/mica_agent/config_service.py`），在 `_main_cli` 内按 `default_data_root()` + `resolve_workspace(cwd)` 构造一次；`run_interactive` 接受可选 `config_service`，二者只读同一解析结果，不在别处另读环境变量或 JSON。

**2.3 来源优先级（严格对齐 §3）**

1. 会话内明确 `/model` 选择（当前进程内已切换值）——最高；
2. 启动时显式 CLI 选择（新增 `--provider` + `--model`，两者同时给出才算显式）；
3. 本会话保存的恢复记录（v5 `session_meta` 选择）；
4. 环境临时连接（`MICA_API_URL/MICA_API_KEY/MICA_MODEL`，三者齐全才算）——**该连接不写文件**；
5. 工作区默认（`<workspace>/.mica/config.json` 的 `defaultModel`）；
6. 全局默认（`~/.mica/config.json` 的 `defaultModel`）；
7. 都不存在 → 保持未配置。

工作区/全局的 `reasoningEffort`、`permissionMode`、`reasoningDisplay` 合并规则：未显式覆盖时工作区高于全局和程序默认；`--permission-mode` 用 argparse `default=None` 区分“用户显式传入”与“默认值”，未显式时由合并结果决定。

**2.4 各层拥有的状态/资源**

| 层 | 拥有 |
|---|---|
| `ConfigService` | 四份文件的读取/校验/合并/来源/安全诊断；目标项安全保存（默认模型）；凭据句柄的构建；不持有 provider、不发起网络 |
| `MicaApp` | 当前 provider、当前模型、连接生命周期（装配/替换/关闭）；Run 唯一性仍归 Engine/Runtime |
| `MainBufferRuntime` | 唯一 Run 任务与取消令牌；在 submit 时**冻结**该 Run 的思考强度设置 |
| `MainBufferScreen` | 终端、渲染器、编辑器、菜单与交互模式；只调用 App 的公开方法，不碰 App/Broker/Store 私有字段 |
| `Provider` | 自身 HTTP 客户端与协议适配，`aclose()` 幂等 |

**2.5 无连接启动与直接/plain 入口**

- 默认 TUI：没有可用连接时不再 `return 2`，而是进入未配置状态：照常渲染启动首屏；就绪区显示固定提示，说明尚无可用模型以及可用的配置方式。
- 未配置时提交普通消息：只给提醒、**保留可编辑草稿**，不创建 User/Turn/checkpoint/Run（`MainBufferRuntime.submit` 在无连接时直接拒绝，`_submit` 检测到拒绝后不清空编辑器）。
- `/model` 入口在未配置时同样可打开，只读本地目录，提示尚无可选连接。
- `--plain`：使用同一配置入口；无法配置时输出固定文字诊断并 `return 2`，不强行开 TUI 菜单（保持现有 plain 语义）。
- 直接 `run_interactive(api_url, api_key, model, ...)` 显式连接入口保持可用：三个位置参数非空白时构成“显式直连”，优先级等同 CLI 显式选择。
- `ProviderFactory` 形状**不变**（`Callable[[str, str], Provider]`）：配置解析出的连接与原直连都走同一个 factory 与同一条装配路径，避免“装配不分叉”被破坏，也避免大规模改测试替身。

**2.6 诚实提示边界**

- A 只装配 `openai-completions`。目录中声明 `openai-responses` / `anthropic-messages` 的连接标为“接口尚未在本版本交付”，不可选作当前模型，不伪装可用、不发送任何测试请求。
- `/login`、`/settings`、`/reload` 尚未交付：在未配置提示与命令识别处以固定文案说明“尚未交付”，不使用假成功事件、不创建假目录、不写任何占位配置。
- `/model` 只读本地保存目录，切换过程**不发送推理测试消息**。

#### 3. 切换失败路径

**3.1 顺序（空闲时执行，严格对齐 §4）**

触发点：空闲（`mode == "idle"` 且 App 无 active run）提交 `/model` 后，在菜单内 Enter 选中项。执行顺序：

1. **校验目标与历史**：目标 `ModelSelection` 必须在本地目录中存在、`enabled`、且其供应商有可用凭据（A 只接受 `api_key`）且 `api == openai-completions`。否则拒绝并给出固定安全原因，不建候选、不改状态。
2. **上下文检查**：若目标 `contextWindow` 为明确值且小于当前 `service.context_snapshot` 的估算占用，则先警告并要求确认；已知超限不悄悄删历史，确认也不代表能突破容量。容量为估计时明确标明估计；服务端真实超限照常报错。A 不实现压缩。
3. **准备候选**：用 `ProviderFactory` 建候选 provider。任何异常 → 关闭已建候选（已拿到对象时）→ 保留旧选择与旧连接，不写会话。
4. **保存会话选择**：`SessionService.update_selection(session_id, selection)` 锁内重读、只改选择、原子替换。失败 → 关闭候选 → 保留旧选择与旧连接，提示“选择未保存”；**不安装**。
5. **安装运行选择并更新事实区**：通过 App 公开方法替换当前 provider/model；更新 `TuiSessionSnapshot`（模型标识）并重绘事实区。此后的下一 Run 冻结新选择；当前若存在已开始的 Run 不可能（仅空闲可达）。
6. **收口旧连接**：`await old_provider.aclose()`。失败 → **单独报告**“旧连接未确认关闭”，不回滚、不声称目标未保存；同时保证旧连接不会被再次关闭（App 只保留新 provider）。

**3.2 失败与取消边界**

- 候选失败/保存失败：闭候选、保旧态。验证方式：注入 fail-close/fail-save 的替身，断言旧 provider 仍可服务下一次 Run、旧选择未变。
- 旧客户端关闭失败：新态生效、旧连接泄漏只报告；不重复关闭（`aclose` 幂等，断言调用次数）。
- 取消未收口：菜单只在空闲可达，而“空闲”定义沿用现有语义（`_active is None` 且终止事件已至）。取消中的 Run 不切换；`/model` 在运行中提交只给忙时提醒，不排队、不取消 Run、不送模型、不创建第二 Run。
- 关闭中（`runtime.is_closed`）：拒绝切换并拒绝新 Run。
- 保存失败不得领先于连接可用：反向地，安装前必先保存成功；若保存成功而安装后的重绘失败，仍以已保存的选择为准并重试重绘，不逆向回写。

#### 4. 选择 wire

**4.1 版本与字段**

- `CURRENT_SESSION_FORMAT_VERSION`：`4` → `5`；`_SUPPORTED_SESSION_FORMAT_VERSIONS` = `{1,2,3,4,5}`。

| 元数据重写 `rename_session` | 保留选择 |

| 回退 `rewind_session` | 保留选择，不擅改模型 |
| 删除 | 无额外处理 |

环境临时连接的恢复：只有当本次进程实际提供了与之匹配的 `(base_url, model)` 时才认这个选择；否则重选，**不把 Key 写会话**。

**4.4 不做的事**
