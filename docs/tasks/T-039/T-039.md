## 目标概览

将 T-037 的存储和 T-038 的目录接成可被后续 `/login` 调用的业务：安全列出连接、添加 API Key 连接、改名/改 Key/启停/确认删除、自定义地址与接口维护，以及目录刷新、勾选保存和手填模型。多文件失败如实报告已完成与未完成范围，迟到结果不覆盖新凭据或重建删除记录。

本卡交产品实现，不做泛泛调研。改动集中于配置与选择模块；通过后接应用/终端菜单及其真实验收，不把内部业务通过说成 `/login` 已可用。

## 现状与实现边界

现有 ConfigService 是配置读取/解析与选择入口；ConfigStore/CredentialStore 分别执行目标 CAS 和原子写入；model_catalog 已负责网络、解析和模型合并，但没有跨文件连接业务。不能把这些编排散到 UI，也不建立第二套配置缓存、事务框架或身份格式。

采用 ConfigService 提供一个**内部**维护入口、委托 `_connection_maintenance.py` 的单一实现。该 helper 只处理连接维护，不反向导入 ConfigService；原有 load/resolve/for_run、公共配置快照和顶层导出不变。可在 ConfigService 通过延迟导入的 `_connection_maintenance()` 构造 helper，复用同一 ConfigStore；不另找 HOME/环境变量或配置根。

## 内部入口与状态归属

提供等价的维护对象与动作，具体辅助命名可按现有代码选择：

- 安全连接列表；开始编辑并捕获完整 models/auth 目标基线。
- 创建连接；更新显示名、enabled、自定义 URL/API 或 API Key；确认删除。
- 使用编辑基线发现目录；保存该结果的显式勾选；保存显式手填模型。

列表/操作结果只含安全名称、稳定 ID、渠道、enabled、凭据可用状态、固定结果类别和必要提示。原始 Key 不返回给列表或公共快照，不进入异常、repr、日志；供 CAS 使用的原始目标基线仅存在于短生命周期、repr 隐藏的内部编辑句柄中，与展示值分开，不暴露可随意修改的原始字典。自定义 URL 供编辑使用的运行期值同样不进入 repr/诊断。不要建立全局句柄表或长期凭据缓存。

文件读写仍只经 ConfigStore/CredentialStore；auth 读取必须走 ConfigStore.read("auth") 的受保护入口。复用既有纯校验规则；本卡明确允许 helper 复用 config_store 的 `_validate_provider_record`、credential_store 的 `_api_key` 作为内部纯校验，不复制另一套规则、不修改底层语义。读取坏 JSON、无效 providers/目标结构或保护失败时明确拒绝，不把无效值当缺失重建。

## 具体行为

### 1. 添加与编辑

- 新连接由业务生成稳定且不含名称/路径的 ID（如 UUID），同名连接合法；不使用名称作为 ID，不复用删除过的 ID。内置渠道取 T-038 固定表对应默认值；自定义显式填写名称、URL、Key、三种已有 API 之一。
- 内置 DeepSeek/OpenRouter 默认 Completions；Go 连接默认值可用已核实的 OpenAI 协议族基址，逐模型 API 仍必须明确选择。不得用名称推断 API，不声称一个 Go 协议族 URL 通用于其他族；按 API 选 Go 推理地址和发送自有头留给后续应用装配，本卡不改 Provider。
- 预检本次输入及将保存的完整供应商记录后，再安全保存凭据，最后保存 models 记录。初始可无模型，但不能把这种状态叫可推理；只有所需记录均已有效保存才能报告本地连接完整。
- 改名保持 ID；禁用/启用保留模型及凭据；自定义可改 URL/API，内置不接受任意地址覆盖。完整目标 CAS 不得悄悄覆盖另一窗口编辑。只改变所请求字段，不改默认、会话或运行连接。
- 更换 Key 前验证输入；受保护原子替换未提交前旧记录保持。不自动发推理请求验证 Key，也不把公开 Go 目录或本地保存当远端认证成功。遇到目录拒绝保留已保存连接，允许继续手填。
- 不把其他认证类型改写成 api_key；订阅登录/刷新归 C2，不实现或消费其他客户端凭据。

### 2. 目录、选择与手填

- 目录 wrapper 使用业务内部受保护读取的目标 Key 和显式连接事实，调用 T-038 discover；只在调用时接收 CancellationToken、可选 transport、自定义运行期 catalog URL、调用方稳定会话 ID。不读其他环境或真实身份，不复制 HTTP client/解析/取消循环。
- 发现前取得 models/auth 基线，网络等待不持任何存储锁。发现结果绑定这次编辑基线，不让调用方把一条连接的结果误用于另一条连接。
- 保存目录选择仍调用 T-038 save_selection；除 models 的完整记录 CAS 外，须拒绝发现期间目标 auth 已更换/删除的过期结果。可在此**同步保存**路径短暂持有既有 auth.json.lock，受保护重读比较后调用 models CAS；此路径不调用 CredentialStore，避免递归取得同一非重入锁。不得在网络 await 中持锁；不得新增反向锁序或通用事务。
- 刷新保留手填字段、未知字段、已有勾选及仍选中的远端缺席模型，显式取消才移除；Go 新项无有效 api_choices 仍拒绝。失败/空/需手填与不完整沿用既有状态，不能失败后清空旧目录。
- 手填是独立、明确的用户操作，不把失败 CatalogResult 伪造成成功。手填 ID/API/明确能力经已有校验后整体保存；未知能力留缺失，不能写程序默认值冒充发现。只改 models，保留无关供应商、根字段、默认和凭据。

### 3. 删除与多文件失败

- 删除必须获得显式确认；无确认不写任何文件。先以完整基线删除 models 连接，使其不再可选，再以 auth 完整目标基线删除其凭据。原本没有凭据时不构造虚假删除目标，不删除其他记录或文件。
- 第一文件提交后第二文件失败时明确报告部分完成及残留范围，不声称整体成功或整体回滚。新增连接凭据成功而 models 失败时同理；不自动回滚覆盖后来的并发写入。
- CredentialStore 已替换但保护未确认的安全错误必须保留其真实含义；无法可靠确认某步是否提交时明确“未确认”，不能凭异常猜测旧记录仍在。不为分类错误文本而改底层异常契约或增加持久化标记。
- 并发改 Key、禁用、删除或保存模型后，过期编辑操作应冲突；若操作已经部分提交再遇冲突，报告已提交范围而非假称全未执行。逐文件原子/CAS 不是跨文件事务，不承诺进程崩溃后的自动回滚。
- 删除不删历史、不自动切供应商、不改默认、不声称远端撤销；迟到目录不能重建已删除连接。当前/默认/恢复引用的运行阻止与提示由现有读取/for_run 及后续 App/TUI 接入，不在本卡重写。

同步本地保存与异步目录分开归属：不要把已提交磁盘变更说成可被 token 撤销。目录取消沿用 CancellationRequested / 外部 CancelledError；后续菜单负责后台执行同步磁盘操作、等待收口及丢弃迟到展示，本卡不自行建立菜单任务或 Agent Run。
