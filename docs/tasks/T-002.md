## 契约与约束

- 本任务只处理 `#` 注释和模块、类、函数或方法的 docstring。界面文本、状态文案、错误消息、日志、
  ANSI 片段、提示词、协议值、测试样本和其他运行时字符串不是注释，不得机械翻译或改写。
- 所有保留的源码注释和 docstring 使用简洁、准确的英文。允许删除无价值注释，不要求给每个私有函数
  补 docstring，也不得把现有中文逐字扩写成更长的英文。
- 删除阶段号、任务号、worker 名称、返工过程、临时结论、失效未来时、分区装饰线、复述代码的注释，
  以及没有背景和移除条件的 TODO/FIXME。
- 保留并准确表达终端 IO 唯一所有权、主缓冲区与 scrollback 约束、可信 ANSI 与不可信正文边界、物理行
  身份、流式与稳定渲染切换、输入模式所有权、Windows 输入后备、取消和资源清理等非显然语义。
- 模块与类 docstring 只概括角色和边界；公共类型、协议和入口在确有必要时说明输入输出、失败语义与关键
  限制；注释必须贴近其解释的最小范围。
- `noqa`、`type: ignore`、`pragma` 和覆盖率排除必须留在原本的精确位置；现有原因若为中文，只翻译原因，
  不改变指令、错误码或覆盖范围。
- 模块级或类级的裸字符串表达式不属于本任务允许修改的正式 docstring；它们会改变严格 AST 比较结果，
  若发现只记录并交给 master 判断，不得在本任务中改写。
- 不得修改标识符、导入、类型注解、装饰器、默认值、产品文本、异常文本、wire value、公共导出、控制流、
  表达式、数据结构或代码格式；发现真正的实现问题只记录，不在本任务修复。
- 不更新冻结中的 `docs/module_map.md`，不开始测试精简、非 TUI 源码返工或源码架构重构。

## 执行要求

1. 开始时只读记录 Git 分支、HEAD、上游和工作区；确认 `2c6b375` 是当前 HEAD 的祖先，且从该产品基线
   到任务起点没有修改 `src/mica_agent/tui/**`。若存在不明改动或写入范围与其他任务冲突，立即停下报告。
2. 用 Python `tokenize` 与 AST 分别识别注释和正式 docstring；不要用“搜索所有中文字符串”的结果替代
   注释审计，因为 TUI 中存在大量合法的中文产品文案。
3. 审计当前全部 TUI Python 文件，分文件完成清理，并保留一份“删除 / 重写 / 保留”的简短分类结果；
   不需要逐条记录翻译流水。
4. 对每个修改后的 Python 文件，将工作树版本与基线 `2c6b375` 中的同一路径解析为 AST，移除模块、类、
   函数和异步函数的正式 docstring 节点后，以 `ast.dump(..., include_attributes=False)` 比较；任何不等价
   都必须视为越界并恢复该实现改动。
5. 再用 token 与 AST 级扫描确认允许范围内没有中文注释或中文正式 docstring，也没有阶段号、任务号、
   worker/返工等施工历史；扫描只针对注释和正式 docstring，不扫描全部字符串字面量。
6. 不使用自动翻译器或无审查的批量替换；每条英文必须与相邻实现、终端安全契约和当前领域术语一致。
