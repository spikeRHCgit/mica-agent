## 追踪契约

### 1.不可复用的生命周期身份

- 每个被观察到的新 transport 生命周期分配单调递增的 `generation`；记录键为 `generation`，裸
  `id(transport)` 只作为同一对象存活期间的辅助字段。
- 维护 `active_generation_by_id`：成功 create 首次观察时分配 generation；若启动失败在 close 时首次被观察，
  同样分配 generation；`__del__` 记录完成后移除活动映射。后续对象即使复用同一个 `id()` 也必须取得新 generation。
- 追踪器只保存 generation、事件序号、ID、PID、测试 node、可执行文件 basename、裁剪创建栈和关闭状态；不得保存
  Process / transport 强引用、完整命令参数、环境变量或凭据。
- 追踪器必须调用原始 create / close / `__del__`，不得吞掉异常、warning 或改变资源关闭顺序。

### 2.原始事件与终态账目

- 每条 create、close、`__del__` 写入单调递增的事件序号和 generation。
- 对每个 generation 汇总以下状态：成功 create、启动失败首次 close、close 次数、`__del__` 次数、
  `is_closing`、returncode、创建 node和最后观察 node。
- 单列：成功 create 后无 close、`is_closing=false` 的 `__del__`、会话结束仍无 `__del__`、启动失败已收口。
- pytest 会话结束和进程退出时各写一份账目；报告必须区分这两个时间点，不能把裸 ID 数当独立对象数。

### 3.运行顺序

1. 先静态检查插件没有强引用、固定等待、GC、重试或 warning 处理，并用既有 T-012 日志做离线 ID 复用自检；这不是
   测试运行，不得重新运行 T-012 候选组。
2. 在 T-011 worktree 记录运行前 `git status --short --branch` 和 collect-only 数量，确认现场仍是 T-011 报告中的
   预期改动；collect-only 不加载追踪插件、不执行测试。
3. 只运行一次：`uv run pytest -q -W error -p t013_ordered_trace`。不要通过管道截断输出；JSONL 使用独立临时文件。
4. 无论通过还是失败，都只分析这一次运行产生的输出和 JSONL，不补跑失败 node、不再运行第二次全量。
