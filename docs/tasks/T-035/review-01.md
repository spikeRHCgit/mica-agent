## 判断审查

1. **没有循环证明协议。** `probe_cases.json` 的最小请求与工具历史后缀为手工确定的合成基准；补证测试在实际 HTTP transport 边界比较完整请求。单 read 分支不只是比较中间 ToolSpec；五工具分支另核对真实注册定义的出站形状。共享 SSE 构造只隔离网络，不代替编码和解析。
2. **本地链路证据有效且边界明确。** 补证实际经过 Provider、Engine、ToolExecutor 和产品 read handler；随机文件内容由真实读取进入下一请求，调用次数限定一次、结果 ID 关联匹配、正常终态与响应关闭均有断言。它证明指定输入下的本地链路，不证明真实渠道会返回 tool_use，也不穷尽所有历史或 SSE 变体。
3. **两种现象没有混为一个根因。** 自动工具选择允许普通文本结束，与 HTTP 400 的请求校验拒绝分开陈述。无空 text、工具 input 为对象、结果紧随调用等已有事实未被忽略；没有反推未经确认的字段错误或将模型文字当作工具事实。
4. **真实对照包没有扩大授权。** A1/A2 先做新会话对照；A3 必须先核实精确目标支持强制选择，且只在首请求指定 read，结果续问恢复 auto。H1/H2 使用新实验的真实工具事实，合成成功后缀明确禁止上传充当真实结果；总体 10 次只是上限，不是执行授权或必跑数量。
5. **后续比较保留必要限制。** 独立请求与 Mica 的系统指引、包装及真实生成的 ID/正文/结果可能不同，报告已要求登记差异，不能仅凭两侧结果不同认定产品缺陷。Provider + Engine 的最小路径即使真实通过，也不自动替代原实际 CLI/TUI 路径验收；原生与转换历史的对照同样不能冒充完全相同输入。
6. **没有越界修复。** 产品、正式测试、配置、依赖和提示词未改；没有读取真实凭据、用户会话或调用真实渠道的产出证据。新增探针为任务期资产，不形成第二套产品实现或长期在线诊断入口。
