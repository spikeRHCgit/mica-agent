依据：[首次中止记录](live-01.md)、[独立基准与对照包](probe_cases.json)、[诊断审查](review-01.md)。本记录不替代此前的真实历史 HTTP 400 诊断，也不修改 worker 的离线结论。

## 授权与执行边界

- 用户在首次中止后同意重新完成 A1/A2，追加最多 4 次模型请求，累计上限由 4 次调整为 5 次；此前消耗的 1 次继续计入，不重置计数。
- 其余边界不变：同一已确认的 Messages 测试连接、新建隔离 HOME/配置/工作区，每组只声明一个 read、最多一次指定临时文件读取；关闭思考、输出预算 1024、每请求 30 秒、零自动重试、不跟随重定向。禁止其他工具执行、强制工具选择、历史切换和 Responses。
- 开始时 HEAD 为 `b1b6d19`，与 `c33365a` 相比仅增加首次停止记录，无产品差异。真实连接仅经已有 ConfigService/受保护凭据读取在内存解析；两组使用同一绑定，不输出模型标识、地址或凭据。
- 无凭据临时探针先通过压缩 SSE 离线自检，再执行真实请求。出站闸门在发送前检查目标、认证头、版本、模型、完整基准字段及每组/累计请求上限；工具执行器只注册带精确路径与次数守卫的产品 read。
- 观察器位于 HTTPX 解压后；原始响应只留当前进程内存，记录仅保留允许的枚举、计数和布尔值。本轮两组均明确观察到 gzip；这不追认首次中止时未记录的 Content-Encoding。

## 可支持的结论

1. 本次新会话最小样本中，实际出站确有正确形状的工具定义；失败表现发生在服务端没有返回 tool_use，而非本地已经收到工具调用却未解析或执行。
2. 不经过 Mica 编码器、Provider 或 Engine 的独立协议请求也出现同样现象，且两侧首请求完整正文与同一手写基准相符。因此没有证据支持优先修补 Mica 的工具解析器、Engine 或单工具请求编码。
3. 仍不能区分模型在 auto 下没有选择工具、实际目标模型的工具行为、渠道未正确转发/转换工具等原因。HTTP 200 与正常终态不等于渠道已经认可并可执行工具；本轮没有强制工具选择证据，也不证明当前渠道/模型永久不支持工具。
4. 本轮未使用产品默认系统指引或五工具完整 CLI/TUI 路径；最小复现的定位不能扩展为用户原会话所有问题均已解释。此前带 Completions 历史时 HTTP 400 的具体根因也没有在本轮验证。
5. Messages 工具验收、恢复、取消和思考续接仍待完成；B 和 Phase 6 状态不变。不根据上述结果改提示词、默认工具策略、历史编码或产品实现。

## 请求计数、清理与后续

- 本轮新增 **2 次**真实请求；连同首次观察器中止的 1 次，累计 **3 / 5 次**，剩余 2 次不是条件 A3 或历史 H 阶段的授权。本轮没有自动/手动重试、额外工具执行、历史实验或 Responses 请求。
- 两个真实用例均未执行 Agent read，未创建真实工具历史；不能将剩余请求或合成历史自动用于下一阶段。
- 临时工作区已由创建者清理。真实凭据仅进程内存使用，未复制到临时配置、日志或会话；没有读取用户会话，没有保存原始请求/响应、正文、随机文件内容、地址、模型标识或本地绝对路径。
- 补测完成后核对并删除本轮创建的无凭据通用临时探针，只删除该文件，不清理其他用户文件。产品、正式测试、依赖和真实配置未修改；无全量/构建/真实终端验收。
- 下一步建议先核实精确目标模型与渠道是否支持 Messages 指定工具选择；支持时再向用户申请 A3 的最多两步真实对照，不支持时不硬发该选项，应由用户决定使用已确认具备工具能力的模型/渠道或向渠道核实协议转换。当前仅执行完 A1/A2，不自动开启下一阶段。
