## 一次性探针的离线定位与修正

1. 真实请求前的首次自检因内存 Mock response 的 content 已缓存而绕过流观察器，表现为解析帧为 0、终态断言失败。定位后将 Mock 改为真正的分块 AsyncByteStream，自检通过。此步骤没有真实渠道请求。
2. 当时自检只覆盖未压缩 SSE；真实 A1 在观察器解码时失败。探针原先包在 HTTP transport 的字节流上，在 HTTPX 的 Content-Encoding 解压之前直接进行 UTF-8 解码，存在诊断层级缺陷。
3. 使用显式 `Content-Encoding: gzip` 的完全合成 SSE、MockTransport 和分块流，离线重现相同的 UnicodeDecodeError，且同样发生于第一个有效解析帧之前。未读取或回放真实响应。
4. 修正一次性探针为通过 HTTPX 公共 `Response.aiter_bytes()` 取得解压后的字节，再交给观察器；向外包装的响应移除已消费的 Content-Encoding/Content-Length，避免二次解压。未修改产品适配器、Engine 或正式测试。
5. 修正后分别执行普通 SSE 与 gzip SSE 的离线自检。两种自检均让独立链路、实际 Mica Provider/Engine 链路完成合成流驱动的一次产品 read 与关联结果回传，观察器终态、随机内容及资源收口断言通过；均为 0 次真实网络请求。

**证据边界**：本轮没有保存真实响应，也没有记录当时的 Content-Encoding，因此不能追认真实 A1 的具体压缩方式或保证其响应正文合法。已确认的是探针对压缩响应的处理缺陷，以及该缺陷能够离线产生同类异常；不是 Mica 产品或原工具问题的根因。修正后的探针尚未再次用于真实渠道。
