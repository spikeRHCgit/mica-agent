# T-029：Provider 与 Engine 的续接携带及 Chat Completions 回传

状态：已完成 · 主线：Phase 6：配置与模型 · 交付项：`docs/phase6_plan.md` B 第 3 步（共 6 步）· 风险：高

## 目标概览

Provider 请求能输入历史续接，正常 Finish 能交回本步续接；Engine 在同轮工具往返中携带，并向完成和中断提交方交付安全续接。Chat Completions 支持 DeepSeek 和 OpenRouter 的续接，不改变已验收的普通推理、工具和取消行为。本卡提供接缝，实际 App 装配与历史恢复由第 6 步接入。

## 具体实现目标

- 每条已完成的 assistant 消息有一个续接位置；无续接时为空。既有调用方不传新参数时保持原有行为。
- 工具往返携带此前兼容的记录；其他供应商、模型或接口的记录不回传，通用历史仍保留。
- 提交方得到的续接已经过原始消息清洗判定、关联检查及单轮体量处理；中断时保留已 Finish 的步骤，未 Finish 的部分正文不带续接。
- DeepSeek 能回传带工具请求的全部兼容历史思考；OpenRouter 能保留并回传有序思考详情；Go 与未启用续接的连接不发送专属字段。
- 未知续接项或字段使该步不可回放，但通用正文和真实工具事实仍可完成；协议本身损坏时沿用真实错误，不冒充正常完成。

## 具体实现方案（2026-10-11 用户审查通过）

### 请求与 Finish

- `ProviderRequest` 在最后新增：
  - `provider_id: str | None = None`：稳定供应商 ID；非空时须为非空白字符串。
  - `api: ProviderApi = ProviderApi.OPENAI_COMPLETIONS`：实际接口枚举。
  - `continuations: tuple[ModelStepContinuation | None, ...] = field(default=(), repr=False)`。
- 槽位对应 `messages` 中全部 assistant 消息，包括此前轮次；空元组补成全 `None`。非空必须为 tuple、长度相等、元素类型正确；调用既有关联检查。不得把消息或记录内容带进异常文本。
- `provider_id=None` 时不产生或回放专属续接；不要从 URL、模型名称或记录推断当前供应商。非空时，回放还要求记录的 provider_id、model_id、api 与本次请求完全一致且状态为 replayable。
- `Finish` 最后新增 `continuation: ModelStepContinuation | None = field(default=None, repr=False)`，只校验类型；关联由拿到完整正文的 Engine 检查。旧位置参数仍可使用。
- 不改 `Message`、`ToolCall`、Engine 对外事件或顶层导出。

### Engine 的同轮携带和安全提交

- `AgentEngine.run` 最后新增可选关键字参数 `completed_continuations_sink`，类型为接收 `tuple[ModelStepContinuation | None, ...]` 的同步回调；验证 callable。它只收到本轮的槽位，与 completed_messages_sink 所交消息中的 assistant 顺序一致，不含输入历史槽位。成功终态前调用一次；回调失败沿用安全提交边界，返回固定诊断的 RunFailed。
- 每次构造后续 ProviderRequest 时传递 provider_id、api 和当前消息对应的完整槽位，不能因重建请求丢失新字段。
- Finish 后先组装未经清洗的完整 assistant 消息（含原始工具调用），再用 `sanitize_step_continuation` 判定并用 `check_step_association` 检查，然后才调用 `sanitize_tool_message`。最终无工具回答同样判定。记录绑定不符或关联不符是 Provider malformed 错误，工具不得执行；不把错误值输出。
- 本轮记录在加入下一请求、完成回调或进度快照前应用 `apply_turn_size_limit`；合计超限后本轮所有非空记录降为不可回放，后续步骤也保持本轮不可回放，不把早先丢弃的数据重新装回。输入历史按各轮已保存的上限使用，不把多轮合计误当一轮。
- 每个已 Finish 的工具步骤将安全记录写入 RunCheckpointProgress.continuation。工具从 not_started → in_progress → success/failed 时保留它；降级后同步更新已有 progress 步骤。部分正文没有 Finish，不带记录。
- 活跃续接也只携带与当前安全消息关联有效的记录；不另存原始工具参数或原始响应副本以绕过清洗。续接内容不进入事件、诊断、repr 或日志。

### Chat Completions

- `OpenAICompatibleProvider.__init__` 新增可选关键字 `continuation_channel: str | None = None`，只接受 `deepseek`、`openrouter` 或 None。默认关闭，Go 使用关闭值；该设置只管协议编解码，不取代 request.provider_id 的来源绑定。第 6 步负责从配置 channel 显式传入。
- DeepSeek：累积 `delta.reasoning_content`，继续产生既有思考事件；正常 Finish 携带一个 ChatReasoningItem。带 tools 的请求为每条兼容 assistant 历史发送 reasoning_content；没有 tools 时不发送。不要只回传最近一个工具步骤。
- OpenRouter：累积 `delta.reasoning_content`、`delta.reasoning` 及有序 `delta.reasoning_details`；字符串片段按到达顺序拼接，details 数组按到达顺序连接，保留每项的 index/id/format 与内容，不凭 index 猜测合并或重排。思考展示使用 reasoning_content，其缺失时使用 reasoning，避免同一片段双发；详情明文只在这两种字符串均缺失时展示，签名、密文、data 不展示。
- details 严格转换为既有 ReasoningDetail：允许 type/id/format/index 和该类型对应的内容字段，缺省可选字段规范化为 None。未知类型、多余字段或不能合法表示的内容使整步记录 unreplayable；不可回放记录不保留原始字典。保留空字符串与 None 的差异。
- OpenRouter 回传 ChatReasoningItem 中实际有内容的 reasoning_content、reasoning、reasoning_details；详情按保存顺序编码，仅输出协议适用且非 None 的字段，不把内部 wire 的无关 null 字段塞给服务端。
- 启用渠道且 request.provider_id 已知时才产生来源绑定的记录；没有任何续接数据时为 None。纯思考、无正文无工具的正常步骤允许完成并带记录；默认关闭渠道的旧空响应规则保持不变。
- 流式累积续接使用 `continuation_size` 对应的 1 MiB 上限保护：超过后释放本步累计专属内容，标记不可回放，后续只继续通用文本、工具和可见思考流；不能先无限累积再在 Finish 时裁剪。不限制用户正文或工具结果来替代续接上限。
- 保持既有终态、工具碎片、重试和断流规则。取消、失败或缺少正常终态不产生 Finish 续接；不得剥离续接后自动重试。

协议依据：OpenRouter 官方 Reasoning Tokens 文档规定流式 details 按顺序连接、回传完整连续块且不得改动；其 index 字段不构成在本卡自行合并的依据。DeepSeek Thinking Mode 文档规定带 tools 时回传此前所有轮次的 reasoning_content。

- https://openrouter.ai/docs/use-cases/reasoning-tokens
- https://api-docs.deepseek.com/guides/thinking_mode

## 完成标准

- ProviderRequest 的默认兼容、槽位数量/类型、关联与绑定过滤有直接断言；Finish repr 不显示思考、签名或密文。
- 用 fake Provider 跑两次工具往返加最终回答：每次请求的槽位正确增长，本轮完成回调含三个位置（其中至少一个 None），输入历史槽位不混入完成回调。
- 工具参数含凭据、思考含本地绝对路径：下一请求、完成回调和取消快照中的记录均不可回放；原始工具参数仍交给既有执行/权限入口，持久化消息保持清洗结果。
- 取消于工具执行中、第二步流中失败、正常纯思考步骤：快照只为已 Finish 步骤保留记录，部分正文无续接，工具状态更新不丢续接。
- 本轮合计恰好 1 MiB 保留，超过 1 字节全部降级且后续不恢复；验证进度、下一请求、完成回调一致，以及多个历史轮次合计超过 1 MiB 不被误丢。
- DeepSeek 固定 SSE 样本验证字符串累积及全部历史回传，带/不带 tools 分别断言完整请求字面量。
- OpenRouter 固定 SSE 样本覆盖 reasoning 字符串、三个详情类型、同 index 的连续片段及不同 index；Finish 记录和下一请求与固定字面量相等，数组顺序、签名、密文保持原值，未双发思考。
- 未知详情字段/类型产生不可回放记录但正文和工具仍正常；超限流能继续完成且不保留累计专属内容；协议损坏、断流、取消不冒充 Finish。
- 供应商、模型、接口不符和 unreplayable 均不回传专属字段；关闭渠道（包括 Go）不发送续接，既有普通请求、工具、取消和重试测试通过。
- 回调异常只产生一次失败终态，诊断和各新增对象 repr 不含续接内容。
- 验证：局部开发运行 `uv run pytest tests/test_provider_contract.py tests/test_openai_provider.py tests/test_engine.py -q -W error`；稳定后运行 `uv run pytest -q -W error`（含现有安装态验证），`uv run ruff check src/mica_agent tests`、`uv run ruff format --check src/mica_agent tests`。如实列出平台跳过项。
- `git status --short` 只显示允许范围内的文件。

## 实际成果

- ProviderRequest 和 Finish 增加续接输入输出，默认兼容原有调用。
- Engine 在原始消息清洗前判定续接，在工具往返、完成回调和中断进度中携带安全记录；单轮超限后统一且持续降级。
- Chat Completions 支持显式启用 DeepSeek/OpenRouter 的续接累积和回传，默认关闭；未知详情或超限不破坏通用正文和工具事实。
