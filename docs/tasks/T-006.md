## 契约与约束

- `.gitattributes` 只为 `src/mica_agent/prompts/system.md` 声明文本与 `eol=lf`；不得借本任务建立未经审计的
  全仓换行策略。
- Git blob 当前已经是 2,591 bytes、62 个 LF、0 个 CR；实现不得改变该 blob 的文本内容。任务 worktree
  中的物理文件必须从 CRLF 恢复为与 blob 逐字节相同的 LF。
- 该文件是随 wheel/sdist 分发并由 `importlib.resources` 读取的包资源。构建产物中的成员必须无 BOM、无 CR，
  且与仓库 blob 逐字节一致。
- 当前未提交状态下无法证明“提交后的全新 worktree”行为；worker 应证明 attribute、当前物理字节与构建
  产物，master 在收口提交后另建干净 worktree 完成最终检出验证。

## 候选经验

<!-- 可复用的教训：现象、证据位置、建议去向 -->

- **精确字节包资源应使用路径级 EOL 契约**：仓库 blob 为 LF 并不能阻止 Windows
  `core.autocrlf=true` 将工作树改成 CRLF；对单个有精确字节要求的资源使用
  `<path> text eol=lf`，比扩大为 `*.md` 或全仓策略更符合证据和最小改动原则。
- **物理规范化需要同时核对 object 与 diff**：本任务中工作树 raw object、filtered object、index blob
  和 HEAD blob 完全相同，且正文 diff 为空；`git status` 仍可因工作树 stat/物理字节变化暂时标记该路径，
  因此交接时应同时报告字节、object ID、正文 diff 和暂存区，而不能只看一项。
- **依赖任务的失败要保留归属**：全量验证暴露的是 T-005 已处理测试的 Windows 临时目录 teardown 时序，
  不应在 T-006 越界修改测试或通过重跑掩盖；应保留首次现场并由 master 在依赖合并顺序中复验。
