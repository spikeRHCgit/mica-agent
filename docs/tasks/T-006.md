## 目标

为 `src/mica_agent/prompts/system.md` 建立明确、最小的 LF 检出契约，使 Windows 上启用
`core.autocrlf=true` 的新 worktree、源码工作树和构建产物都保留与 Git blob 一致的 UTF-8/LF 精确字节，
解除 T-005 的全量验收阻塞。不得通过放宽精确字节测试、修改产品读取逻辑或改变用户提示词内容规避问题。

## 契约与约束

- `.gitattributes` 只为 `src/mica_agent/prompts/system.md` 声明文本与 `eol=lf`；不得借本任务建立未经审计的
  全仓换行策略。
- Git blob 当前已经是 2,591 bytes、62 个 LF、0 个 CR；实现不得改变该 blob 的文本内容。任务 worktree
  中的物理文件必须从 CRLF 恢复为与 blob 逐字节相同的 LF。
- 该文件是随 wheel/sdist 分发并由 `importlib.resources` 读取的包资源。构建产物中的成员必须无 BOM、无 CR，
  且与仓库 blob 逐字节一致。
- 当前未提交状态下无法证明“提交后的全新 worktree”行为；worker 应证明 attribute、当前物理字节与构建
  产物，master 在收口提交后另建干净 worktree 完成最终检出验证。
- T-005 暂不合并；本任务独立处理仓库可复现性，完成后由 master 按依赖顺序收口。

## 验收

- 验证级别：`docs/code_spec.md` §6.1 中的「依赖、入口或包资源」。
- 开始时在 T-006 新 worktree 复现：`git ls-files --eol -- src/mica_agent/prompts/system.md` 显示
  `i/lf w/crlf`，原始字节含 62 个 CR，指定精确字节测试失败。
- `.gitattributes` 的唯一产品规则精确匹配该资源，`git check-attr text eol -- <path>` 返回 `text: set`、
  `eol: lf`。
- 规范化后，工作树资源为 2,591 bytes、62 个 LF、0 个 CR、无 UTF-8 BOM，并与 `git show
  HEAD:src/mica_agent/prompts/system.md` 逐字节一致；`git diff` 不得显示提示词正文变化。
- `uv run pytest tests/test_system_prompt.py -q -W error` 通过。
- `uv run pytest -q -W error` 全量通过；只执行一次，若失败先保留现场并诊断，不盲目重跑。
- `uv run ruff check src/mica_agent tests` 和 `uv run ruff format --check src/mica_agent tests` 通过。
- `uv lock --check` 与 `uv build --offline` 通过；检查新建 wheel 与 sdist 内的该资源，证明无 BOM、无 CR、
  与 Git blob 逐字节一致。
- `git diff --check` 与 `git diff --cached --check` 通过；暂存区为空，实际 tracked diff 仅限
  `.gitattributes` 和本任务卡。
- master 收口提交后，在启用 `core.autocrlf=true` 的新 worktree 中复核 `w/lf`、精确字节测试和资源字节，
  再解除 T-005 阻塞。
