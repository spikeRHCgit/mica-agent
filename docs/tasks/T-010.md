## 迁移要求

### 1. 先冻结迁移前事实

- 记录两个文件修改前的测试函数名称、参数项和 collect-only 数量。
- 建立旧 13 个收集项到最终测试的逐项映射；最终报告必须说明哪些被现有项严格包含、哪些通过加强现有
  断言承接、哪些仍作为独立参数项保留。

### 2. 路由与帮助

- 保留目标文件现有 7 项 CLI 参数矩阵，并增加对 `session_mode`、`PermissionMode` 和 `plain` 的联合断言；
  不新增与旧 6 项一一重复的第二个参数化测试。
- help 行为由现有 `test_cli_help_documents_default_terminal_and_plain` 承接；保留 default terminal、
  `--plain`、移除 preview/Textual 等现有断言，不再保留旧 help 测试。

### 3. 默认路由装配与真实 turn

- 在 `test_default_route_drives_the_assembled_app` 中合并旧快照测试的独有证据：
  - ContextBuilder 和系统提示词各构建一次；
  - `stored_session`、startup resources 和 session snapshot 传入 screen；
  - workspace `AGENTS.md` 来源、相对路径、工具列表以及空 skill/extension 列表准确；
  - workspace、session label 和 model 准确；
  - screen 通过真实 App run 提交用户消息与完成轮次，会话可从 SessionService 重新列出；
  - 默认 TUI 路径不向 plain stdout/stderr 写普通输出；
  - Provider 最终只关闭一次。
- 不把这些断言拆成多个仅检查私有字段的小测试，也不复制第二套 `ScriptedProvider` 或 dependency factory。

### 4. continue / resume 会话选择

- 迁移并保留 `continue`、`resume` 两个参数项：已有会话被选中并传给 screen，session label 保持所选标题，
  后续真实 prompt 进入 Provider 上下文，Provider 只关闭一次。
- 可以新增一个窄小参数化测试，或在不降低可读性的前提下扩展现有 session-routing 测试；不得把两种模式
  合成一个不再区分输入的宽泛断言。

### 5. 失败、取消与 plain 兼容

- 加强目标文件现有 run-failure 测试：固定安全诊断不泄漏 key/私有 URL，Provider 只关闭一次，失败会话
  不产生 turn。
- 加强现有 cancelled-screen 测试：`CancelledError` 继续传播，Provider 只关闭一次，取消会话不产生 turn。
- 加强现有 plain-route 测试：不构建 MainBufferScreen，stdout 精确包含模型回复，stderr 为空，Provider 请求
  中最后一条消息保持 USER role，Provider 只关闭一次。
- 保留目标文件现有 startup failure、normal exit、already-closed failure、preview rejection 和 distribution
  依赖边界；不要为了减少数量把不同生命周期入口互相替代。

### 6. 清理旧资产

- 只有逐项迁移完成后才能删除 `tests/test_p5_09_integration.py`。
- 删除旧文件专属的 `InputScript`、`Recorder`、重复 Provider/dependency helper；若目标测试确实需要输入或
  输出记录，优先使用局部窄小结构，不建立新的全局测试框架。
- 目标文件的模块 docstring、正式 docstring 和 `#` 注释统一使用英文；只整理本任务触及的目标文件，不扩大
  到其他测试。
