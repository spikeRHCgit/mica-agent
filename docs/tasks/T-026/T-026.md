## 调研问题

每条事实附来源链接；区分「官方文档明确写出」「官方 SDK 类型定义」「推断」三种来源，查不到的写「未核实」和查过的位置。凡是问「候选」的，给出一到两个可选方案和各自的代价，不替 master 选。

### Responses（`openai-responses`）

1. **请求**：系统指引用 `instructions` 还是 developer/system input item；通用消息、`function_call`、`function_call_output`、`reasoning` 四类 input item 的必需字段；function 工具定义格式；`reasoning`（effort 取值、summary）、`max_output_tokens`、`store`、`include`、`parallel_tool_calls` 的含义和限制。
2. **流式事件**：产出正文、思考摘要或思考正文、函数参数增量与完成、输出项新增与完成所用的事件类型；`response.completed`、`response.failed`、`response.incomplete`、`error` 的形状和区别；`incomplete_details` 的取值。
3. **续接**：`store=false` 时，同一轮工具往返需要回传哪些输出项（reasoning item 的 `id`、`encrypted_content`、`summary`）；`include` 需要什么值；assistant message item 的 `phase` 字段是什么、哪些模型返回、是否必须回传；回传的项来自另一模型或另一账号时服务端怎样表现；各 ID 的前缀和格式。
4. **错误**：HTTP 错误体和流内错误事件的形状；认证、限流、超时、上下文超限各自怎样识别。

### Messages（`anthropic-messages`）

5. **请求**：`system` 的位置和形式；messages 角色交替要求；text、tool_use、tool_result、thinking、redacted_thinking 内容块的字段；工具定义格式；`max_tokens` 是否必需；思考参数的当前形式（`budget_tokens`、adaptive、effort 等）及与输出预算的关系；必需请求头和认证方式。
6. **流式事件**：`message_start`、`content_block_start/delta/stop`（`text_delta`、`thinking_delta`、`signature_delta`、`input_json_delta`）、`message_delta`、`message_stop`、`ping`、`error` 的形状；`stop_reason` 全部取值，哪些算正常完成。
7. **续接**：工具往返中 thinking、redacted_thinking 块是否必须原样回传、能否修改或省略；签名绑定什么（模型、账号等），跨模型回传时服务端怎样表现；更早轮次的思考块能否省略；交错思考（interleaved thinking）的条件。
8. **工具 ID**：`tool_use.id` 的格式约束；`tool_result` 的位置和 `tool_use_id` 对应要求；错误结果的表示方式。

### Chat Completions 内置渠道与跨接口

9. **思考与续接回传**：OpenRouter、DeepSeek、OpenCode Go 各自在流里怎样返回思考内容（例如 `reasoning_content`、`reasoning`、`reasoning_details`）；同一轮工具往返中是否要求回传、回传哪个字段；不回传时官方写明的后果。
10. **对照现有实现**：第 9 条的要求与 `openai_compatible.py` 现有编码和解析相比，缺哪些。只列差异，不改代码。
11. **OpenCode Go 的接口分配**：哪些模型走 Chat Completions、哪些走 Responses 或 Messages；官方是否给出可机读的映射；需要的请求头。
12. **跨接口工具 ID**：三类接口对工具调用 ID 的格式限制；一种接口产生的 ID 直接用在另一种接口时，会被拒绝的情况。

### 续接记录的候选
