## 候选经验

<!-- 可复用的教训：现象、证据位置、建议去向 -->

- **现象**：用 `-p <module>` 加载仓库外 pytest 插件时，若长时间无 stdout（例如 `2>&1 | tail` 缓冲整个运行），
  长时命令可能被外部中断；改为流式输出后才能观察到真实卡点（约 12% 后停顿）。
  **证据位置**：`%TEMP%\t011_full_trace_run.txt` 与三轮追踪尝试的进度输出。
  **建议去向**：`docs/lessons/inbox.md`。
- **现象**：`PYTHONASYNCIODEBUG=1` 会显著放慢运行并产生大量回调日志，长时间全量运行更易被中断；诊断时
  优先保留 `PYTHONTRACEMALLOC`，tracing 插件自身已能提供创建栈。
  **证据位置**：三次追踪尝试的对比。
  **建议去向**：`docs/lessons/inbox.md`。
- **现象**：`BaseSubprocessTransport.__del__` 触发时 `_proc` 可能已为 `None`，导致 `__del__` 事件读不到 PID；
  PID 关联应依赖 `create` / `close` 事件的 PID，`__del__` 用 `created_node` + `transport_id` 定位。
  **证据位置**：`%TEMP%\t011_lifecycle_trace_smoke.jsonl`（`del` 事件 `pid` 为 `null`）。
  **建议去向**：`docs/lessons/inbox.md`。
- **现象**：在类级别挂钩 `BaseSubprocessTransport.close` / `__del__`（而非包装实例方法），可在不持有强引用、
  不改变 GC 时机的前提下观测 transport 生命周期；先用 `__dict__` 检查子类是否重写成员可确认挂钩点。
  **证据位置**：`%TEMP%\t011_lifecycle_trace.py` 与 `_WindowsSubprocessTransport.__dict__` 检查。
  **建议去向**：`docs/lessons/inbox.md`。
