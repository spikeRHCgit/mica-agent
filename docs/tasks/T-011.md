状态：待开始 · 阶段：阶段间治理 · 负责：外部 worker · 分支：`task/T-011-app-checkpoint-tests` · 基线：`fa0a68b`

## 目标

收口 `tests/test_app.py` 与阶段命名的 `tests/test_p5_10g_integration.py` 中重复的 checkpoint 生命周期测试：

- 分别保留运行中 `CancellationToken.cancel()` 与外部 `asyncio.Task.cancel()` 两种取消入口；
- 把重复的取消持久化断言并入更完整的跨模型恢复测试；
- 把重复的可恢复失败断言并入“失败后继续运行”的完整测试；
- 把工具批次中 `SUCCESS / NOT_STARTED` 的独有 checkpoint 行为迁入行为命名的
  `tests/test_tool_session_integration.py`；
- 逐项迁移完成后删除 `tests/test_p5_10g_integration.py`。

完成后只保留一套 App/checkpoint 生命周期证据，不改变产品代码、持久化格式、取消语义或工具行为。

## 当前证据

- 当前 `tests/test_app.py` 有 41 个顶层测试函数、45 个收集项；
  `tests/test_p5_10g_integration.py` 有 3 个顶层测试函数、3 个收集项，两文件合计 48 项。
- 当前全仓为 1728 个收集项；T-010 主线全量为 `1726 passed, 2 skipped`。
- `test_cancelled_run_commits_checkpoint` 与
  `test_cancelled_checkpoint_restores_under_a_new_model` 使用同一外部 task-cancel 路径；后者具有更完整的跨模型
  恢复与“不伪造 assistant”证据，但还需吸收前者的 history、空 turn、checkpoint kind 等精确断言。
- `test_cancelled_partial_text_is_restored_without_forged_assistant` 使用运行中的
  `CancellationToken.cancel()`；该入口与外部 task cancel 的传播和清理路径不同，必须作为独立测试迁入
  `test_app.py`，不得被前一场景替代。
- `test_failed_run_commits_recoverable_checkpoint` 与 `test_follow_up_run_sees_checkpoint_context` 使用同一
  authentication failure；后者已经覆盖后续成功、上下文顺序和磁盘 checkpoint/turn，补齐 kind、partial、
  空 turn、history 和首次 Provider request 断言后可以删除前者。
- `test_auth_failure_checkpoint_then_successful_turn` 被上述加强后的 App 测试严格包含，不应保留第三份装配。
- `test_tool_batch_cancel_keeps_completed_prefix_and_unstarted_call` 是独有证据：它证明同批次第一个工具完成、
  第二个工具未开始时，checkpoint 和恢复上下文只包含真实完成前缀；必须迁移保留。

- 在该测试中保留或补齐：终态 `RunCancelled`、history 中 USER/partial/cancelled 状态、没有成功 turn、单个

- 完整承接后删除 `test_cancelled_run_commits_checkpoint`；不要保留第二套 `HangingProvider` 和第二条相同

### 3. CancellationToken cancel

- 把 `test_cancelled_partial_text_is_restored_without_forged_assistant` 迁入 `tests/test_app.py`，以行为命名并明确

- 保留 token 在 Provider 已输出 partial 后触发、终态正常返回 `RunCancelled`、无 turn、checkpoint kind 与
  partial 内容、后续运行恢复原 USER/partial/incomplete 状态且不伪造 assistant 的全部证据。
- 优先复用 `test_app.py` 现有的 `_ScriptedProvider`、App/session helper 和事件收集工具；允许为确定性挂起保留
  一个窄小局部 Provider，不建立新的共享测试框架。

  USER、真实 partial 和固定 recoverable-failure 状态，磁盘无成功 turn、只有一个
  `RECOVERABLE_FAILURE` checkpoint 且保存真实 partial，首次请求仍为 SYSTEM + USER。
- 保留该测试现有的第二次成功、恢复上下文顺序、incomplete 状态和最终成功 turn 断言。
- 完整承接后删除 `test_failed_run_commits_recoverable_checkpoint`，并删除旧阶段文件中严格重复的
  `test_auth_failure_checkpoint_then_successful_turn`。
