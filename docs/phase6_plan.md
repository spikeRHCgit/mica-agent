## 1. 阶段目标

让用户无需预先填写环境变量即可进入 Mica，在终端中配置多个供应商、登录 ChatGPT 官方订阅、保存模型目录、切换模型与接口，并管理工作区共享设置。切换和恢复必须保留真实会话与工作进度，不损坏已有历史、权限、取消和终端输入能力。

本阶段沿用主缓冲区前端及现有 Agent Loop，增加必要的配置服务、协议适配和会话契约，不借功能开发启动 D-014 延期的整体架构重构。实现严格限于本文交付目标；相邻阶段的功能不能顺手加入。

## 2. 需求输入

### 2.1 已确认

- **配置分工**：全局使用 `~/.mica/config.json`、`models.json`、`auth.json`，分别保存设置、供应商与模型、凭据；工作区只使用 `<workspace>/.mica/config.json`。配置保持简单 JSON，不增加 `version` 或配置版本迁移系统。
- **错误处理**：未知键提醒后忽略；已知键取值不合法时提醒并使用该项默认值；其他合法字段继续加载。JSON 语法错误直接报错并阻止开始会话，不把整份错误文件当作空配置继续对话。
- **启动体验**：首次直接进入 TUI，显示介绍和缺少模型配置的提示；用户主动使用 `/login`。没有可用模型时发送普通消息只提示配置，不启动 Run。
- **渠道范围**：支持多个连接及同名模型，先提供 ChatGPT 官方订阅、OpenRouter、DeepSeek、OpenCode Go 和自定义供应商；不扩充大量预置官方渠道。
- **接口范围**：实现 `openai-completions`、`openai-responses`、`anthropic-messages`，模型可覆盖供应商默认接口；跨模型、跨供应商和跨接口切换保留会话事实，不承诺继承不兼容的内部思考状态。
- **发现与能力**：配置连接后自动尝试获取模型列表，用户选择保存项；失败时允许手工填写模型 ID。不发送额外推理请求测试连接。能力按手工声明、明确官方信息、默认值依次采用；未知上下文为 200000 tokens，默认文本输入、不支持多模态、不支持思考。本阶段只记录图片能力，不实现图片输入或传输。
- **命令分工**：`/login` 管理连接与登录，`/model` 选择当前模型，`/settings` 管理有限选项，`/reload` 主动重载配置；不保留 `/config` 别名，不做文件监听。
- **选择与默认**：`/model` 的 Enter 只切换当前会话；Ctrl+S 明确保存高亮项为全局默认，不同时切换当前会话。恢复会话记住供应商与模型，不记住 Key；缺失或禁用时提示处理，不静默换模型。
- **工作区设置**：`/settings` 的 Enter/Space 默认保存到工作区并生效；Ctrl+S 逐项同时应用到全局。设置作用于该工作区的新建、切换和恢复会话，不能被历史会话旧设置覆盖。已开始的 Run 不变，其他进程在安全读取节点更新。
- **交互边界**：四个命令只在空闲时执行；Ask/Permission 也属于运行中。忙时尝试命令只在输入区短暂灰色提醒，不排队、不取消 Run、不发送给模型；配置菜单 Esc 只关闭菜单，Ask/Permission Esc 仍取消 Run。
- **维护与模式**：已有供应商可改 Key、重新授权、刷新目录、改显示名称、禁用、启用或确认删除；删除只清理本地配置与凭据，不删除历史。取消内置工作模式和 `workMode` 字段，Mica 不与 aTa 捆绑。

## 3. 具体实现方案

本节描述要实现的职责与数据流，不宣称文件或能力已经存在。新增模块按实际职责命名，完成时更新 `docs/module_map.md`；不提前把预期文件写成源码事实。

### 3.1 配置读取、来源与文件写入

建立唯一配置入口，负责读取、校验、合并、来源说明和保存。CLI、应用和菜单使用同一份解析结果，不分别读取环境变量或 JSON。有效设置、模型目录和凭据分开传递；凭据不进入可打印的普通配置快照。

**来源按类别处理**：

| 类别 | 采用方式 |
|---|---|
| 当前供应商与模型 | 会话中明确 `/model` 选择最高；启动时显式 CLI 选择高于恢复记录，恢复记录高于环境连接和工作区/全局默认。没有显式或恢复选择时，按环境、工作区默认、全局默认查找；不存在则保持未配置。 |
| 工作区共享设置 | 未显式覆盖时，工作区字段高于全局字段和程序默认；不从历史会话恢复旧值。现有显式 CLI 覆盖仅属于启动进程，必须区别于 argparse 的默认值并显示来源；用户在该进程明确修改该项后，以新的用户操作为准。其他进程的显式覆盖不被文件写入偷偷撤销。 |
| 模型能力与接口 | 当前模型显式字段高于供应商默认或官方发现值；缺失时使用已验证的适配器默认与 §2.1 能力默认。已保存的明确能力字段保留，刷新只补缺失项，不覆盖用户手工值。 |
| 凭据 | 始终绑定选定供应商。既有 `MICA_API_URL/MICA_API_KEY/MICA_MODEL` 作为不写入文件的临时连接保留，不能把其 Key 自动套给后来选择的其他供应商；不增加一套任意环境变量插值语言。 |

字段缺失可以继承较低来源；字段存在但值非法时提醒并使用该字段的程序默认，不能悄悄从另一层找值掩盖错误。模型连接必需字段没有安全默认时，该条连接不可用，其他合法连接仍可用。文件缺失是未配置，不是语法错误；无法读取、JSON 根结构错误和语法损坏分别给出可操作的安全诊断。

保存前在锁内重新读取最新文件，只改目标项并保留无关字段；复用既有文件锁和临时文件原子替换方式，不另建通用事务框架。损坏文件不自动覆盖，写失败保留原字节。新模型、认证和默认选择分步提交时，只在所需记录全部有效后标记连接可用；默认值和运行状态不领先于保存结果。并发编辑不能无提示覆盖其他窗口刚保存的项。

**文件字段基线**：

| 文件 | 内容 |
|---|---|
| `config.json` | `defaultModel`（`provider` + `model`）、`reasoningEffort`、`permissionMode`、`reasoningDisplay`。后三项默认分别为 `off`、`default`、`collapsed`。 |
| `models.json` | `providers` 按稳定供应商 ID 索引；供应商声明显示名称、渠道类型、`enabled`、`baseUrl`、默认 `api` 和 `models`。模型保存 `id`、可选名称、接口覆盖、`contextWindow`、`maxTokens`、`input`、`reasoning`、`thinkingLevelMap`。能力默认在读取时补，界面明确标注采用默认值，不把未知能力伪装成发现结果。 |
| `auth.json` | 按供应商 ID 保存有类型的 API Key 或 OAuth 凭据；订阅记录包含经过验证的身份、issued client ID、tokens、授权范围和到期信息，保留本机稳定 host ID。菜单只显示安全标签和状态，不显示 token。 |

`maxTokens` 是模型允许的输出预算信息，不是上下文长度；有明确值时约束请求，无明确值时使用适配器有界默认，不能因上下文默认 200K 就请求 200K 输出。不同接口需要的字段不同，例如 Messages 需要输出预算，而 ChatGPT 订阅 HTTP 路径不接受 `max_output_tokens`。精确类型与安全诊断在首批配置契约中固定，不开放任意 HTTP header 或原始响应路径配置。

工作区配置禁止存凭据；发现疑似凭据字段时提醒并忽略，不回显值。全局认证文件使用实际可验证的用户权限保护；Windows 不能把 Unix chmod 当作权限验收，必要时使用用户目录 ACL 并检查是否对其他用户开放。所有认证写入原子完成，失败不能截断旧文件。

### 3.2 未配置启动与空闲连接切换

当前 `cli.py` 在进入 TUI 前要求三个环境变量，`MicaApp` 构造固定 Provider/model，`MainBufferRuntime` 固定绑定 App。本阶段改动这条装配链，让终端启动与“连接已经可用”分开，未配置时仍保留输入区、事实区和配置入口。

连接选择与装配归应用侧配置协调入口；Provider 客户端的关闭仍由明确的应用所有者负责，Runtime 仍只拥有唯一 Run 及其消费任务。TUI 不直接修改 App/Engine 私有字段，也不创建假的 Provider 或假的成功事件表示未配置。直接 `run_interactive(...)` 的既有显式连接入口和 `plain=True` 默认保持可用；`--plain` 从同一配置入口获得连接，不能配置时给出文字诊断，不强行打开 TUI 菜单。

空闲切换按“校验目标与历史 → 准备新连接 → 保存会话选择 → 安装运行选择并更新事实区 → 收口旧连接”完成。准备或保存失败保留旧选择并关闭候选资源；安装后的旧资源清理失败单独报告，不能伪装成目标配置未保存。下一轮 Run 只使用开始时固定的连接、模型能力、思考与权限设置，不能半轮替换。取消后需等真实任务与检查点收口才算空闲。

模型切换不重读并替换该会话已冻结的系统提示词或 AGENTS，也不新建会话、清空历史、重复执行工具。上下文缩小时先警告并确认；已知超限时不悄悄删历史，也不把确认当作突破容量限制的许可。容量只能估计时标明估计，服务端真实超限仍正常报错；本阶段不顺手实现压缩。

未配置时提交内容只给出配置提醒，保留可编辑草稿，不产生 User/Turn/checkpoint。JSON 语法错误按 §3.1 阻止开始会话，修好后可以重新启动；已运行进程的 `/reload` 遇到此错误时保留旧快照供显示与修复，但禁止新 Run 使用一份被声称已重载成功的错误配置。

### 3.3 统一会话、接口适配与思考续接

继续由 `Message/ToolCall` 表达供应商无关的对话与工具事实，由 Provider 模块转换请求和流式响应；Engine 保持统一模型/工具/权限/取消循环。三个接口必须统一产出完整文本、独立思考事件、完整工具调用和真实终态，不能让每个接口拥有第二套 Agent Loop。

| 接口 | 适配重点 |
|---|---|
| `openai-completions` | 扩充现有 `OpenAICompatibleProvider`；合并工具参数碎片，处理独立 reasoning 字段及渠道明确要求的续接数据，不依据正文标签猜测思考。 |
| `openai-responses` | 将消息和工具事实转换为 input items，关联 function call/output，保留必要 phase 与受支持的 reasoning items；失败、不完整和流结束缺少正常终态不能冒充 Finish。 |
| `anthropic-messages` | 独立 system 与 messages，转换 tool_use/tool_result，完整组装 block 和 JSON 参数，正确处理 thinking/signature、输出上限和工具往返。 |

各适配器复用现有 `httpx`，分别维护请求编码和响应解析，不引入第二套 HTTP 链路。供应商 ID 与模型 ID 决定能力，协议 ID 决定适配器；同一供应商的模型可使用不同协议。认证及少量官方渠道请求要求在连接装配边界设置，不泄漏到工具执行或前端。

**历史与专属续接分开**：会话事实保持唯一有序来源；必要的协议续接记录使用有明确字段、长度上限、来源绑定和校验的内部数据契约，不保存 SDK 对象、整个原始响应或任意字典。关联到对应供应商、模型和模型步骤，不能靠接口名相同认定兼容。Engine 在同轮工具往返中传递它，App/SessionService 在安全边界提交它，TUI 只使用允许展示的文字。

活跃请求需要的未经改写协议内容只在有界运行上下文内保留，不进入日志、repr 或普通持久化。对签名/加密字段不能正则替换后仍声称有效；保存候选通过既有敏感信息边界并验证关联内容未被清洗改变时才能标记可回放，否则明确标记不可回放，只保存清洗后的通用事实。不能为保持签名而绕过凭据、路径及工具参数清洗。精确保存白名单、关联顺序和失败降级先审查再编码。

兼容原连接继续时完整回传协议要求的数据；跨模型、供应商或接口时过滤不兼容续接，重新编码普通历史与真实工具事实。不能合法转换的旧工具/思考组合使用明确的 Mica 历史工作记录，保留实际行为和结果，不伪造目标模型的签名、思考或成功工具结果。切回原连接也重新检查绑定上下文，不保证旧签名在混合历史中仍有效。

工具调用与结果在目标请求中保持一一关联；目标接口要求不同 ID 形式时，只建立请求内映射，不改写保存的调用身份或产生执行动作。系统指引与历史记录分开转换，Mica 中断提示保留来源，不能把工具输出或历史正文提升为 system/developer 指令。

中断继续使用 `RunCheckpoint`：保留用户指令、已完成工具结果、部分正文与真实工具状态，区分 SUCCESS/FAILED/IN_PROGRESS/NOT_STARTED；完整成功只提交 Turn。跨接口恢复不能自动执行旧工具或为未完成工具补结果；对可能已产生副作用的工具提示先核对工作区。可见思考文本与不可见协议续接不是同一数据，显示模式不影响协议必要回传。

### 3.4 会话身份与兼容保存

现有 `SessionMeta` 没有供应商/模型选择。增加独立选择字段，保存稳定供应商 ID 与模型 ID，不保存 URL、Key、工作区设置或菜单组件。继续、恢复、分支及元数据重写必须保留选择；清空内容保留当前选择，回退不擅自改模型。

旧 v1～v4 会话保持可读；旧记录没有选择时使用明确启动选择或现行默认，并告知来源。已经保存的选择缺失或禁用时保留引用并要求处理，不静默按默认替换。环境临时连接的恢复只能匹配本次确实提供的对应连接，否则重新选择；不能把临时 Key 写入会话以使恢复“总是可用”。

现有 JSONL 版本用于严格会话契约，不等于给用户配置增加 `version`。新增选择和续接字段需要兼容读写设计，旧文件只读不改字节，业务写入锁内原子升级；新格式不得伪称旧 v4。首批先审查选择字段，协议批次再审查续接字段；能安全纳入同一新格式则复用，不能提前塞入未经定义的占位字段。具体 wire 版本与形状在契约审查后固定。

### 3.5 `/login`、模型目录与供应商维护

菜单依次提供订阅登录、内置渠道 API Key、自定义供应商，以及已有供应商维护。自定义配置填写名称、URL、Key、接口；稳定 ID 与显示名称分离，改名称不使历史引用失效。Key 输入遮蔽，不进入 editor 历史、用户消息、截图或诊断。

保存连接后自动请求模型目录，使用有界请求与可取消任务；不发推理测试。目录适配按渠道解析 ID、名称和明确能力，获取失败保留连接并允许手工模型 ID；空列表与请求失败要区别显示。不因发现或恢复历史执行任何工具。

模型选择采用 ↑/↓ 导航、Space 勾选、Enter 保存；只保存选中的模型。刷新时已有模型保留选中状态，明确字段按 §3.1 保留；远端暂时未返回的已有模型不自动删除。没有当前可用模型时转入 `/model` 明确选择；已经可用则返回草稿，不自动改当前或全局默认。

已有供应商可重填 Key、重新授权、显式刷新目录、禁用或启用；自定义供应商可改 URL/API，内置订阅授权端点不开放任意改写。新认证未成功验证和写入前保留旧记录。禁用保留连接、目录与凭据，模型不再可选或用于新请求；引用它的当前/默认/恢复选择不被删掉，只提示启用或重选。

删除需要确认，清理该供应商本地连接、目录与凭据，不删历史或改用其他供应商。删除与刷新并发时，迟到响应不能重建已删除的配置；删除与 token 刷新使用同一凭据归属锁。多文件清理部分失败须报告未完成范围，残留不得被当作有效连接。这里是本地删除，不声称已经远端撤销授权。

内置渠道从官方文档确定模型目录、基址和认证，不把当前模型名称、额度和价格硬编码成产品承诺。OpenCode Go 按模型使用不同接口，发送 Mica 自己的 User-Agent 和稳定、不含工作区路径的会话标识；不能冒充其他客户端。官方目录缺少可靠接口信息时使用已核实的渠道映射或让用户显式指定，不按模型名称猜协议。

### 3.6 ChatGPT 官方订阅

直接采用官方 Sign in with ChatGPT 的开源客户端流程，不复用 pi/Codex 的凭据或登录文件，不读取密码，不依赖 ChatGPT 私有 backend-api 或启动 Codex app-server。

用户主动选择后在系统浏览器完成授权；本地回调只监听 `127.0.0.1`，使用每次独立的 state、nonce 和 PKCE。保存实际 issued client ID 与本机稳定 host ID；验证 ID token 签名、issuer、audience、到期与 nonce，确认返回权限允许 ChatGPT plan usage。签名验证使用成熟库，不手写密码学；新增验证依赖与许可证、锁文件及分发影响需先按 code spec 审查。

每个授权记录绑定验证后的账号与注册身份，返回登录不得错配其他账号。取消、拒绝、超时或返回无 plan usage 权限只给出真实状态，不能把“身份登录成功”当作“可以推理”。支持独立保存多组订阅连接；到期刷新在同一凭据锁内串行执行，锁内重读最新 token，并原子替换整组更新数据，避免多个进程竞争轮换 token。撤销或刷新失败提示重新登录，不自动换渠道。

OAuth 模型目录按账号实际可见项解析；HTTP 推理使用官方 Responses 路径、`store=false`、`stream=true` 和完整 input，不依赖 `previous_response_id`。冻结的系统指引转换为该路径允许的 instructions/developer 形式，不能发送被拒绝的 system item；本地工具按该路径允许的 namespace/additional_tools 形式适配，不照搬 API Key 请求全部字段。收到 `response.completed` 才是正常完成，额度错误、failed、incomplete 和中途断流按实际失败处理。

真实账号授权、渠道可用性与实际工具请求需要用户参与，模拟 OAuth/SSE 不能替代；遇到官方授权资格或额度限制及时说明，不靠非官方端点绕过。

### 3.7 `/model`、`/settings`、`/reload` 与输入所有权

新增菜单复用 `terminal.py` 的读取、`MainBufferScreen` 的按键入口和渲染器的底部交互区，不另开输入线程、焦点树或全屏框架。菜单取代整个 composer/facts/working 区域，历史仍可见；关闭恢复原草稿、编辑光标和事实信息。菜单状态、Ask、Permission 与普通编辑互斥，不能双重消费 ↑/↓、Enter、Space 或 Esc。

`/model` 只读取保存的本地目录：显示“模型名称 [供应商]”，当前标记与 default 标记分开；文本筛选名称或供应商，↑/↓ 导航，Enter 切换并关闭，Ctrl+S 保存高亮项为全局默认但不切换或关闭，Esc 只关闭且不撤销已保存默认。跨供应商时简短提示后续历史会发送到目标渠道，不能误称只发送新一句话。

`/settings` 只展示以下三项，不照搬参考图增加标签页和功能：

| 项 | 可选值与生效 |
|---|---|
| `reasoningEffort` | off/minimal/low/medium/high/xhigh/max 中模型实际支持的档位；映射采用官方能力或明确 `thinkingLevelMap`。不支持思考时只显示 off，不发送不支持的参数。 |
| `permissionMode` | default/solo；保存后从下一 Run 使用现有策略入口，不绕过工具注册、Schema、文件能力限制、取消或清洗。 |
| `reasoningDisplay` | full/collapsed/hidden；当前界面立即采用，内容呈现按既有视觉规格，不参与 Ctrl+O。 |

Enter/Space 循环切换选中项并保存到工作区；Ctrl+S 将这一项同时应用到全局，不整组复制、不改其他工作区覆盖。写失败不显示虚假生效状态。模型切换后重新计算思考有效值；保留偏好与说明当前有效值，不把旧档位硬发给新模型。

权限配置只选择现有模式，不把内置权限矩阵复制到 JSON 或开放自定义策略编辑。当前模式与来源在设置界面说明，事实区维持既有布局，不顺手增加未经确认的字段。

修改窗口立即生效，其他进程在下一 Run、打开 `/settings` 或 `/reload` 时读取文件；正在进行的 Run 冻结不变。共享指配置来源共用，不撤销其他进程用户明确指定的启动覆盖；界面需说明这种覆盖，防止写入成功却被误认为没有生效。`Shift+Tab` 按既有需求接入权限切换，同样保存工作区值；运行中只记录待生效值，当前 Run 收口后提交，不能在 Ask/Permission 中抢 Tab。

`/reload` 重新读取 config/models/auth，不强制联网刷新目录，也不重载 AGENTS、提示词或未实现的扩展。成功后更新当前有效设置、模型能力和事实；当前模型被删或禁用时保留选择引用但禁止新请求并提示处理。语法或读取错误保留此前显示快照，明确未重载成功并阻止错误配置下新请求，不半份更新。

当前 screen 在运行时忽略普通编辑键，不能仅添加一个命令处理函数就宣称忙时提醒可达。需允许运行中的非阻塞输入区保留本地命令草稿；完整命令提交时识别忙状态并给灰色短提示，不提交第二 Run、发送给模型或排队。Ask/Permission 仍独占输入；不为捕获命令破坏其回答。提示使用可注入时钟或现有刷新机制，不能新建常驻输入消费器。

目录请求或登录等待仍不是 Agent Run；用户可以取消。每次菜单操作绑定其生命周期，关闭或更换后丢弃迟到展示结果，资源由创建者收口；不得因网络等待卡住键盘、动画或终端退出。

## 4. 实施顺序与任务划分

按四个功能闭环顺序交付，阶段批次名称不是任务 ID；真正派发时才分配 `T-###`、任务卡和授权范围。不为每个字段、菜单按键或单处测试另开卡。热点和共享契约顺序施工，默认不并行修改 CLI/App/会话/TUI 核心。

| 批次 | 完整交付 | 依赖 | 状态 |
|---|---|---|---|
| A：配置、启动与模型选择 | 三文件解析和安全保存；未配置 TUI；既有 Chat Completions 连接装配；本地 `/model` 当前/默认切换；会话选择兼容保存与恢复；首个菜单真实终端验收。 | 无 | 未开始 |
| B：三接口与历史续接 | Responses、Messages 与现有接口统一；模型/工具/思考往返；安全续接契约与兼容保存；跨接口完成/中断历史接手；请求失败和资源收口。 | A 验收 | 未开始 |
| C：登录、发现与连接维护 | 自定义与三个内置 API 渠道；模型多选/手工添加/刷新；ChatGPT 官方订阅与刷新；重配、禁用、启用、删除；真实渠道验收。 | B 验收 | 未开始 |

首批修改入口以 `cli.py`、App/Runtime 装配、SessionService/JSONL 与 screen/editor 为主；第二批以 Provider、Message/Finish、Engine/App 进度与保存为主；第三批完成配置侧认证和目录服务并接菜单；第四批接运行设置与现有权限/呈现入口。允许新增职责完整的配置或认证模块，不预设大型管理框架。

**契约先审**：A 编码前提交配置字段、来源判定、空闲装配和选择 wire 的精确方案；B 编码前提交续接记录、流式完成、敏感清洗与旧格式回放的精确方案；C 引入认证依赖前提交库选择与分发影响。审查在相应任务内完成，不额外制造小任务；依赖任务只使用已经合并的契约。若需要改变已确认行为或扩大公共面，停下说明，不能用实施细节名义越界。

## 5. 验收安排

### 5.1 自动化与安全保护

测试按稳定行为归入现有资产，必要时新增配置/认证契约测试，不按阶段号命名；优先复用和加强现有场景。代表性测试先覆盖功能闭环，再在稳定最终版本集中执行 `docs/code_spec.md` §2.4 要求的全量、静态、兼容和分发验证，不要求每写一个函数就新增测试或重复全量。

| 验收领域 | 必须证明 |
|---|---|
| 配置 | 缺失/合法/未知键/非法值/语法损坏分别符合规则；正确覆盖与来源；保存目标项、并发编辑和替换失败不损坏旧文件；工作区无凭据。 |
| 启动与切换 | 无环境连接仍进入 TUI；未配置提交无 Run；当前/默认分离；切换保存失败保持旧选择；资源只有一个关闭所有者；直接与 plain 入口保留。 |
| 会话兼容 | 真实 v1～v4 固定样本可读且只读字节不变；新字段和原子升级安全；元数据操作保留选择；缺失渠道不自动换；Turn/checkpoint 顺序不变。 |
| 三接口 | 真实格式的流碎片、正常/失败/不完整终态、工具参数完整组装；思考后的两次工具往返；取消/断流及关闭；非法工具不能执行；只重试允许的网络边界。 |
| 跨接口恢复 | 有成功工具历史及有中断工具历史均能接手；通用事实不丢，专属数据不串渠道；不伪造 TOOL/最终回答或重放旧副作用；切回旧连接也检查绑定。 |
| 认证与目录 | 模型目录差异和畸形内容、手工值保护、取消与迟到响应；OAuth state/nonce/签名/权限失败；刷新轮换竞争、重配与删除竞争、原子写失败；日志/会话/错误/repr 无测试凭据。 |
| 设置与重载 | 当前、新建和恢复读取同一工作区设置；显式覆盖可解释；另一进程下一安全节点更新；进行中 Run 不变；逐项全局不改其他覆盖；重载失败没有半份生效。 |
| 终端回归 | 草稿、光标、Unicode/粘贴、方向键/数字/Enter/Esc、Ask 自定义答案、权限导航、Ctrl+C、Ctrl+O、resize/scrollback 与历史层级不退化。 |

并发测试使用 Event/队列/实际状态与有界等待；认证和模型服务用可控边界替身，默认不访问真实用户文件、Key 或外部服务。测试失败先保留现场、定位原因，不能跑到绿或因后续通过宣称历史间歇问题修复。

### 5.2 真实 Windows Terminal 与渠道验收

A 完成首个 `/model` 后即由用户检查导航、筛选、Enter/Ctrl+S/Esc、长失焦、resize、草稿与物理光标，不等全部菜单完成才发现共用输入问题。C/D 再复验登录多选、设置、忙时提示及 Ask/Permission，正向/负向视觉参考按 `docs/assets/tui/README.md` 流程保存；新菜单不以自动化截图自批真实验收。

真实登录/推理由用户明确参与：官方 ChatGPT 授权、OpenRouter/DeepSeek/OpenCode Go 目录与至少一条真实工具对话、跨接口切换及中断恢复。只在用户主动进行验收时发送推理，不在 `/login` 或 `/model` 隐藏发送测试消息。三种协议均需有实际渠道证据；缺账号、接口能力或额度时明确未验收，不用模拟结果冒充。

### 5.3 阶段交付与文档收口

交付上述四个闭环后，更新 README 的实际配置/命令使用方法、源码地图、终端现行规格及公共契约说明；旧说明与被替代测试同步清理。施工与返工在任务卡记录，阶段完成后按文档规范保留目标、已交付能力、最终代码层实现与验收结论，不复制报告全文。

阶段只在自动化、必要分发和用户真实环境验收分别具备证据后标记完成；任务 Git 收口按现有授权进行并验证远端，不把推送当作产品验收。不自动启动 Phase 7。
