# 项目经验

## Worker 任务体量

- 任务单默认覆盖一个可独立验收的中等体量完整功能块；派发前先评估产品模块、测试范围和迁移成本，避免同时出现“跨度过大”和“拆得过碎”。
- 同一组件内紧密耦合、需要共同验证的行为应合并派发，不要仅为方便审查而把一个完整体验拆成单个方法、单个视觉细节或极小测试切片。
- 任务同时跨越多层公共契约、不同运行链路、持久化格式和兼容迁移时，才优先拆成连续任务，不把多个高风险闭环一次性交给同一 worker。
- 后续任务以“一次可完成、一次可审查、一次可回退，同时具有可感知交付价值”为尺度；预计难以在一轮稳定完成时再继续拆分。
- 已经开始执行的任务不因拆分规则更新而中途改写；如确需调整，由 master 明确下发差异指令，避免打乱 worker 的现有工作。
- 当前任务通过 master 验收并完成 GitHub 同步后，应在同一轮直接派发下一个任务单；只有返工、基线冲突或需要用户处理的外部阻塞才暂停推进。
- 任务会改变既有公共输出或 wire 结构时，派发前先搜索所有直接断言与安装态覆盖，并把必要的最小测试更新纳入 allowlist，避免产品契约与测试编辑范围互相冲突。

## 异步测试同步

- 异步取消、流式输出和资源清理测试不要用固定 `sleep()` 猜测事件已经发生；应等待可观察状态或显式事件，并为等待设置有界超时，避免机器负载或导入耗时导致不稳定失败。
- 异步清理测试的外层有界 timeout 必须覆盖业务超时、内部清理等待上限和调度余量，不能与理论最大耗时设置成同一个值。
- Textual 的 `call_after_refresh()` 等延迟回调可能在目标组件终态移除后才执行；查询可选节点时先判断 `DOMQuery` 是否非空再调用 `first()`，终态清理必须允许节点已经不存在并保持幂等。
- 不要机械消除全部墙钟等待。若测试目标是证明「延迟副作用时刻过后仍未发生」，且没有等价的后代进程观测手段，必要的墙钟等待可以保留。根因未决的 flake 应先增加测试侧诊断或隔离证据，禁止通过放宽断言、吞错误、skip/xfail 或臆测产品修复来修绿。

## 测试资产治理

- 新增测试优先放入最接近其行为边界的现有测试文件；只有形成独立公共契约或独立测试装配时才新建文件，避免一次返工一个测试文件。
- 产品入口、实现路径或兼容层被删除时，必须在同一任务或紧随其后的清理任务中迁移、合并或删除对应测试。仍处于默认运行路径的旧实现测试，不能仅因看起来旧而删除。
- 删除测试前必须证明：对应产品路径确实已退出；独有的公共行为、安全负向边界和回归价值已迁移或明确不再适用；删除后不会只剩对私有实现的乐观覆盖。
- 异步或进程测试优先等待可观察状态；必要的延迟副作用墙钟等待，以及根因未决 flake 的诊断优先处理，见「异步测试同步」。

## Worker 构建与验证节奏

- Worker 先理解目标和直接相关代码，再连续完成一个可运行的功能闭环；不要把验收清单机械转换成逐行为实现、逐行为测试的命令流水。
- 紧密相关的行为用少量代表性的公共场景共同覆盖，通常先运行一次聚焦测试；出现失败后只重跑受影响的最小测试组。
- 兼容测试、分发测试、全量测试、Ruff、格式检查和离线构建集中在功能稳定后的最终验收，各执行一次即可。
- 只有实际出现间歇失败、资源警告或清理竞态时才安排多次稳定性复跑；不能把三次、五次重复运行作为默认要求。
- Worker 报告聚焦最终实现、真实发现的问题、最终验证和剩余风险，不记录每条测试或每次命令的完整时间线。

## TUI 视觉验收

- 已确认的正向参考图和实际问题图应保存到仓库内的 `docs/assets/tui/`，任务单必须要求 Worker
  实际打开对应图像；不能只靠文字转述视觉目标，也不能把问题图误当成待复刻样式。
- 界面测试、DOM 断言、全量通过和安装态构建只能证明行为与结构，不代表视觉完成。涉及布局、
  边框、间距或响应式呈现时，必须在可比视口和相同状态下对照截图，并等待用户手工视觉验收
  后再做任务 Git 收口。

## TUI 事件与输入所有权

- `run_id` 只标识整轮运行，不能默认等于一个可见回复组件；同一 Run 存在多次模型步骤时，
  必须按公开事件边界创建独立片段，并用真实 DOM 顺序验证“模型文字 → 工具 → 后续文字”。
- Ask、权限、取消和历史滚动等关键键盘行为不能只依赖挂载时的一次 `focus()`；应建立唯一的
  App 级输入所有者，并覆盖终端失焦/恢复、交互切换和 Run 终态后的焦点恢复。
- `Esc`、`Ctrl+C` 等全局控制键必须覆盖 Textual 默认绑定并走产品自己的取消/退出状态机；
  自动测试除按键结果外，还要验证 Run、Provider、Broker、Bash 和会话提交的清理边界。
- Pilot 中手工发送 `AppBlur`/`AppFocus` 只能验证应用层处理函数，不能证明真实 Windows 终端驱动
  会产生同样事件。涉及失焦恢复时必须先核对锁定依赖的实际驱动事件，再让首个键盘、鼠标或
  resize 输入承担幂等自愈，并保留真实终端长时间失焦冒烟验收。
- “取消后不写半轮”只证明完整轮次的原子性，不等于可恢复。Agent 的主动中断或 Provider
  可恢复失败还需要独立的中断检查点：保留原始用户指令和结构完整的安全进度，明确未完成状态，
  不伪造模型总结、未执行工具结果或成功终态。
- 当锁定的终端输入 API 已丢弃 key-up、重复计数或事件身份时，应用层不能声称能区分延迟自动重复
  与新的独立按键；只能保证合并可观察的近同步重复，并把持续按住等剩余风险写入契约和真实终端
  验收步骤，不能用测试名称替平台补造不存在的信息。
- 流式 transcript 的“用户已离底”必须在 PageUp、滚轮或拖动意图进入时同步生效，不能等异步
  `scroll_y` watcher 再更新；延迟的自动跟随回调还必须可合并、可失效，否则新输出会在用户上翻
  后把视口重新拉到底部，表面上看起来像失焦或滚动键失灵。

## 主缓冲区终端前端

- 真实 Windows Terminal 冒烟持续否定框架内的焦点和滚动修补时，应重新审查所有权边界，
  不能继续用更多 DOM 焦点恢复和自动跟随状态掩盖架构不匹配。终端原生 scrollback、鼠标滚动
  和背景应由终端拥有，Mica 只维护自己的语义文档和底部输入区域。
- “透明背景”不等于“主缓冲区”。仍进入 alternate screen、捕获鼠标或维护内部 transcript
  的实现不会获得终端原生历史与滚动；验收必须检查实际控制序列和退出后的 scrollback。
- 主缓冲区也不等于纯追加日志。需要动态工具卡片、全局历史展开和底部编辑区时，应保留轻量
  组件文档并差分重绘：普通流式更新只重绘变化尾部，历史高度变化或宽度变化才允许受控全量
  重绘，并用真实终端验证视口、草稿和 scrollback 不丢失。
- 环境事实与 Run 状态必须分开。模型、工作区/分支和会话名称由公开状态驱动并在事实变化后
  刷新；`working/done/stop/error` 只表达当前 Run 生命周期，不混入模型名、路径或会话标识。
- 工具状态可以用大面积语义色块表达，但 NO_COLOR 下必须保留稳定符号或安全原因；不能为了
  极简而让颜色成为唯一状态。活动工具的实时输出保持有界，完整安全结果只在终态和全局展开
  模式中呈现。
